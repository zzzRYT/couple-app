# Feature Specification: 프롬프트로 꾸미는 커플 D-day와 우리 방

**Feature Branch**: `001-couple-prompt-todo` (spec 디렉터리 이름이며, 작업 브랜치는 `fm/cpl-spec-v3`)

**Created**: 2026-10-24

**Status**: Draft (배치 계산 방식은 디자인 단계에서 결정)

**Input**: 커플이 앱에서 D-day를 확인하고, 둘만의 방 한 화면을 프롬프트로 꾸민다.

## Clarifications

### Session 2026-10-24

- Q: 첫 버전의 제품 범위는 무엇인가? → A: 모바일 앱에서 커플 공간과 초대, 메인 D-day 페이지, 프롬프트로 꾸미는 커플 방 한 페이지를 제공하고 캘린더와 할 일은 제외한다.
- Q: 꾸미기 기능에 AI 생성 배지를 표시할 것인가? → A: 배지나 라벨 요구사항은 두지 않는다. 출시 전 법률상 표시 의무를 검토한다.
- Q: 해외 AI 제공자에게 프롬프트와 방 설정을 보낼 수 있는가? → A: 전송 전에 이용자의 명시적 동의를 받는다.
- Q: 꾸미기 요청 한도와 가격 상품을 정했는가? → A: 커플당 하루 10회 한도는 남용 방지용으로만 사용하며, 가격 상품으로 사용량을 제한하지 않는다. 가격 상품은 두지 않는다.
- Q: 로그인과 초대 방식은 무엇인가? → A: 카카오·Apple·이메일 로그인을 제공하고, 공유 가능한 만료 코드로 상대를 초대한다.
- Q: 사진 업로드는 첫 버전에 포함하는가? → A: 포함하지 않는다.
- Q: 한쪽이 커플 공간을 종료하면 데이터는 어떻게 되는가? → A: 어느 쪽이든 종료할 수 있고, 종료 후 30일 동안 보관하며 그 기간에는 복구할 수 있다. 이후 삭제한다.
- Q: 장식·캐릭터·배경화면 위치를 앱이 정한 지점으로 제한할 것인가? → A: 고정 지점으로 제한하지 않고, 커플별 환경과 프롬프트에 따라 다른 배치를 허용한다. 배치를 계산하는 방식은 진행 중인 연구를 참고해 디자인 단계에서 정한다.
- Q: 방의 D-day 블록에서 프롬프트로 바꿀 수 있는 항목은 무엇인가? → A: 블록을 방에서 옮기거나 제거하고 모양·색·크기를 바꿀 수 있지만, 날짜 값과 정확성, 접근성은 앱이 관리하며 프롬프트로 바꿀 수 없다. 블록을 방에서 제거해도 메인 D-day 페이지는 유지한다. 설정·되돌리기·기록·삭제·공간 나가기 컨트롤은 고정 상태를 유지한다.
- Q: 첫 버전 방 장면의 구성과 사용량은 무엇인가? → A: 라이선스가 있는 작은 2D 카탈로그 오브젝트와 짧은 텍스트를 자유 배치·회전·레이어 순서로 구성한다. 장면별 수량은 초기 가정으로 두며, 생성 이미지·임의 벡터 그림·외부 코드는 제외한다. 커플당 하루 10회 요청 한도는 남용 방지용이다.
- Q: 앱의 캐릭터와 방의 낮·밤 및 인터페이스 테마는 무엇인가? → A: 앱 소유의 독창적인 마스코트가 기본으로 방과 메인 페이지에 나타나며, 정해진 슬롯·팔레트·크기·위치·표정·포즈로 꾸밀 수 있다. 방은 낮/밤 테마를 가지며 인터페이스는 다크 모드를 지원한다.
- Q: 다국어 출시는 어떻게 처리할 것인가? → A: 모든 인터페이스 문구는 번역 리소스를 사용하고 기기 언어와 앱 내 언어 설정을 지원한다. 한국어 우선 출시는 가정이며, 두 번째 언어와 전체 출시 언어는 미결정이다.
- Q: 성공 기준의 목표 수치는 정했는가? → A: 커플이 AI를 활용해 자기 방을 꾸미는 경험을 검증할 수 있도록 수치 기준을 두되, 목표 숫자는 임시 가정으로 표시한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 커플 공간 만들고 D-day 확인하기 (Priority: P1)

사용자는 카카오, Apple 또는 이메일로 로그인한 뒤 커플 공간을 만들고 상대에게 초대 코드를 공유한다. 상대가 만료 전에 코드를 수락하면 두 사람은 함께한 날짜를 입력하고 메인 페이지에서 D-day를 확인한다.

**Why this priority**: 커플 공간과 D-day가 둘이 함께 앱을 시작하는 기본 경험이다.

**Independent Test**: 두 사용자가 초대 코드로 같은 공간에 참여하고, 함께한 날짜를 입력해 동일한 D-day를 확인하는 흐름을 검토한다.

**Acceptance Scenarios**:

1. **Given** 커플 공간이 없는 사용자, **When** 공간을 만들고 초대 코드를 공유하면, **Then** 상대는 코드를 수락해 공간에 참여할 수 있다.
2. **Given** 사용된 적 없는 초대 코드, **When** 코드가 만료되었거나 이미 수락된 뒤 다시 사용되면, **Then** 참여를 거부하고 새 코드를 발급할 수 있다.
3. **Given** 두 사람이 참여한 공간, **When** 한 사람이 함께한 날짜를 입력하거나 수정하면, **Then** 메인 D-day 페이지에 같은 날짜 기준의 일수가 표시된다.

### User Story 2 - 프롬프트로 둘만의 방 꾸미기 (Priority: P1)

두 사람은 자신들의 방 한 페이지를 자연어 프롬프트로 꾸민다. 문구와 색, 라이선스가 확인된 2D 오브젝트, D-day 블록의 위치와 모양·색·크기를 요청할 수 있다. 오브젝트와 텍스트는 자유롭게 배치하고 회전하거나 레이어 순서를 바꿀 수 있다. 사용자는 적용 전에 미리 보고, 확인하거나 취소하고, 프롬프트로 배치된 요소를 옮기거나 제거하고, 이전 배치를 복구할 수 있다.

**Why this priority**: 커플이 AI를 활용해 자신들의 공간을 직접 꾸미는 것이 앱의 핵심 경험이다.

**Independent Test**: 서로 다른 커플이 입력한 프롬프트에서 서로 다른 방 배치가 제안되는지, 프롬프트로 요소를 옮기거나 제거할 수 있는지, 되돌리면 이전 배치가 복구되는지 요구사항을 검토한다.

**Acceptance Scenarios**:

1. **Given** 활성 커플 공간, **When** 한 사람이 꾸밈 프롬프트를 입력하면, **Then** 요청에 맞는 짧은 문구, 색, 라이선스가 확인된 2D 오브젝트와 D-day 블록 표현의 미리 보기가 나온다.
2. **Given** 여러 프롬프트가 서로 다른 분위기나 꾸밈을 요청함, **When** 각 요청의 미리 보기를 만들면, **Then** 결과는 각 프롬프트의 의도에 따라 달라질 수 있다.
3. **Given** 서로 다른 두 커플이 서로 다른 배치를 요청함, **When** 각 커플의 방 미리 보기를 만들면, **Then** 방 배치가 눈에 띄게 달라야 한다.
4. **Given** 방에 프롬프트로 배치한 요소, **When** 사용자가 프롬프트로 위치를 옮기거나 제거하면, **Then** 미리 보기에 요청된 배치 변경이 반영된다.
5. **Given** 방의 D-day 블록, **When** 사용자가 프롬프트로 위치·모양·색·크기를 바꾸면, **Then** 화면 표현만 바뀌고 날짜 값·정확성·접근성과 고정 컨트롤은 바뀌거나 가려지지 않는다.
6. **Given** 미리 보기, **When** 사용자가 취소하거나 다른 프롬프트를 입력하면, **Then** 공유 중인 방과 커플 데이터는 바뀌지 않는다.
7. **Given** 사용자가 미리 보기를 확인함, **When** 변경을 적용하면, **Then** 두 사람에게 같은 방이 반영되며 상대방은 앱을 열거나 공유 방이 동기화될 때 최신 상태를 본다.
8. **Given** 저장된 이전 배치, **When** 사용자가 되돌리기를 요청하면, **Then** 이전 방 배치가 복구되며 상대방은 앱을 열거나 공유 방이 동기화될 때 최신 상태를 본다.
9. **Given** 프롬프트가 데이터나 기능을 변경하라고 요청함, **When** 요청을 처리하면, **Then** 해당 변경은 거부되고 가능한 꾸밈 요청을 안내한다.
10. **Given** 프롬프트가 첫 버전의 장면 한도를 넘는 오브젝트나 텍스트를 요청함, **When** 미리 보기를 만들면, **Then** 정해진 한도를 넘는 결과는 적용하지 않고 가능한 범위를 안내한다.
11. **Given** 새 커플의 방, **When** 방을 처음 연다, **Then** 앱 소유 마스코트가 기본으로 표시되고 방의 16개 오브젝트 한도에 포함된다.
12. **Given** 마스코트가 있는 방, **When** 사용자가 마스코트를 꾸민다, **Then** 슬롯 아이템, 승인 팔레트 색, 앱 정의 표정·포즈만 선택할 수 있고 base design을 대체하거나 다시 그리게 할 수 없다.
13. **Given** 지원 언어의 prompt와 room text, **When** AI 미리보기를 생성한다, **Then** prompt를 요청 언어로 처리하고 커플이 작성한 텍스트는 원문 그대로 보존한다.

### User Story 3 - 언어 및 표시 테마 설정 (Priority: P1)

사용자는 기기 언어를 기본으로 시작하고 설정에서 앱 언어를 선택한다. 날짜와 D-day 문구는 해당 언어 관례를 따르며, 방의 낮/밤 모드와 앱 인터페이스의 다크 모드는 독립적으로 설정할 수 있다.

**Why this priority**: 앱의 문구와 날짜가 각 구성원이 이해하는 방식으로 표시되고 모든 표시 모드에서 방과 고정 UI를 읽을 수 있어야 한다.

**Independent Test**: 기기 언어 감지, 앱 내 언어 변경, 긴 번역문, day/night와 light/dark 네 조합의 대비·보호 영역을 검토한다.

**Acceptance Scenarios**:

1. **Given** 지원 언어가 있는 기기, **When** 앱을 처음 연다, **Then** 기기 언어의 번역 리소스와 날짜·숫자·D-day 형식을 사용한다.
2. **Given** 앱 설정에서 다른 지원 언어를 선택함, **When** 화면을 다시 표시한다, **Then** 모든 UI 문자열이 선택 언어로 바뀌고 긴 문구가 잘리지 않는다.
3. **Given** 방의 낮/밤과 인터페이스 light/dark 조합 각각, **When** 방을 렌더한다, **Then** 보호 영역·대비·가독성 규칙을 만족한다.
4. **Given** 시간대 자동 방 모드, **When** 자동 모드가 선택됨, **Then** 방이 낮/밤 variant를 사용한다. 자동 모드는 초기 기본 가정이며 캡틴 확인이 필요하다.

### User Story 4 - 커플 공간 종료와 복구 (Priority: P2)

어느 쪽이든 커플 공간을 종료할 수 있다. 종료 후 30일 동안 두 사람의 데이터는 보관되고 복구할 수 있으며, 기간이 지나면 삭제된다.

**Why this priority**: 관계가 끝나거나 공간을 더 이상 사용하지 않을 때 데이터 처리와 복구 가능 기간을 예측할 수 있어야 한다.

**Independent Test**: 한 사람이 공간을 종료한 시점부터 30일 안의 복구와 30일 경과 후 삭제라는 상태 전이를 검토한다.

**Acceptance Scenarios**:

1. **Given** 활성 커플 공간, **When** 어느 한 사람이 종료를 선택하면, **Then** 공간은 종료 상태가 되고 두 사람에게 복구 가능 기간이 안내된다.
2. **Given** 종료 후 30일 이내, **When** 구성원 중 한 사람이 복구를 요청하면, **Then** 공간과 보관 데이터가 복구된다.
3. **Given** 종료 후 30일이 경과함, **When** 보관 기간이 끝나면, **Then** 커플 공간과 해당 데이터가 삭제된다.

### Edge Cases

- 상대가 초대 코드를 수락하지 않거나 초대가 만료된 경우, 초대자는 코드를 다시 발급할 수 있다.
- 두 사람이 동시에 꾸밈을 확인하면 나중 요청의 미리 보기는 현재 저장된 방을 바탕으로 다시 확인받아야 한다.
- 프롬프트가 모호하거나 지원하지 않는 항목을 요구하면 적용 가능한 부분만 임의로 저장하지 않고, 지원 범위의 대안 미리 보기를 제안한다.
- AI 제공자 이용 불가 또는 동의 철회 시 현재 방은 유지되고 프롬프트 전송은 이루어지지 않는다.
- 프롬프트로 배치가 달라지더라도 기능과 고정 컨트롤이 있는 화면 보호 영역은 장식이 가리거나 입력을 가로채지 않도록 유지되어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

**계정·커플 공간·초대**

- **FR-001**: 제품은 모바일 앱으로 제공해야 한다. 앱은 카카오, Apple, 이메일 로그인을 제공해야 한다.
- **FR-002**: 로그인한 사용자는 두 명이 구성원이 되는 커플 공간을 만들 수 있어야 한다.
- **FR-003**: 구성원은 상대에게 공유할 수 있는 초대 코드를 발급해야 하며, 코드는 만료되어야 하고 한 번 수락된 코드는 다시 사용할 수 없어야 한다.
- **FR-004**: 초대받은 사용자가 유효한 코드를 수락한 뒤에만 두 번째 구성원으로 참여해야 한다. 공간은 최대 두 명의 구성원만 허용해야 한다. 초대자는 앱을 열거나 공유 공간이 동기화될 때 최신 구성원 상태를 확인할 수 있어야 한다.
- **FR-005**: 커플 공간과 D-day 및 방 꾸밈 데이터는 해당 공간의 두 구성원만 열람하고 변경할 수 있어야 한다.

**메인 D-day 페이지**

- **FR-006**: 구성원은 함께한 날짜를 입력하고 수정할 수 있어야 하며, 앱은 메인 페이지에 함께한 일수를 표시해야 한다.
- **FR-007**: 두 구성원에게 동일한 날짜 기준의 D-day가 표시되어야 한다.

**프롬프트로 꾸미는 커플 방**

- **FR-008**: 각 커플 공간에는 프롬프트로 꾸미는 방 페이지 하나가 있어야 한다.
- **FR-009**: 방 장면은 라이선스가 있는 2D 카탈로그 오브젝트와 짧은 텍스트로 꾸밀 수 있어야 한다. 사용자는 프롬프트로 오브젝트와 텍스트의 자유 위치, 회전, 레이어 순서를 정할 수 있어야 한다.
- **FR-010**: 오브젝트 배치는 앱이 정한 고정 지점으로 제한하지 않아야 한다. 프롬프트와 커플별 환경에 따라 서로 다른 배치를 제안해야 하며, 서로 다른 두 커플이 서로 다른 배치를 요청하면 미리 보기의 방 배치가 눈에 띄게 달라야 한다. 배치 제안은 적용 전에 미리 볼 수 있어야 한다.
- **FR-011**: 시스템은 제안을 공유 방에 반영하기 전에 사용자의 명시적 확인을 받아야 한다. 취소하거나 다른 제안을 요청한 경우 현재 방은 유지되어야 한다.
- **FR-012**: 확인된 꾸밈은 공유 방의 현재 상태로 저장되어야 하며, 상대방은 앱을 열거나 공유 방이 동기화될 때 최신 상태를 확인할 수 있어야 한다.
- **FR-013**: 사용자는 프롬프트로 배치된 오브젝트와 짧은 텍스트를 옮기거나 제거할 수 있어야 하며, D-day 블록도 방에서 옮기거나 제거할 수 있어야 한다. 블록을 제거해도 메인 D-day 페이지의 날짜와 기능은 유지되어야 한다. 되돌리기는 직전 적용 전 방 배치를 복구해야 한다. 구성원은 이전에 저장된 방 꾸밈도 복구할 수 있어야 하며, 버전 보관 개수나 정리 기간은 이 명세에서 정하지 않는다.
- **FR-014**: 프롬프트는 커플 공간 정보, D-day 데이터, 기능 목록, 기능 동작, 권한, 고정 컨트롤을 만들거나 변경하거나 삭제할 수 없어야 한다.
- **FR-015**: 기능과 고정 컨트롤이 있는 화면 영역은 보호 영역으로 유지되어야 하며, 어떤 꾸밈 배치에서도 장식이 이를 가리거나 입력을 가로채거나 사용을 방해하지 않아야 한다. 고정 컨트롤은 꾸밈 프롬프트로 숨기거나 이름 또는 동작을 바꿀 수 없어야 한다.
- **FR-016**: 사용자는 꾸밈 프롬프트를 보내기 전에 해외 AI 처리 여부, 전송되는 정보와 처리 목적을 안내받고 명시적으로 동의해야 한다. 동의 전 또는 동의 철회 후에는 프롬프트나 방 설정을 해외 AI 제공자에게 전송하지 않아야 한다.
- **FR-017**: 꾸밈 프롬프트 처리에 필요한 정보는 사용자가 동의한 범위로 제한해야 한다. 커플 공간의 D-day 등 방 꾸밈과 무관한 데이터는 전송하지 않아야 한다.
- **FR-018**: 각 새 커플의 방과 메인 페이지에는 앱 소유의 독창적인 마스코트가 기본으로 표시되어야 한다. 마스코트는 방의 다른 카탈로그 오브젝트처럼 이동·크기 조정·배치할 수 있어야 하며, 의상 아이템은 머리·얼굴·목·손의 고정 슬롯에서 선택하고, 색은 승인 팔레트 안에서 고르고, 표정·포즈는 앱이 정의한 제한된 선택지에서 정해야 한다. 프롬프트로 마스코트의 기본 디자인을 바꾸거나 다시 그릴 수 없어야 하며 기존 캐릭터나 브랜드를 요청하는 프롬프트는 거절해야 한다.
- **FR-019**: 모든 화면의 사용자에게 보이는 문구는 번역 가능한 리소스에서 제공해야 하며, 새 언어를 추가할 때 화면 코드 변경이 필요하지 않아야 한다. 기기 언어를 기본값으로 사용하고 앱 설정에서 언어를 바꿀 수 있어야 한다. 날짜, 숫자, D-day 표현은 선택 언어 관례를 따라야 하며 긴 번역문을 수용하는 레이아웃이어야 한다. AI 프롬프트는 지원 언어로 입력할 수 있어야 하고, 사용자가 방에 작성한 문구는 번역하지 않고 입력 언어 그대로 저장해야 한다. 사용 폰트는 각 지원 언어의 문자 범위를 포함해야 한다. 서버 오류는 언어 중립 코드로 반환하고 앱이 현재 언어로 번역해야 한다.
- **FR-020**: 방은 낮과 밤 표시 모드를 제공해야 하며, 사용자는 직접 전환하거나 시간대에 따라 자동 전환하도록 설정할 수 있어야 한다. 기본값은 시간대 자동 전환으로 가정한다(캡틴 확인 필요). 앱 인터페이스는 기기 설정을 기본으로 따르는 다크 모드와 수동 테마 재정의를 제공해야 한다. 두 방 모드와 두 인터페이스 모드의 모든 조합에서 보호 영역, 대비, 가독성 요건을 지켜야 한다.
- **FR-021**: 첫 버전은 사용자 사진 업로드, 생성 이미지, 임의 벡터 그림, 외부 코드 적용을 제공하지 않아야 한다.

**커플 공간 종료·복구**

- **FR-022**: 어느 구성원이든 커플 공간을 종료할 수 있어야 한다.
- **FR-023**: 종료된 공간의 D-day와 꾸밈 데이터는 종료 시점부터 30일 동안 보관되어야 하며, 이 기간에 어느 구성원이든 복구를 요청할 수 있어야 한다.
- **FR-024**: 종료 후 30일이 지나면 커플 공간과 보관 대상 데이터는 삭제되어야 한다.
- **FR-025**: 커플에게 꾸밈 결과의 개인적·비상업적 이용을 허용하되, 꾸밈 결과의 소유권을 보장하지 않아야 한다.
- **FR-026**: 방 장면에는 D-day 블록을 표시해야 한다. 프롬프트는 블록의 위치와 모양·색·크기를 바꿀 수 있지만, 날짜 값과 계산의 정확성, 접근성은 앱이 소유하고 프롬프트가 바꾸거나 손상할 수 없어야 한다.
- **FR-027**: 화면의 설정·되돌리기·기록·삭제·공간 나가기 컨트롤은 장식 배치가 달라져도 위치를 바꾸거나 가리거나 조작을 방해할 수 없어야 한다.
- **FR-028**: 꾸밈 요청은 무료로 제공하고 커플당 하루 최대 10회로 제한해야 한다. 이 한도는 남용 방지용으로만 사용하고 결제나 가격 차등과 연계하지 않아야 한다.
- **FR-029**: 첫 버전의 카탈로그와 장면당 오브젝트·텍스트 수는 Assumptions의 초기 가정 범위를 넘지 않아야 한다. 한도를 넘는 프롬프트 결과는 적용할 수 없으며 가능한 범위를 안내해야 한다.

### Out of Scope

- 공유 캘린더, 일정, 할 일 목록과 할 일 템플릿
- 상대방 재촉 기능
- 사용자 사진 업로드
- 생성 이미지, 임의 벡터 그림, 외부 코드
- 가격 상품, 유료 요금제 및 사용량에 따른 결제 차등
- 웹 앱과 PWA

### Key Entities *(include if feature involves data)*

- **커플 공간(Couple Space)**: 구성원 두 명, 함께한 날짜, 활성·종료 상태와 종료 시각을 가진 공유 단위.
- **구성원(Member)**: 커플 공간의 한 사용자.
- **초대(Invitation)**: 공유 및 수락이 가능한 만료 코드와 발급·수락·만료 상태를 가진 초대 기록.
- **방 테마(Room Theme)**: 커플 방의 낮/밤별 asset·색 variant, 방 모드와 D-day 블록 표현 설정.
- **방 테마 버전(Room Theme Version)**: 사용자가 확인해 적용한 장면과 낮/밤 테마 설정의 이전 상태로, 복구의 기준이 된다.
- **꾸밈 요청(Decoration Request)**: 사용자 프롬프트, 미리 보기 결과, 적용 또는 취소 상태를 가진 요청. 프롬프트는 방 오브젝트의 배치·회전·레이어와 D-day 블록의 표현을 제안하되 앱이 소유한 날짜 값과 정확성을 변경하지 않는다.
- **AI 처리 동의(AI Processing Consent)**: 해외 처리 안내를 확인하고 동의하거나 철회한 구성원과 동의 시점을 기록한다.
- **앱 마스코트(App Mascot)**: 앱 소유 기본 디자인, 카탈로그 의상 슬롯, 승인 색 팔레트, 표정·포즈 상태를 가진 독창적인 캐릭터다.
- **사용자 언어 설정(Locale Preference)**: 기기 언어 기본값을 따르거나 앱에서 선택한 지원 언어다.
- **방 모드 및 인터페이스 테마(Room Mode and UI Theme)**: 낮/밤 방 표현과 기기 기본값/수동 재정의를 가진 인터페이스 명암 설정이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 신규 커플의 90% 이상이 앱을 연 뒤 5분 안에 초대 수락, 함께한 날짜 입력, 메인 D-day 확인을 완료한다. 목표 수치는 임시 가정이다.
- **SC-002**: 활성 커플의 60% 이상이 첫 주 안에 꾸밈 프롬프트를 제출하고, 미리 보기를 확인해 방 꾸밈을 한 번 이상 적용한다. 목표 수치는 임시 가정이다.
- **SC-003**: 서로 다른 꾸밈 의도의 프롬프트 10개 중 8개 이상에서 요청 의도에 맞는 차이가 적용된 미리 보기에 나타난다. 목표 수치와 평가 방법은 임시 가정이다.
- **SC-004**: 확인되지 않은 프롬프트 결과가 공유 방이나 커플 데이터에 반영되는 사례가 0건이어야 한다.
- **SC-005**: 종료 후 30일 이내 복구 요청은 보관된 데이터와 함께 복구되고, 30일이 지난 공간은 삭제되어야 한다.

## Assumptions

- 첫 버전에는 어떤 형태의 알림도 제공하지 않는다. 후속 버전에서 필요성이 확인되면 별도 결정으로 추가할 수 있다. 초대 수락과 꾸밈 적용·되돌리기는 공유 상태에 저장하고, 상대방은 앱을 열거나 공유 방이 동기화될 때 최신 상태를 본다.
- 초기 장면 구성 가정(캡틴 결정, 실제 장면 검토 후 소유자가 조정 가능): 시작 카탈로그에는 라이선스가 확인된 작은 2D 오브젝트 24~36개를 두며, 한 장면에는 오브젝트 최대 16개와 짧은 텍스트 최대 3개를 둔다.
- 카탈로그 24~36개에는 마스코트 기본 포즈와 착용 아이템이 포함된다. 초기 30개 목표의 가정 분할은 마스코트 포즈 4개, 슬롯별 착용 아이템 8개, 일반 방 오브젝트 18개다. 마스코트는 새 방마다 기본 1개가 있으며 16 오브젝트 한도 안에 포함된다.
- **임시 가정(캡틴 미확정)**: 한국어를 먼저 출시하고 다국어 리소스 구조를 영어 리소스로 검증한다. 두 번째 출시 언어와 전체 출시 언어 집합은 캡틴이 결정한다. 시간대에 따른 방 자동 전환을 기본으로 한다.
- **임시 가정(캡틴 미확정) - 목표 수치**: SC-001의 90%·5분, SC-002의 60%·첫 주, SC-003의 8/10은 제품 목표를 정하기 전의 검증용 제안 수치다.
- **법률 검토 위험**: AI 생성 시각 결과에 법률상 고지·표시 의무가 있는지 출시 전에 검토해야 한다. 앱 내 AI 배지나 라벨을 붙이는 요구사항은 두지 않는다.

## Open Research

- 배치가 앱 정의 고정 지점에 제한되지 않고 커플별로 달라질 수 있다는 제품 방향은 정해졌다. 배치 계산과 제안의 구체적인 방식은 진행 중인 연구를 참고해 디자인 단계에서 결정한다.
- 카탈로그 마스코트와 아이템별 저작권·상표 검토, 슬롯 간 조합, 방/페이지별 표시 표현, 지원 언어와 두 번째 출시 언어, 시간대 자동 전환의 기준 시간대는 구현/디자인 전에 구체화한다.
