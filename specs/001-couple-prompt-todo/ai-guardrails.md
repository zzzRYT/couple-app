# AI 생성 가드레일 (생성 오브젝트 · 신고 · 운영)

**작성일**: 2026-10-27 · **상태**: 제안(소유자의 4차 답변을 해석한 **가정**, `spec.md` Decided 27~32) · **적용 범위**: P2 기능 US8(새 배경·말풍선 장식 생성)과 US9(신고) · **관련**: `spec.md` FR-060~FR-068, `plan.md` "생성 오브젝트", `data-model.md`(`GeneratedObject`·`GenerationAttempt`·`AppConfig`·`GenerationBlock`·`Report`), `contracts/api.md`, `contracts/generated-object.schema.json`, `research.md` 9장, `design/reference-library/`

## 0. 먼저 정직하게: 가드레일이 하는 일과 못하는 일

- **하는 일**: 위험을 줄인다. 요청 단계에서 위험한 범주를 거르고, 결과를 코드로 엄격히 검증하고, 별도 검사를 한 번 더 하고, 남용을 한도로 막고, 문제가 생기면 앱 업데이트 없이 끄고, 신고로 사람이 지울 수 있게 한다.
- **못하는 일**: 저작권·상표 침해, 혐오 상징, 불쾌한 그림을 **없앨 수 없다**. 도형 40개 이하·평면 채움·글자 없음이라는 형식 제한이 표현력을 크게 줄여 위험을 낮추지만, 단순한 도형도 특정 로고나 상징을 닮을 수 있다. 텍스트 기반 2차 검사는 그림을 **보지 못한다**. 스타일 적합도 검사는 "우리 스타일에 가까운가"이지 "남의 것과 닮았는가"가 아니다.
- **AI 결과물의 권리는 법적으로 불확실하다**(`research.md` 9.2). 약관과 안내는 소유권·비침해를 약속하지 않는다(FR-025·FR-068).
- 모든 수치(한도·보관일·임계값)는 **가정**이며 서버 설정값으로 둔다.

## 1. 방어 계층

| # | 계층 | 어디서 | 막는 것 | 실패하면 |
|---|---|---|---|---|
| 1 | 접근 통제 | 서버 | 비구성원·동의 없음·종료된 공간(없는 공간과 같이 취급)·점유자 아님 | 403/404/409, 모델 호출 없음 |
| 2 | 킬 스위치·보관함·한도 | 서버 | 생성 꺼짐, 보관함 가득, 시도 한도·쿨다운, 하루 3회 | 503/409/429, 모델 호출 없음 |
| 3 | 입력 정책 | 서버(결정론 필터 + 분류 호출) | 위험한 요청 범주 | 422 `GENERATION_REFUSED`, 횟수 안 씀 |
| 4 | 생성 지시 | 서버 → 모델 | 시스템 지시에 정책·형식·스타일 규칙·기준 라이브러리 | (모델이 어겨도 5·6이 막음) |
| 5 | 형식 검증·정규화 | 서버(공유 검증기) | 코드·참조·범위·팔레트·복잡도·대비·스타일 | 오류 피드백으로 1회 재시도 → 503 `GENERATION_FAILED` |
| 6 | 2차 모델 검사 | 서버(별도 호출) | 1차가 놓친 정책 위반(라벨 포함) | 같은 재시도 규칙, 호출 오류는 **실패로 처리**(fail-closed) |
| 7 | 렌더 전 재검증 | 앱 | 저장 뒤 검증기가 강화된 경우 | 그 장식은 그리지 않음 |
| 8 | 킬 스위치(렌더) | 서버 설정 → 앱 | 이미 저장된 문제 장식 | 생성 장식 렌더링을 끔 |
| 9 | 신고·운영 제거 | 앱 + 운영자 | 모두 통과했지만 문제인 장식 | 신고자 화면 즉시 숨김 → 운영자가 제거·재생성 차단 |

규칙: **모델이 "괜찮다"고 해도 코드 검증(5)을 대신하지 못한다.** 서버 집행만 인정하고 클라이언트 검사는 편의일 뿐이다.

## 2. 입력 정책

### 2.1 거절 범주

| `category` | 거절하는 요청 | 예 | 이유(사용자에게 말할 것) | 권하는 대안 |
|---|---|---|---|---|
| `ip` | 저작권·상표·브랜드·로고·기존 캐릭터·IP를 따르는 요청, "~처럼 똑같이" | 유명 캐릭터 귀 모양 말풍선, 브랜드 로고 간판 | 저작권 문제가 생길 수 있어요 | 모양과 색으로 묘사 |
| `people` | 실존 인물·유명인, 사람 얼굴·초상(커플 본인 포함) | 연예인 실루엣 벽 장식, 우리 얼굴 초상 | 실제 사람 그림은 만들 수 없어요 | 풍경·무늬 |
| `unsafe` | 성적·폭력·혐오·차별·자해·불법 | 선정적 곡선, 피 무늬, 혐오 상징 | 안전하고 포근한 앱이라서요 | 포근한 장식 |
| `personal` | 개인정보·전화번호·주소·URL·QR·글자 위주 그림 | 전화번호가 크게 보이는 벽, QR 무늬 | 개인정보·링크·글자는 그림 안에 넣지 않아요 | 글자는 방의 짧은 문구로 따로 |
| `photo_like` | 사진처럼 사실적인 이미지 | 포토리얼한 풍경 | 손그림 느낌의 장식만 만들어요 | 부드러운 손그림 묘사 |
| `off_purpose` | 배경·말풍선·작은 방 소품 밖의 목적: 캐릭터·마스코트 변경·**마스코트나 앱 캐릭터를 닮은 소품(눈·입이 있는 얼굴 모양)**·기능 요청, 정치·종교 선전 | 곰 캐릭터, 마스코트 색 바꾸기, 눈코입 달린 쿠션, 게임 | 만들 수 있는 건 배경, 말풍선, 작은 방 소품뿐이에요(캐릭터는 안 돼요) | 배경·소품 장식 |
| `injection` | 지시 무시·시스템 프롬프트 요구·형식 우회·원본 JSON/SVG를 직접 주입 | "이전 지시 무시", "<script>" | (거절 문구는 `off_purpose`와 같은 말투로 순하게) | 배경 장식 |

- **혼합 요청**: 허용 부분과 위반 부분이 섞이면 **전체를 거절**하고 허용되는 부분을 대안으로 권한다(부분 적용 없음, 가정).
- **마스코트**: 어떤 요청도 마스코트를 바꾸거나 새로 만들 수 없다(FR-018). 마스코트를 닮은 캐릭터 요청은 `off_purpose`.
- **재생성 차단**: 신고로 제거된 장식과 같은 지문(`GenerationBlock`)의 요청은 `ip`(또는 해당 범주)로 거절한다.

### 2.2 집행 방식

1. **결정론적 사전 필터(서버, 모델 호출 전)**: 프롬프트 길이 상한(기존 상한 + 생성 요청 200자 가정), 제어 문자·마크업(`<`, `>`, `{`·`}` 연속 구조)·URL·`@핸들`·전화번호·QR 요청 패턴 검출 → `personal`/`injection`. 한국어·영어·일본어 패턴을 쓴다. **단어 필터만으로는 충분하지 않다**(`research.md` 4장).
2. **분류 호출(모델)**: 구조화 출력 `{ "decision": "allow" | "refuse", "category": …, "mixed": boolean }`만 받는다. 사용자 프롬프트는 "신뢰할 수 없는 데이터" 영역에 넣고 분류 지시와 분리한다. 호출 오류·형식 오류는 **거절이 아니라 실패**(`503 GENERATION_FAILED`)로 처리하고 횟수를 쓰지 않는다. 분류가 `allow`여도 4~6 계층이 계속 작동한다.
3. **적용 범위**: 입력 정책은 US8부터 **모든 꾸미기 프롬프트**(카탈로그 배치 요청 포함)에 적용한다. US2만 있는 단계에서는 기존 금지 IP 지칭 거절(`prompt.brand.*`)만 쓰고, US8부터는 같은 거절이 `gen.refuse.*`로 모인다(키는 둘 다 유지).
4. **프롬프트에 들어가는 것**: 현재 요청 문장, 최소한의 현재 장면 요약, 카탈로그 ID·설명, 기준 라이브러리와 스타일 규칙. **날짜·이메일·이름·초대 코드·다른 구성원 정보는 보내지 않는다**(FR-017 기존). 상대가 적은 공유 대화 메시지를 모델 입력에 넣지 않는다(간접 주입 방지).

### 2.3 거절 문구(ko/en/ja, 번역 키)

원칙: 친근하게, **무엇이 안 되는지와 이유**를 짧게, **허용되는 대안 하나**를 권하고, 횟수를 쓰지 않았다고 알린다. 영어·일본어는 원어민 검수 전 초안이다. 키와 문구는 `design/i18n-copy.md`의 `gen.refuse.*`와 같다.

| 키 | 한국어 |
|---|---|
| `gen.refuse.title` | 이 장식은 만들 수 없어요 |
| `gen.refuse.ip` | 이미 있는 캐릭터·브랜드·로고나 다른 사람의 작품을 닮은 그림은 만들 수 없어요. 저작권 문제가 생길 수 있어서예요. 대신 '연한 노란 별 무늬 벽 장식'처럼 모양과 색으로 말해 주세요. |
| `gen.refuse.people` | 실제 사람이나 유명인이 나오는 그림은 만들 수 없어요. 대신 '구름 사이로 달이 보이는 창밖 풍경'처럼 풍경이나 무늬로 말해 주세요. |
| `gen.refuse.unsafe` | 성적이거나 폭력적이거나 누군가를 해치거나 차별하는 내용은 만들 수 없어요. 포근한 분위기의 장식으로 다시 말해 주세요. |
| `gen.refuse.personal` | 전화번호, 주소, 링크, QR 코드나 글자가 많은 그림은 만들 수 없어요. 글자는 방의 짧은 문구로 따로 넣을 수 있어요. |
| `gen.refuse.photo` | 사진처럼 실제 같은 이미지는 만들 수 없어요. 모피의 세계처럼 부드러운 손그림 느낌으로 말해 주세요. |
| `gen.refuse.purpose` | 배경이나 말풍선 장식만 만들 수 있어요. 캐릭터나 다른 물건은 만들 수 없고, 모피는 바꿀 수 없어요. '벽 아래 물결 띠'처럼 배경 장식으로 말해 주세요. |
| `gen.refuse.note` | 이번 요청은 오늘 횟수에 들어가지 않았어요. |

(영어·일본어 문구는 `design/i18n-copy.md`.)

## 3. 출력 검증

공유 검증기(`packages/scene-contract`, 참고 구현 `design/tools/mopi-shape/`)가 서버에서 돌고 앱에서 렌더 직전에 한 번 더 돈다. 검증 항목은 `contracts/generated-object.schema.json`(구조)과 검증기(교차 검사)이며 안정적인 오류 코드를 쓴다.

| 영역 | 규칙 |
|---|---|
| 형식 | 허용목록 JSON만(키 허용목록, `additionalProperties:false`, `__proto__` 등 금지 키), 텍스트·이미지·URL·스크립트·참조·변환·투명·그라데이션·애니메이션이 형식에 없음, SVG 문자열 거부 |
| 한도 | 도형 ≤40, 경로 문자 ≤600·명령 ≤48(M L H V C Q Z 절대 대문자만), 점 ≤24, JSON ≤12KB, viewBox 32~512, 복잡도 ≤60, 좌표 소수 2자리 이하·범위 [−8, w+8]×[−8, h+8] |
| 색 | 채움색 ≤4가지, 앱 팔레트 허용목록(일러스트 팔레트 15색 + 방 낮 벽·바닥색)만, 윤곽선 색 고정 |
| 라벨 | 1~24자, 허용 문자만, URL·`@`·`<`·`>`·연속 5자리 이상 숫자 금지 |
| 말풍선 | 글 영역 `textArea`가 viewBox 안에 있고(너비 ≥40%, 높이 ≥25%), 그 뒤를 덮는 rect/ellipse/poly가 있으며, 글자색과 채움색 대비 ≥4.5:1 |
| 배치 | 배경 조각은 카탈로그 오브젝트·마스코트 아래 층, 보호 영역 규칙(FR-015)은 배경 띠만 예외(위 요소 대비 검증) |
| 스타일 적합도 | 색 수·윤곽 규칙·곡선 비율 등 휴리스틱 점수 0~1이 임계값(0.7 가정) 미만이면 실패. **스타일 가까움만 잰다, 저작권 유사도가 아니다.** |

검증 실패는 **오류 코드 목록**을 모델에 되돌려 한 번 다시 만들게 한다(사용자 프롬프트는 되풀이하지 않는다). 두 번째도 실패하면 `503 GENERATION_FAILED`.

## 4. 2차 모델 검사

- **별도 호출**(다른 시스템 지시, 생성 호출의 문맥을 공유하지 않음)이 `{프롬프트, 라벨, 문서 요약(도형 종류·개수·팔레트 이름·좌표 범위), 정책 범주표}`를 받아 `{ "decision": "pass" | "fail", "category": … }`를 돌려준다.
- 검사 대상은 **프롬프트와 결과의 일치·정책 위반 신호**다. 호출이 실패하거나 형식이 틀리면 **실패 처리**(fail-closed).
- **한계**: 텍스트·구조 기반이라 그림 자체를 보지 못한다. 렌더한 이미지를 보고 판단하는 검사(서버 래스터 렌더 + 비전 모델)는 비용·구현이 늘어 **열린 질문**(`spec.md` Open Decisions 17)이다. 그동안은 형식 제한(도형 수·평면 색·글자 없음)과 신고가 보완한다.
- 비용: Haiku 5.5, 성공 1회당 약 $0.0004(`plan.md` 표, 추정).

## 5. 재시도와 실패 안내

- 재시도는 **최대 1회**(검증·2차 검사 실패 때만). 입력 정책 거절은 재시도하지 않는다.
- 실패 안내(ko): 제목 "이번에는 만들지 못했어요", 본문 "잠시 뒤 다시 말해 주세요. 방은 그대로예요. 오늘 횟수는 쓰지 않았어요."(`gen.fail.*`).
- 킬 스위치가 꺼진 경우: "새 장식 만들기를 잠시 쉬어요. 이미 만든 장식과 다른 꾸미기는 그대로 쓸 수 있어요."(`gen.disabled.*`).

## 6. 횟수와 남용 한도

| 한도 | 값(가정, 서버 설정) | 기준 | 초과 시 |
|---|---|---|---|
| 하루 꾸미기(**성공한 미리 보기만**) | 커플당 3회, 방 시간대 자정 초기화 | `daily_request_count` | `429 DAILY_LIMIT_REACHED`, 안내 "내일" |
| 시도(거절·실패 포함) | 커플당 하루 30회 | `GenerationAttempt` | `429 RATE_LIMITED` |
| 분당 요청 | 사용자당 4회 | 슬라이딩 윈도 | `429 RATE_LIMITED` + `retryAfterSeconds` |
| 연속 거절 | 1시간 안 5번 → 그 커플 생성 1시간 쉼 | 쿨다운 | `429 RATE_LIMITED` |
| 일일 거절 누적 | 15번 → 그날 생성 잠금 + 운영자 표시 | 일일 | 잠금 |
| 신고 | 사용자당 하루 10건 | `Report` | `429 REPORT_RATE_LIMITED` |
| 보관함 | 커플당 상한 = 서버 설정값(기본 40, 가정; `active + candidate`) | `GeneratedObject` | `409 LIBRARY_FULL`(모델 호출 전) |
| 운영자 차단 | 커플 단위 `generation_blocked_until` | 운영자 설정 | `503 GENERATION_DISABLED`(그 커플만) |

- **왜 거절·실패가 횟수를 쓰지 않나(가정)**: 실패에 벌을 주면 사용자는 안전한 요청도 겁내고, 거절을 횟수에 세면 "정책이 나를 벌준다"는 느낌이 든다. 대신 **시도 한도와 쿨다운**이 남용 비용을 막는다. 소유자가 거절·실패도 세기를 원하면 `daily_request_count` 증가 위치만 옮기면 된다(`spec.md` Open Decisions 14).
- **계정 단위 제재**: 반복 남용은 운영자가 `generation_blocked_until`을 설정하거나 Supabase Auth 계정 정지(기존 수단)로 처리한다. 자동 영구 차단은 두지 않는다.

## 7. 로깅과 보관

- `GenerationAttempt`에 입력 정책 판정·범주·결과 판정·재시도 횟수·검증 코드·소모 여부·모델 ID·토큰 수와 **남용 대응용 프롬프트**를 남긴다. **보관 30일(가정)** 뒤 삭제하고, 공간이 종료되면 즉시 읽을 수 없고 공간의 완전 삭제(내부 예약 작업) 때 함께 지운다. 이용자 화면에는 보이지 않고 RLS로 클라이언트가 읽지 못한다.
- 일반 로그에는 프롬프트·모델 출력·키·서명 URL·초대 코드를 쓰지 않는다(기존 allowlist 규칙).
- 개인정보 처리방침에 "AI 처리와 남용 방지를 위한 프롬프트 판정 기록 보관"을 넣어야 한다(법률 검토, `spec.md` Open Decisions 18).

## 8. 킬 스위치와 비상 대응

| 스위치 | 효과 | 적용 |
|---|---|---|
| `generation_enabled=false` | 새 생성 요청 거절(`GENERATION_DISABLED`), 카탈로그 꾸미기는 계속 | 서버 요청마다 읽음, 앱은 `features.generation`으로 화면 맞춤 |
| `generated_render_enabled=false` | 방·보관함·미리 보기에서 생성 장식을 그리지 않음(데이터는 보존) | 스냅샷의 `generatedObjects`가 비고 앱이 그리지 않음 |
| `generation_min_validator_version` 상향 | 강화된 검증기로 렌더 전 재검증 | 앱이 재검증 실패 장식을 그리지 않음 |
| 커플 단위 `generation_blocked_until` | 한 커플의 생성만 차단 | 서버 |

비상 절차(수동, PoC): ① 신고·모니터링에서 문제 감지 → ② `generation_enabled=false` → ③ 필요하면 `generated_render_enabled=false` → ④ 대상 장식 `removed_by_operator`와 `GenerationBlock` → ⑤ 원인 범주 분석 후 입력 정책·검증기·레드팀 세트에 사례 추가 → ⑥ 스위치 복구. 스위치는 앱 업데이트 없이 서버 설정으로 바꾼다. (스위치 변경 권한자·연락 체계는 열린 질문.)

## 9. 신고와 운영 처리 (요약)

- 방의 생성 장식을 누르면 **장식 상세 시트**에서 "신고하기"(사유: 저작권을 닮음 / 불쾌하거나 성적·폭력적임 / 개인정보가 들어 있음 / 기타 + 선택 메모) → 확인 → **신고자 화면에서 즉시 숨김**(상대는 검토 전까지 그대로, 시트에 "내 화면에서만 숨겼어요") → 운영자 대기열.
- 운영자(PoC: 수동)는 서버 전용 `review_report`로 `removed`(두 사람 화면에서 제거 + 재생성 차단) 또는 `kept`로 결정한다. 신고자는 "접수됨"과 "검토를 마쳤어요"를 보고, 제거된 경우 두 사람 모두 "검토 결과 이 장식은 방에서 빠졌어요"를 한 번씩 본다(신고자는 상대에게 알리지 않는다).
- 신고 내용·메모는 상대에게 보이지 않는다. **방 전체 신고**(`room_scene`)도 같은 시트와 설정의 문의·신고에서 한다. **홈 커버 사진은 신고 대상이 아니다**(업로드된 사진이며 AI 생성물이 아니다, 결정 `spec.md` Decided 38). 연결 끊기와 별개다.
- 절차 문서: `docs/operator-review-runbook.md`(태스크, 목표 응답 시간·담당자는 열린 질문).

## 10. 약관·안내에 들어갈 것 (법률 검토 전 항목)

이용자가 프롬프트에 책임진다 · 앱이 장식을 제거하거나 생성을 막을 수 있다 · 결과가 틀리거나 마음에 들지 않을 수 있다 · 소유권·비침해를 보장하지 않는다 · 프롬프트와 판정 기록이 남용 방지용으로 30일 보관된다 · 신고와 연결 끊기 수단 · 만 14세 이상. 스토어·Anthropic 정책 확인 항목은 `research.md` 9.2~9.3.
