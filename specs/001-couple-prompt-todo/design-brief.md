# Claude Design 시각 설계 브리프

## 시각 결정과 다음 단계

- 캡틴은 stage-1 시안 중 **A(손그림 따뜻함)**를 최종 방향으로 선택했다(처음 B(평면 기하학)를 고른 뒤 A로 변경). 완성된 시각 설계와 구현 인계 산출물은 [`design/`](../../design/README.md)에 있다.
- stage-1 artifact의 **고정 컨트롤 레이어**와 **프롬프트 입력 패널**을 승인했다. stage 2는 같은 artifact canvas에서 진행하고, 완성된 화면과 구현 인계 산출물을 저장소에 전달한다.
- 앱 정체성을 나타내는 하나의 앱 소유 마스코트를 둔다. 마스코트 base design은 앱 소유로 고정하고 방/메인 페이지에 기본 표시한다. 방에서는 머리·얼굴·목·손의 카탈로그 착용품, 승인 색 팔레트, 제한된 표정/포즈, 크기와 위치를 꾸밀 수 있다. 기존 캐릭터·브랜드를 요청하는 프롬프트는 거절한다.
- 방은 낮/밤 콘셉트를 모두 표현한다. 사용자가 직접 전환하거나 시간대에 따라 전환할 수 있으며, 기본은 공간 생성자의 시간대 자동 전환이다. 설정에서 모드와 시간대를 바꿀 수 있다. 앱 인터페이스는 기기 설정을 기본으로 따르는 다크 모드와 수동 재정의를 제공한다.
- 출시 언어는 한국어(`ko-KR`), 영어(`en-US` 기본 변형 제안), 일본어(`ja-JP`)다. 날짜·숫자·D-day 문구를 각 locale에 맞춘다.

## 목적과 범위

이 브리프는 구현 전에 Claude Design에서 완성할 모바일 앱 시각·상호작용 설계 입력이다. 현재 제품 명세와 기술 계획의 경계를 지키고, 화면의 실제 스타일은 아래 질문에 답해 결정한다. 이 단계에서 앱 코드나 개발자용 UI를 만들지 않는다.

제품은 둘이 함께한 날짜를 확인하는 메인 D-day 페이지와, 프롬프트로 함께 장식하는 방 페이지를 가진다. 방 꾸밈은 카탈로그 2D 오브젝트와 짧은 텍스트를 자유 배치·회전·레이어링한다. 프롬프트 결과는 적용 전에 미리보기, 확인, 취소할 수 있고 과거 버전을 되돌리거나 복구할 수 있다.

## 설계할 화면과 상태

각 화면은 iOS/Android의 기본 안전 영역, 화면 크기, 키보드, 접근성 글자 확대를 고려해 설계한다. 필요한 경우 화면별 empty/loading/error/offline/loading states를 모두 보여 준다.

1. **온보딩 / 시작** — 제품의 커플 공간·메인 D-day·함께 꾸미는 방 소개, 로그인 시작, 개인정보/약관 진입, 서비스 연령/스토어 정책 문구 위치. 첫 실행 및 재실행 상태.
2. **로그인 선택 / 인증** — 카카오, Apple, 이메일 선택; OAuth 이동·복귀, 이메일 입력·코드/링크 안내, 처리 중, 취소, 재시도, 만료·오류 상태.
3. **커플 공간 생성** — 함께한 날짜 입력/수정, 날짜 형식·유효성 오류, 생성 중, 성공, 연결 오류.
4. **초대 코드 생성 및 공유** — 생성 중, 코드와 만료 시간, OS 공유 시트, 복사, 만료 임박, 공유 취소, 재발급(기존 코드 폐기 안내), 네트워크 오류.
5. **초대 코드 입력/수락** — 코드 입력, 코드 확인, 초대 상대/공간 확인과 수락, 만료·사용됨·유효하지 않음, 공간 인원 초과, 이미 다른 공간 소속일 때 안내 상태.
6. **메인 D-day 페이지** — 기본 D-day와 앱 소유 마스코트, 날짜 편집, 상대 초대 미완료, 초대 완료/상대 참여, 로딩, 동기화 오류, 오프라인 마지막 상태, 날짜 미설정/수정 상태. D-day 문구 및 날짜 형식은 선택 언어를 따른다. 방으로 이동하는 명확한 진입 버튼.
7. **방 페이지** — 마스코트가 기본 포함된 확정 장면, 낮/밤 직접 전환·시간대 자동 전환, 네이티브 D-day 위젯, 방 도구(설정/꾸미기/기록/되돌리기/삭제/나가기 등 고정 조작), 마스코트 슬롯/색/표정/포즈 꾸미기, 상대방 변경 실시간 반영, 로딩, 오프라인 읽기 전용, 동기화 중/실패, 장면 데이터 복구 오류.
8. **공유 프롬프트 대화 / 입력** — 둘이 보는 message history와 live preview, 점유 세션 idle 상태, 한쪽이 입력 중인 상태와 점유자 표시, 비점유 파트너의 읽기 전용 disabled input, submit 중, online-only, 동의 필요, 하루 10회 소진, 지원하지 않는 요청, 실패/재시도. 키보드가 주요 고정 컨트롤을 가리지 않는 상태.
9. **공유 미리보기 / 적용 확인·취소** — 두 파트너에게 같은 현재 방과 후보를 보여 주고, 점유자에겐 confirm/cancel, 상대에겐 read-only 표시. 점유 상태/owner 표시, 유효성 경고, 지원 범위 초과/수정 제안, 네트워크/모델 오류, 세션 만료 직전 상태.
10. **되돌리기 확인** — 현재 점유자의 직전 적용 결과/원래 방 복구 확인, 취소, 성공 및 undo 성공 후 lease 해제; 늦은 중복 요청 시 server conflict 안전 상태.
11. **버전 기록 / 복구** — 버전 목록·시각·변경자, 미리보기, 선택, 복구 확인, 복구 성공, 빈 기록, 이전 데이터 호환 오류. 프롬프트 전문은 기본 목록에서 공개하지 않음.
12. **해외 AI 처리 동의** — 전송 정보(프롬프트와 필요한 방 배치), 처리 목적, Anthropic 등 처리 사업자/국가, 보관·철회 방식, 동의/나중에/철회 상태. 요청 직전 사용자별 선택과 커플 공동 사용 조건을 UI에서 설명.
13. **설정** — 프로필/로그아웃, 앱 언어 선택(기기 언어 기본값), `system/light/dark` UI 테마 선택, 날짜 편집, 동의 상태·철회, 앱 정보, 개인정보 처리방침/약관/신고 연락처, 공간 종료 진입, 로딩/오류 상태.
14. **공간 종료 / 30일 복구** — 결과와 공유 접근 중단을 설명하는 확인, 취소, 종료 직후 복구 가능 기한, 복구 확인, 복구 성공/실패, 30일 만료 및 삭제 완료. 잘못 누른 느낌을 줄이지 않도록 결과와 날짜를 또렷하게 쓴다.
15. **신고 / 차단** — 상대/공유 문구/장면 신고 entry, 사유 선택, 제출 성공/실패, 차단 확인과 차단 후 결과, 지원 연락처. 스토어 리뷰 전에 실제 운영 경로를 연결한다.
16. **공통 오류·빈·로딩·오프라인 상태** — 서버/AI 일시 장애, 로그인 만료, 접근 거부, 인터넷 끊김, 요청 한도, 구버전 장면, 삭제된 에셋, 데이터 동기화 대기. 앱은 마지막 확정 방·D-day를 표시하고 오프라인 편집이나 미리보기를 적용하지 않는다.

## 장면과 고정 UI 경계

- 배경/콘텐츠 영역은 자유 배치 2D 장면이다. 오브젝트와 짧은 텍스트만 장면 그래프에 둔다. 오브젝트는 위치·크기·회전·앞뒤 순서를 가질 수 있다.
- 설정, 기록, 되돌리기, 삭제, 공간 나가기, 닫기, 확인/취소 같은 컨트롤은 장면 캔버스 외부의 네이티브 뷰 레이어에 둔다. 장식이 버튼 영역이나 실제 터치 영역을 가리거나 터치를 가로채지 않도록 한다.
- D-day는 앱 소유 의미 위젯이며 장면 캔버스에서 렌더하지 않고 별도 네이티브 뷰로 겹쳐 표시한다. 위젯 자체의 배치·크기·모양·색은 안전 범위에서 바꿀 수 있고, 방에서 숨길 수 있다. 프롬프트로 날짜 값·정확성·접근성 레이블을 바꾸지 못한다. 위젯을 숨겨도 메인 D-day 페이지는 유지한다.
- 보호 영역은 고정 디자인 좌표가 아니라 시스템 안전 영역, 고정 컨트롤, D-day 위젯, 필수 가독성 영역의 실제 측정값에서 결정한다. 서로 다른 화면비와 글자 크기에서 영역이 달라져도 충돌하지 않는 예시를 보여 준다.
- prompt와 preview는 shared conversation에 저장하고 두 파트너에게 실시간 표시한다. 점유 파트너에게만 입력·요청·confirm/cancel/undo를 제공하고, 비점유 파트너에게는 owner 표시 및 대화/preview의 live read-only view를 제공한다. preview는 공유 대화에는 보이지만 confirm 전 공유 room theme/version을 바꾸지 않는다. 취소하면 현재 방이 그대로 남고 lease가 풀린다.
- 점유 중 파트너의 작성 상태를 보여 준다. idle lease는 3분(가정)이며 배경/종료 시 heartbeat가 멈춰 만료된다. 만료 후 상대가 takeover하여 대화 및 이전 preview를 이어서 본다. 캡틴은 timeout과 read-only UI 동작을 조정할 수 있다.

## 접근성·가독성·다국어

- 본문/작은 글자 대비는 최소 4.5:1, 큰 글자는 3:1을 목표로 한다. 색만으로 상태를 구분하지 않고 레이블·아이콘·형태를 함께 사용한다.
- D-day는 네이티브 접근성 트리에서 읽을 수 있고, 숫자·레이블 순서를 한국어·영어·일본어 스크린 리더에서 검토한다. 장식 오브젝트는 기본적으로 읽기 순서에서 제외한다.
- 시스템 글자 크기 확대 시 문구/D-day 영역이 커지고 보호 영역이 재계산되는 상태를 디자인한다. 자동 축소로 글자를 읽기 어렵게 만들지 않는다.
- 탭 영역은 플랫폼 권장 최소 크기에 맞추고, 긴 누름 외에 명확한 탭 동작과 접근성 레이블을 제공한다.
- 모든 UI 문구는 번역 리소스로만 제공하고, 지원 언어 추가에 화면 코드 변경이 필요하지 않도록 설계한다. 기기 언어 기본값, 앱 언어 선택, 날짜·숫자·D-day 표기 관례, 긴 번역문, pseudo-localization을 검수한다.
- AI 프롬프트는 지원 언어로 입력할 수 있고, 커플이 쓴 방 텍스트는 번역하지 않고 입력 그대로 저장한다. 서버 오류는 언어 중립 코드이며 UI가 현재 언어로 메시지를 렌더한다.
- 한국어·영어·일본어 각각의 본문/버튼/숫자 조합, 줄바꿈, 텍스트 확장, 긴 날짜 문구를 확인한다. 권장 번들은 Inter (Latin/Latin-ext), Noto Sans KR (Hangul), Noto Sans JP (Japanese) family를 분리해 포함하는 안이다. 지원 glyph와 fallback을 실제 fixture로 확인하고 한 CJK font가 다른 지역 script를 덮는다고 가정하지 않는다. OFL license, reserved name 조건, 제작자/출처를 기록한다. 두 Noto variable subset TTF는 약 19.1MB 합산(Inter 제외, 압축 전)이며 실제 iOS/Android build size를 측정한다. 원격 폰트 로딩은 쓰지 않는다.
- 대비와 가독성은 낮 방+밝은 UI, 낮 방+어두운 UI, 밤 방+밝은 UI, 밤 방+어두운 UI 모든 조합에서 확인한다. 보호 영역과 D-day 접근성은 조합과 글자 크기에 관계없이 유지한다.

## 에셋 목록과 디자인 단계 질문

V1 카탈로그 규모는 라이선스 확인이 끝난 작은 2D 오브젝트 **24–36개**다. 마스코트 포즈와 착용 아이템도 이 수에 포함된다. 화면 장면에는 마스코트를 포함해 오브젝트 최대 16개, 짧은 텍스트 최대 3개만 둔다. 아래는 30개를 상정한 분할 제안이며, 구체 asset ID는 stage 2에서 확정한다. 4개 마스코트 포즈, 8개 착용품, 18개 일반 오브젝트의 초기 30개 split은 캡틴 승인 가정이다.

| 종류 | 제안 수 | 필요한 용도 |
|---|---:|---|
| 마스코트 포즈 variant | 4 | 앱 정의 상태 |
| 머리·얼굴·목·손 슬롯 착용품 | 8 | 슬롯별 카탈로그 아이템 |
| 일반 방 오브젝트 | 18 | 식물·소품·수집품·날씨·축하·추상 요소 |
| **합계** | **30** | 24–36 범위 내 조정 가능 |

디자인 단계에서 답할 질문:

1. 마스코트의 고유 base design과 낮/밤별 asset variant를 어떻게 정의할까?
2. 제한 팔레트, 슬롯 아이템과 표정/포즈가 모든 테마에서 분명하고 읽히는지 어떻게 확인할까?
3. 선택된 A 방향의 화면·컴포넌트 토큰을 어떻게 일관되게 적용할까? [`design/tokens.json`](../../design/tokens.json)에 확정했다.
4. 기존 캐릭터·브랜드 요청과 에셋 권리를 어떻게 문서화할까? 앱 소유 마스코트와 승인 카탈로그 외 모방·복제는 허용하지 않는다.

에셋 인계는 각 asset ID, 라이선스/제작자/원본 증빙, 파일 checksum, 최종 크기, 투명 배경 여부, 여백·회전 안전 공간을 manifest 표에 연결한다. 실행 앱은 고정된 이미지 파일만 렌더하며 임의 SVG/코드를 수신하지 않는다. 구현 검토용 제공 포맷은 투명 배경 PNG 또는 정적 WebP @2x/@3x이며, ICC/sRGB·투명도·파일 크기 권고와 픽셀 크기는 실제 디자인 canvas 배수에 맞춰 산정한다. 디자인 원본의 벡터 파일은 작업 원본/권리 보관을 위해 전달할 수 있지만 V1 런타임 리소스에는 넣지 않는다.

## 제품 어조

친밀하고 차분하며, 두 사람을 동등한 구성원으로 대한다. 꾸밈을 과장하거나 값비싼 선물·이상적인 연애를 기본값처럼 말하지 않는다. 동의, 공유, 종료/복구, AI 처리 실패는 짧고 직접적인 한국어로 설명하며 모호한 긍정 표현으로 결과를 감추지 않는다. 디자인 시안 문구는 실제 제품 카피처럼 완성하되, 가격/요금제·사진·캘린더·할 일 기능을 암시하지 않는다.

## Claude Design에서 돌려받을 필수 산출물

1. **완성된 화면 설계본**: 위 화면과 모든 주요 상태를 포함하는 공유 가능한 디자인 파일 또는 이미지 세트. iOS/Android 대표 viewport, 긴 문구·오류·빈·오프라인 예시를 포함한다. 아직 구현하지 않은 화면은 stub로 두지 말고 디자인 단계에서 완성한다.
2. **컴포넌트와 토큰 목록**: 버튼/텍스트 입력/확인창/탭 바/상태 메시지/프롬프트 카드/에셋 오브젝트/D-day 네이티브 위젯의 역할·변형·상태·접근성 이름.
3. **수치 토큰**: 색 이름과 HEX/RGB, 본문/큰 글자 대비 측정, 여백·간격 scale, 모서리·선 두께, 폰트 family/weight/size/line height, 안전 영역/터치 영역 기준, elevation/shadow.
4. **에셋 사양서**: 카탈로그 목표 수와 카테고리별 최종 목록/ID, 마스코트 base/pose와 착용 slot 조합, 낮/밤 자산 variant, 픽셀 크기와 @2x/@3x 규격, 투명 여부, 포맷, 파일 크기 목표, 대체 텍스트/장식성 구분, 권리·제작·출처 기록, 교체/폐기 절차.
5. **상호작용 노트**: 주요 화면 간 이동, 키보드와 공유 시트 동작, preview/confirm/cancel/undo/restore, D-day 위젯 이동/숨김, 스크롤/레이어 순서, offline/error/retry, 두 파트너 동기화가 눈에 보이는 방식.
6. **구현 인계 요약**: 반응형 viewport 규칙, 보호 영역 예시, 기기별 예외, 고대비/글자 확대/스크린 리더 주석, 미결 질문 및 제안 답변. 구현팀은 이 완료된 설계를 기준으로 화면 코드를 시작한다.
