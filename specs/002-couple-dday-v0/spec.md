## Clarifications

### Session 2026-11-02

- Q: V0의 제품 범위는? → A: Apple 로그인, 커플 연결, D+Day 홈, 자동·생일·시즌·직접 추가 기념일, iOS 위젯, 로컬 알림, 최소 설정, TestFlight 배포·OTA. 방·프롬프트·커버 사진은 숨긴다(오너 피벗).
- Q: 알림 시간 기본값(Q2)? → A: **그려진 대로.** 기념일 당일 오전 9:00(공간 시간대) + 미리 알림 1개, 기본 "하루 전". 미리 알림은 없음/하루 전/3일 전/일주일 전 중 하나만 고른다.
- Q: 알림 문구에 무엇을 보이나(Q4)? → A: **그려진 대로.** 자동 기념일은 제목("오늘은 우리 100일이에요"), 시즌은 제목("오늘은 빼빼로데이예요"), 생일은 이름("오늘은 하루님 생일이에요"), 직접 추가는 제목을 숨긴 "오늘은 둘만의 기념일이 있어요".
- Q: 500일·1000일을 넣나(Q5)? → A: **넣지 않는다.** V0의 일수 기념일은 50·100·150·200·300일이다.
- Q: 신고·차단(S15)을 V0 설정에 두나(Q8)? → A: **뺀다.** 두 사람 공간이며 문의하기로 대신한다.
- Q: 알림 권한은 언제 묻나(Q11)? → A: **그려진 대로.** 연결 완료 직후 사전 안내 한 번(`V0-start-notify`) → "알림 켜기"일 때만 iOS 권한 창. 앱 첫 실행에서는 묻지 않는다.
- Q: 이 출시의 버전 이름은? → A: **V0**(오너 2026-11-02, "V0 통일해서 진행하자, V1은 AI활용 방 꾸미기 기능이 들어간 버전"). 이 문서의 D+Day 출시가 V0이고, **V1은 AI 방 꾸미기(방·프롬프트)가 들어가는 다음 버전**이다. 보드·문구 일부는 이 결정 전에 그려져 이번 출시를 "V1"이라고 부르지만, 이 기능 폴더와 handoff는 모두 V0으로 쓴다.
- Q: 디자인 정본은? → A: 위 아티팩트가 정본이다. 저장소 `design/` 미러(PR <https://github.com/zzzRYT/couple-app/pull/25>)는 아직 병합 전이라 이 기능은 거기에 의존하지 않는다.

## 용어

- **공간**: 연결된 두 사람의 공유 데이터 묶음(기존 `couple_space`). **공간 시간대**: 공간의 IANA 시간대(기존 `couple_space.time_zone`).
- **사귄 날**: 공간의 시작일(기존 `couple_space.anniversary_date`). 당일이 1일째(D+1)다.
- **기념일 종류**: 함께한 날(일수 50·100·150·200·300, 매년 주년), 생일, 시즌(빼빼로데이 11/11, 크리스마스 12/25), 직접 추가.
- **화면 ID**: 아티팩트 보드의 프레임 이름(예: `V0-home`, `V0-anniv-list`). 수락 기준의 "보드와 일치"는 이 프레임을 말한다.
- **요구 사항 ID**: `V0-F01`~`V0-F14`(기능), `V0-DR-01`~`V0-DR-06`(날짜 규칙), `V0-NF-01`~(공통 품질). 수락 시나리오 ID는 `<요구 사항 ID>-AC-<두 자리>`다(예: `V0-F07-AC-03`). 테스트 이름에 이 ID를 그대로 넣는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 오너와 여자친구 폰에 빈 앱이 TestFlight로 깔린다 (Priority: P1) — V0-F14

오너는 GitHub에서 버튼 한 번으로 iOS 빌드를 만들고 TestFlight에 올린다. JS·문구·자산만 바뀌면 새 빌드 없이 OTA로 고친다.

**Why this priority**: 모든 다음 단계의 확인이 실제 폰(TestFlight)에서 이루어진다. 서명·App Group 위험을 가장 먼저 줄인다.

**Independent Test**: `workflow_dispatch` 한 번으로 빌드가 TestFlight에 나타나고, 내부 테스터 폰에 설치된 앱에 preview 채널 OTA 문구 변경이 보인다.

**Acceptance Scenarios**:

1. **V0-F14-AC-01** — **Given** EAS·Apple 자격 증명이 등록된 저장소, **When** 오너가 `release-ios` 워크플로를 `profile=testflight`로 실행하면, **Then** EAS Build가 `.dev` bundle id(`com.jinjinstar.aroom.dev`)로 store 서명 빌드를 만들고 성공 시에만 EAS Submit이 App Store Connect에 올린다. 실패하면 제출하지 않는다.
2. **V0-F14-AC-02** — **Given** 올라간 빌드, **When** ASC 처리가 끝나면, **Then** 내부 테스터(오너·여자친구)가 TestFlight 앱으로 설치할 수 있고 빌드 번호는 이전보다 크다(원격 자동 증가).
3. **V0-F14-AC-03** — **Given** preview 채널 빌드가 설치된 폰, **When** 오너가 `ota` 워크플로로 같은 runtime의 JS 변경을 preview 채널에 게시하고 앱을 두 번 다시 열면, **Then** 바뀐 문구가 보인다. native 변경(위젯 extension·권한·플러그인)은 runtime이 달라 OTA로 적용되지 않는다.
4. **V0-F14-AC-04** — **Given** preview에서 확인한 업데이트, **When** 오너가 같은 업데이트 그룹을 production 채널로 승격하면, **Then** production 채널 빌드가 그 업데이트를 받는다. 롤백은 이전 그룹 재게시로 한다.
5. **V0-F14-AC-05** — **Given** 저장소, **When** 비밀 정보를 찾아보면, **Then** Apple·EAS 토큰과 키는 저장소·로그에 없고 GitHub Actions secret과 EAS credentials에만 있다.
6. **V0-F14-AC-06** — **Given** production App ID `com.jinjinstar.aroom`이 소유자 지시로 개인 팀에 등록되어 있고(2026-11-06) 이름·상표 확인(G2)은 아직 열려 있는 상태, **When** push·PR·예약으로 워크플로가 돌아도, **Then** production으로 빌드·제출하지 않는다. production 경로는 오너가 `release-ios`를 `profile=production`으로 직접 실행할 때만 쓴다(`identity.ts`의 G2 메모).
7. **V0-F14-AC-07** — **Given** App Store에서 받은 production 앱, **When** 앱을 열거나 앱으로 돌아왔을 때(6시간에 한 번까지) 설치된 네이티브 버전이 App Store 조회(iTunes Lookup, 앱 id 6831581664)로 읽은 최신 버전보다 낮으면, **Then** `V0-update`(V0-11) 대화 상자가 보이고 "App Store에서 업데이트"는 App Store의 아룸 페이지를 연다. 버전이 같거나 높거나 조회가 실패하면 보이지 않고, development·preview 빌드는 확인하지 않는다. 새 서버 값이나 유료 서비스는 쓰지 않는다.
8. **V0-F14-AC-08** — **Given** `V0-update`, **When** "나중에"를 누르면, **Then** 닫히고 이 기기에서 그 버전으로는 다시 묻지 않으며 더 새 버전이 나오면 다시 뜬다. 최소 버전 규칙이 없어 강제 업데이트는 없다. OTA 업데이트는 네이티브 버전을 바꾸지 않아 이 안내를 띄우거나 없애지 않는다.

### User Story 2 - 로그인하고 둘이 연결된다 (Priority: P1) — V0-F01, V0-F02

처음 연 사람은 짧은 소개를 보고 Apple로 로그인한 뒤(이메일 로그인은 User Story 9) 새로 시작하거나 초대 코드로 참여한다. 만든 사람은 사귄 날과 자기 이름·생일을 넣고 초대 코드를 보낸다. 참여한 사람은 코드를 넣고 확인한 뒤 이름·생일을 넣는다.

**Why this priority**: 두 사람이 연결되어야 나머지 모든 기능에 데이터가 생긴다.

**Independent Test**: 시뮬레이터 두 대(또는 TestFlight 폰 두 대)에서 A가 공간을 만들고 B가 코드로 참여하면 두 기기 모두 `V0-start-connected` → 홈으로 간다.

**Acceptance Scenarios**:

1. **V0-F01-AC-01** — **Given** 로그인하지 않은 첫 실행, **When** 앱을 열면, **Then** `V0-start-intro`(소개 한 장 + "Apple로 계속하기"(첫 번째) + "이메일로 로그인" + 약관 동의 문구)가 보이고 카카오 버튼은 없다(개발 빌드의 테스트용 빠른 로그인은 예외, production·preview에서는 숨김).
2. **V0-F01-AC-02** — **Given** `V0-start-intro`, **When** Apple 시트를 취소하거나 오류가 나면, **Then** S02 취소·오류 상태를 그대로 보여 주고 다시 시도할 수 있다.
3. **V0-F01-AC-03** — **Given** Apple 로그인 성공, 활성 공간 없음, **When** 로그인이 끝나면, **Then** 앱 비밀번호가 없고 안내를 본 적 없으면 `V0-auth-setpw-prompt`(V0-F16)를 거쳐, 그 밖에는 바로 `V0-start-choose`(새로 시작하기 / 초대 코드가 있어요)로 간다.
4. **V0-F02-AC-01** — **Given** `V0-start-choose`, **When** "새로 시작하기"를 누르면, **Then** `V0-start-date`가 열리고 날짜를 고르면 "오늘은 {n}일째 · D+{n}" 미리 보기가 바뀐다(`V0-DR-01`).
5. **V0-F02-AC-02** — **Given** `V0-start-date-picker`, **When** 오늘(기기 시간대) 이후 날짜를 고르면, **Then** `V0-start-date-future` 오류가 보이고 다음으로 갈 수 없다.
6. **V0-F02-AC-03** — **Given** 사귄 날을 고른 상태, **When** 다음을 누르면, **Then** `V0-start-profile`(이름 필수 1~10자, 생일 선택: 월·일, "태어난 해도 넣기" 기본 꺼짐)이 열린다. 이름이 비면 `V0-start-profile-err`가 보이고 저장하지 않는다.
7. **V0-F02-AC-04** — **Given** 프로필 입력 완료, **When** 다음을 누르면, **Then** 이름·생일이 먼저 저장되고 공간이 만들어진 뒤(공간 시간대 = 만든 사람 기기 시간대) `V0-start-invite`(8자리 코드, 24시간·1회, 공유·복사·재발급은 S04)가 보인다.
8. **V0-F02-AC-05** — **Given** `V0-start-invite`, **When** "홈에서 기다릴게요"를 누르면, **Then** `V0-home-pending`으로 가고 홈에 초대 코드가 계속 보인다(PR 26 규칙: 홈 snapshot 새로 고침 뒤에도 새 코드가 사라지지 않음).
9. **V0-F02-AC-06** — **Given** `V0-start-choose`, **When** "초대 코드가 있어요" → `V0-start-enter`에 코드를 넣고 확인하면, **Then** 유효하면 `V0-start-found`("{name}님의 공간이에요", 사귄 날·오늘 일수)가, 만료·사용됨·잘못됨·이미 공간 있음이면 S05 오류가 그대로 보인다.
10. **V0-F02-AC-07** — **Given** `V0-start-found`, **When** "참여하기"를 누르면, **Then** 참여한 뒤 `V0-start-profile`(이름·생일)을 거쳐 `V0-start-connected`("{name}님과 함께한 지 {n}일째예요")가 보인다. "참여하지 않기"는 `V0-start-enter`로 돌아간다.
11. **V0-F02-AC-08** — **Given** A가 `V0-home-pending`에 있음, **When** B가 참여를 마치면, **Then** A는 앱을 연 동안에는 Realtime 힌트로, 아니면 다음에 앱을 열 때 `V0-start-connected`를 한 번 보고(V0-00 흐름 3) `V0-start-notify` 사전 안내를 거쳐 `V0-home`으로 간다.
12. **V0-F02-AC-09** — **Given** 연결 흐름의 어느 단계, **When** 뒤로 버튼을 누르면(스와이프 뒤로는 PR 24대로 막혀 있음), **Then** 이전 단계로 돌아가고 입력한 값은 남아 있다. 공간을 만든 뒤(`V0-start-invite`)에는 날짜·프로필 단계로 돌아가지 않는다(PR 24의 안전한 뒤로 규칙).
13. **V0-F02-AC-10** — **Given** 참여는 했지만 이름을 넣기 전에 앱을 끈 사람, **When** 앱을 다시 열면, **Then** 홈 대신 `V0-start-profile`부터 이어 간다.
14. **V0-F02-AC-11** — **Given** 상대가 아직 참여하지 않은 공간(혼자 만든 공간), **When** 홈 `V0-home-pending`의 "상대에게 코드를 받았어요"나 설정 › 우리 › 상대의 "연결하기 ›"를 누르면, **Then** 각각 `V0-connect-code`(받은 코드 입력)와 `V0-connect`(내 초대 코드 보내기 / 받은 코드 입력하기)가 열린다(V0-10). 연결된 공간에서는 두 진입점이 없고 설정에 "{name} · 연결됨"만 보인다. 오프라인이면 두 진입점이 비활성이다.
15. **V0-F02-AC-12** — **Given** 혼자 만든 공간이 있는 B, **When** `V0-connect-code`에 A의 유효한 코드를 넣고 `V0-connect-move`("상대의 공간으로 옮길까요?")에서 "옮겨서 연결하기"를 누르면, **Then** B의 공간을 닫고(기존 공간 종료) 같은 코드로 A의 공간에 참여해 두 사람 모두 연결된 공간을 본다. 서버 계약은 바꾸지 않는다. 만료·사용됨·틀림·인원 초과·네트워크 오류는 공간을 닫지 않고 S05 오류를, 이 기기에서 만든 내 코드는 `V0-connect-own`을 보여 준다. 혼자 공간이 있는 사람이 초대 링크를 열어도 같은 확인을 거친다.
16. **V0-F02-AC-13** — **Given** B의 공간을 닫은 뒤, **When** 참여가 실패하면(그 사이 만료 등), **Then** 종료 알림을 확인 처리하고 코드를 들고 시작 화면의 코드 입력(`V0-start-enter`)으로 가서 S05 오류를 보여 준다. "공간이 끝났어요" 화면은 보이지 않는다.

### User Story 3 - 홈에서 D+N과 다음 기념일을 본다 (Priority: P1) — V0-F03, V0-F09, V0-F13

연결된 두 사람은 앱을 열면 함께한 일수(가장 큼), 사귄 날, 다음 기념일 카드와 다가오는 기념일 3개를 본다. 기념일 당일에는 축하 카드가 보인다.

**Why this priority**: 앱의 핵심 가치. 기존 백엔드에 바로 연결할 수 있다.

**Independent Test**: 두 계정을 연결한 뒤 기기 날짜를 바꿔 가며 `V0-home`, `V0-home-today`, `V0-home-late`, 오프라인·오류 상태가 보드와 같게 보이는지 확인한다.

**Acceptance Scenarios**:

1. **V0-F03-AC-01** — **Given** 연결된 공간, **When** 홈을 열면, **Then** `V0-home`처럼 앱 이름, 아루미(마스코트), 두 사람 이름, "함께한 지", D+N, "{date}부터", 다음 기념일 카드(제목·날짜·D-n), 다가오는 기념일 3개 + "전체 보기"가 보인다. 커버 사진·방 카드·방 버튼·꾸미기 버튼은 없다.
2. **V0-F03-AC-02** — **Given** `V0-home`, **When** "전체 보기"나 다가오는 기념일 행을 누르면, **Then** 기념일 탭(`V0-anniv-list`) 또는 그 기념일 상세로 간다.
3. **V0-F03-AC-03** — **Given** 상대가 아직 참여하지 않음, **When** 홈을 열면, **Then** `V0-home-pending`(상대 자리 "상대", "상대를 기다리는 중", 초대 코드와 공유·복사·남은 시간, 안내 문구)이 보인다. 상대 생일과 직접 추가 기념일은 연결 뒤에 보인다는 힌트가 있다.
4. **V0-F03-AC-04** — **Given** 상대가 사귄 날을 바꿈, **When** 내가 다음에 홈을 열면, **Then** `V0-home-partner-edited` 안내("{name}님이 사귄 날을 {date}로 바꿨어요")가 한 번 보이고 D+N이 새 날짜로 계산된다.
5. **V0-F03-AC-05** — **Given** 탭 막대, **When** 앱이 활성 공간 상태이면, **Then** 시스템 탭 막대에 홈·기념일·설정 3개만 있다(방 탭 없음).
6. **V0-F09-AC-01** — **Given** 오늘이 100일, **When** 홈을 열면, **Then** 다음 기념일 카드 자리에 `V0-home-today` 축하 카드("오늘은 우리 100일", 본문 "{date}부터 {n}일째 함께했어요.")가 보이고 방 꾸미기 제안 버튼은 없다.
7. **V0-F09-AC-02** — **Given** 오늘이 빼빼로데이 또는 크리스마스, **When** 홈을 열면, **Then** `V0-home-today-season` 카드("오늘은 {title}", 아루미 축하 문구)가 보인다.
8. **V0-F09-AC-03** — **Given** 100일이 3일 전이었고 이 사람이 아직 그 축하를 닫지 않음, **When** 홈을 열면, **Then** `V0-home-late`("{date}이 {title}이었어요. 아루미가 조금 늦게 축하해요.")가 보인다. 생일·시즌·직접 추가는 당일만 보인다.
9. **V0-F09-AC-04** — **Given** 같은 날 주년과 일수(또는 생일·직접·시즌)가 겹침, **When** 홈을 열면, **Then** 카드는 하나만, 우선순위 주년 > 일수 > 생일 > 직접 > 시즌으로 고른다.
10. **V0-F09-AC-05** — **Given** 축하 카드, **When** 닫으면, **Then** 그 사람에게는 다시 보이지 않고(일수·주년은 서버 기록, 그 밖은 이 기기 기록) 상대에게는 영향이 없다.
11. **V0-F13-AC-01** — **Given** 데이터 로딩 중, **When** 홈·기념일 탭을 열면, **Then** `V0-state-loading` 스켈레톤이 보인다.
12. **V0-F13-AC-02** — **Given** 첫 불러오기 실패(네트워크 아님), **When** 화면을 열면, **Then** `V0-state-error`(전부 아니면 없음: 일부만 그리지 않음)와 "다시 시도"가 보인다.
13. **V0-F13-AC-03** — **Given** 마지막으로 받은 데이터가 있고 오프라인, **When** 화면을 열면, **Then** `V0-state-offline`처럼 마지막 데이터 + "오프라인이에요 · 마지막 확인 {time}" 띠가 보이고 편집 버튼은 비활성(점선)이다.
14. **V0-F13-AC-04** — **Given** 받은 데이터가 없고 오프라인(앱을 새로 시작), **When** 화면을 열면, **Then** `V0-state-offline-empty`가 보인다.
15. **V0-F13-AC-05** — **Given** 상대가 연결을 끊거나 계정을 삭제함, **When** 내가 앱을 열거나 Realtime 알림을 받으면, **Then** `V0-state-ended`("{name}님이 연결을 끊었어요") 또는 `V0-state-ended-deleted`("상대가 계정을 삭제했어요")와 "새로 시작하기"가 보이고, 이 기기의 위젯·예약 알림이 지워진다.

### User Story 4 - 기념일 목록에서 모든 기념일을 날짜순으로 본다 (Priority: P2) — V0-F04, V0-F05, V0-F06, V0-F08

기념일 탭은 함께한 날·생일·시즌·직접 추가를 한 목록에 날짜순으로 보여 준다. 상세는 날짜·D-n·계산 방법·알림 설정을 보여 준다.

**Why this priority**: 홈 다음으로 많이 쓰는 화면이며 150일·생일·시즌은 백엔드 변경이 필요하다.

**Independent Test**: 고정 시각 fixture로 목록을 그려 보드의 행·순서·구간과 같은지 단위 테스트와 화면 확인으로 본다.

**Acceptance Scenarios**:

1. **V0-F04-AC-01** — **Given** 사귄 날 2025-06-29, **When** 목록을 보면, **Then** 일수 기념일은 50·100·150·200·300일(각 한 번)과 매년 주년만 있다. 500·1000일은 없다.
2. **V0-F04-AC-02** — **Given** 자동 기념일 상세(`V0-anniv-detail-years`), **When** 열면, **Then** "사귄 날로 자동 계산돼요", 계산 칸("매년 사귄 날과 같은 날짜 ({md})" 또는 "사귄 날({start})을 1일째로 세어 {n}일째 되는 날"), 고치기·지우기 없음, "알림 설정 열기"가 보인다.
3. **V0-F05-AC-01** — **Given** 나는 생일을 넣었고 상대는 안 넣음, **When** 목록을 보면, **Then** 상대 생일 대신 `V0-anniv-list-bwait` 행("{name}님이 생일을 넣으면 함께 보여요")이 보이고 상대도 내 생일을 보지 못한다.
4. **V0-F05-AC-02** — **Given** 둘 다 생일을 넣음, **When** 목록을 보면, **Then** "내 생일"과 "{name} 생일"이 매년 양력 월·일로 보이고 나이·태어난 해는 어디에도 보이지 않는다.
5. **V0-F05-AC-03** — **Given** 생일 상세(`V0-anniv-detail-birthday`), **When** 상대 생일을 열면, **Then** "생일은 본인만 고칠 수 있어요." 안내만 있고 편집 버튼은 없다. 내 생일은 설정 `V0-set-me`로 고친다.
6. **V0-F05-AC-04** — **Given** 내가 생일을 안 넣음, **When** 목록을 보면, **Then** "내 생일을 넣으면 서로 보여요" + "내 생일 넣기"가 보이고 누르면 `V0-set-me`로 간다.
7. **V0-F06-AC-01** — **Given** 어느 공간, **When** 목록을 보면, **Then** 빼빼로데이(11/11)와 크리스마스(12/25)가 매년 보이고 상세(`V0-anniv-detail-season`)는 "매년 자동으로 들어가는 기념일이에요", "매년 {md}"를 보여 준다. 고치기·지우기는 없다.
8. **V0-F08-AC-01** — **Given** 오늘 2026-11-02, **When** 목록을 열면, **Then** "오늘"(있을 때) → "다가오는 기념일"(오늘 다음 날부터 1년 뒤까지, 날짜 오름차순) → "지난 기념일 {n}개 보기"(접힘, 1년 전까지, 날짜 내림차순) 순서다(`V0-anniv-list`, `-list-past`, `-list-today`).
9. **V0-F08-AC-02** — **Given** 목록, **When** 필터 "직접 추가"를 고르면, **Then** 직접 추가 기념일만 보이고(`V0-anniv-list-custom`), 하나도 없으면 `V0-anniv-list-empty`("둘만의 기념일을 추가해 보세요")가 보인다.
10. **V0-F08-AC-03** — **Given** 각 행, **When** 그려지면, **Then** 종류 아이콘, 제목, 날짜, D-n(오늘이면 "오늘", 내일이면 "D-1")이 보이고 직접 추가 행에는 "직접" 배지가 있다. VoiceOver는 "{title}, {date}, {left}"로 읽는다.
11. **V0-F08-AC-04** — **Given** 사귄 날보다 앞선 시즌·생일, **When** 목록을 계산하면, **Then** 넣지 않는다.

### User Story 5 - 둘만의 기념일을 추가·편집·삭제한다 (Priority: P2) — V0-F07

두 사람 모두 제목·날짜·반복·메모·알림으로 기념일을 만들고 고치고 지운다. 동시에 고치면 충돌 안내가 보인다.

**Why this priority**: V0의 유일한 사용자 생성 데이터이며 동시성·RLS 검증이 필요하다.

**Independent Test**: 두 계정으로 같은 기념일을 동시에 고쳐 충돌·삭제됨 안내를 확인한다(Deno + pgTAP + RNTL).

**Acceptance Scenarios**:

1. **V0-F07-AC-01** — **Given** 기념일 탭, **When** "기념일 추가"를 누르면, **Then** `V0-edit-new`(제목, 날짜, 반복 매년/한 번만, 메모(선택), 알림 기본 설정/끄기)가 열리고 제목이 비면 저장 버튼이 비활성이다.
2. **V0-F07-AC-02** — **Given** 입력 중, **When** 제목이 20자를 넘거나 메모가 100자를 넘으면, **Then** `V0-edit-err-long` 안내와 글자 수 표시가 보이고 저장되지 않는다. 공백만 있는 제목은 `V0-edit-err-empty`다.
3. **V0-F07-AC-03** — **Given** 유효한 입력, **When** 저장하면, **Then** 서버에 저장되어 두 사람 모두에게 보이고 `V0-edit-saved` 토스트("저장했어요") 후 목록으로 돌아간다. 상대 기기는 앱이 열려 있으면 바로, 아니면 다음에 열 때 반영된다(`edit.shared.hint`).
4. **V0-F07-AC-04** — **Given** "한 번만" 반복, **When** 지난 날짜를 고르면, **Then** `V0-edit-once` 미리 보기("지난 날짜예요. 지난 기념일에 들어가요.")가 보이고 저장할 수 있다.
5. **V0-F07-AC-05** — **Given** 직접 추가 상세(`V0-anniv-detail-custom`), **When** 열면, **Then** 만든 사람("{name}님이 추가했어요 · {date} 수정" 또는 "내가 추가했어요 · …"), 메모, 반복, 알림, 편집 버튼이 보인다.
6. **V0-F07-AC-06** — **Given** 편집 화면(`V0-edit-edit`), **When** "이 기념일 삭제" → 확인(`V0-edit-delete`)을 누르면, **Then** 두 사람 모두에게서 사라지고 "삭제했어요" 토스트 후 목록으로 간다.
7. **V0-F07-AC-07** — **Given** 고친 내용이 있는 편집 화면, **When** 취소를 누르면, **Then** `V0-edit-discard`("고친 내용을 버릴까요?" 버리기/계속 고치기)가 보인다. 고친 내용이 없으면 바로 닫힌다.
8. **V0-F07-AC-08** — **Given** A가 편집 화면을 연 뒤 B가 같은 기념일을 먼저 저장, **When** A가 저장하면, **Then** 서버가 버전 충돌을 돌려주고 `V0-edit-conflict`("{name}님이 먼저 고쳤어요", 최신 내용을 불러옴)가 보이며 A가 확인 후 다시 저장할 수 있다. 마지막 저장 승리는 쓰지 않는다.
9. **V0-F07-AC-09** — **Given** A가 편집 중 B가 그 기념일을 삭제, **When** A가 저장하거나 화면을 새로 고치면, **Then** `V0-edit-gone`("이미 삭제된 기념일이에요")이 보이고 확인 후 목록으로 간다.
10. **V0-F07-AC-10** — **Given** 네트워크 오류, **When** 저장하면, **Then** `V0-edit-saveerr`("저장하지 못했어요. 고친 내용은 그대로 있어요.")가 보이고 입력은 유지된다. 같은 요청을 다시 보내도 중복 생성되지 않는다(멱등 키).
11. **V0-F07-AC-11** — **Given** 오프라인, **When** 기념일 탭을 보면, **Then** 추가·편집 버튼은 비활성이며 대기열에 넣지 않는다.
12. **V0-F07-AC-12** — **Given** 다른 공간의 사용자, **When** 이 공간의 기념일을 읽거나 쓰려 하면, **Then** RLS·RPC가 거부한다(NOT_FOUND).

### User Story 6 - 홈 화면과 잠금 화면 위젯으로 바로 본다 (Priority: P2) — V0-F11

iOS 홈 화면 small·medium·large와 잠금 화면 circular·rectangular·inline 위젯이 D+N과 다음 기념일을 보여 준다.

**Independent Test**: TestFlight 폰에서 위젯을 추가하고 자정·데이터 변경·로그아웃 때 바뀌는지 본다.

**Acceptance Scenarios**:

7. **V0-F11-AC-07** — **Given** 잠금 화면 위젯, **When** 그려지면, **Then** 사람 이름은 없고 직접 추가 제목은 privacySensitive로 표시된다. 위젯 공유 데이터에 생일 연도·토큰은 없다.
8. **V0-F11-AC-08** — **Given** 위젯, **When** 탭하면, **Then** 앱의 홈(또는 보드가 정한 대상)으로 열린다.
9. **V0-F11-AC-09** — **Given** 기념일 추가·편집·삭제, 사귄 날·시간대·이름·언어 변경, 로그인·동기화 성공, **When** 앱이 데이터를 받으면, **Then** 위젯 데이터를 원자적으로 바꾸고 reload를 요청한다.

### User Story 7 - 기념일 알림을 받는다 (Priority: P2) — V0-F10

연결 직후 사전 안내에서 알림을 켜면 각 기기에 가까운 기념일부터 로컬 알림을 예약한다. 설정에서 시간·미리 알림·종류·기념일별로 끈다.

**Why this priority**: 서버 푸시 없이 기기 예약만 하므로 범위가 작지만 예약·취소 누락 위험이 있다.

**Independent Test**: 시뮬레이터에서 기기 시각을 바꿔 예약 목록(`getAllScheduledNotificationsAsync`)과 실제 표시를 확인한다.

**Acceptance Scenarios**:

1. **V0-F10-AC-01** — **Given** 연결 완료(`V0-start-connected`), **When** "시작하기"를 누르면, **Then** 한 번만 `V0-start-notify` 사전 안내가 보이고 "알림 켜기"일 때만 iOS 권한 창(`V0-start-notify-os`)을 띄운다. "다음에"면 다시 띄우지 않고 설정 알림 행으로만 켠다.
2. **V0-F10-AC-02** — **Given** 알림 허용, **When** 예약을 계산하면, **Then** 각 기념일 당일 09:00(공간 시간대)과 미리 알림(기본 하루 전, 같은 시각)을 가까운 것부터 최대 50개 예약하고, 같은 발생을 두 번 예약하지 않는다(식별자 = 종류·키·발생일·오프셋).
3. **V0-F10-AC-03** — **Given** 알림 문구, **When** 알림이 울리면, **Then** 제목은 앱 이름, 본문은 `notify.body.*`(자동·시즌은 제목, 생일은 이름, 직접 추가는 "오늘은 둘만의 기념일이 있어요"/"둘만의 기념일까지 {n}일 남았어요")다.
4. **V0-F10-AC-04** — **Given** `V0-set-notify`, **When** 알림 끄기·시간 변경·미리 알림 변경·종류별 끄기(함께한 날/생일/시즌/직접 추가)를 하거나, 직접 추가 기념일의 편집 화면·상세에서 그 기념일의 알림을 "알림 끄기"로 바꾸면, **Then** 이 기기의 예약만 다시 계산하고 상대 기기에는 영향이 없다. 설정 화면에는 기념일별 스위치가 없다(V0-07 보드).
5. **V0-F10-AC-05** — **Given** OS 권한 거부, **When** 설정 알림을 열면, **Then** `V0-set-notify-denied`("기기에서 알림이 꺼져 있어요", "기기 설정 열기")가 보이고 미리 알림 묶음은 숨고 스위치는 비활성이며 예약은 하지 않는다.
6. **V0-F10-AC-06** — **Given** 앱을 포그라운드로 가져옴·데이터 변경·시간대 변경·언어 변경, **When** 예약을 다시 맞추면, **Then** 차이만 취소·추가하고 부족해진 목록을 채운다.
7. **V0-F10-AC-07** — **Given** 로그아웃·연결 끊기·공간 끝남·계정 삭제, **When** 일어나면, **Then** 이 기기의 V0 예약 알림을 모두 취소한다.
8. **V0-F10-AC-08** — **Given** 상대가 기념일을 바꿨고 내 앱은 닫혀 있음, **When** 원래 예약 시각이 오면, **Then** 이전 예약이 울릴 수 있다(V0 수락). 앱을 다음에 열면 새 일정으로 바뀐다. 이 동작은 설정 안내(`set.notify.note`)에 적혀 있다.

### User Story 8 - 최소 설정으로 내 정보·우리·알림·화면·계정을 관리한다 (Priority: P2) — V0-F12

**Why this priority**: 사귄 날·시간대·생일 변경, 로그아웃·연결 끊기·계정 삭제는 출시 요건이다.

**Independent Test**: RNTL로 각 설정 화면의 행·대화 상자를 확인하고 Deno·pgTAP로 서버 변경을 확인한다.

**Acceptance Scenarios**:

1. **V0-F12-AC-01** — **Given** 설정 탭, **When** 열면, **Then** `V0-set-main`/`-main-2`처럼 내 정보(이름·생일), 우리(사귄 날, 상대 "{name} · 연결됨", 기준 시간대), 알림, 화면(언어·화면 모드), 도움(문의하기·개인정보 처리방침·이용약관·버전), 계정(로그인·보안 — 오른쪽 값 "Apple로 로그인함" 또는 "이메일로 로그인함", 로그아웃, 연결 끊기, 계정 삭제)이 있다. 방 낮·밤, AI 동의, 커버, 신고·차단 행은 없다.
2. **V0-F12-AC-02** — **Given** `V0-set-me`, **When** 이름(1~10자)과 생일(월·일, 연도 선택)을 고쳐 저장하면, **Then** 상대 화면·목록·위젯에 반영된다. 생일을 지우면 상대의 내 생일 행도 사라진다.
3. **V0-F12-AC-03** — **Given** `V0-set-start`, **When** 새 사귄 날을 고르면, **Then** "바꾸면 오늘이 {n}일째가 돼요" 미리 보기가 보이고 저장 시 `V0-set-start-confirm`("{old} → {new}. {name}님 화면과 위젯, 날짜 기념일도 함께 바뀌어요.")을 거쳐 두 사람에게 적용된다. 미래 날짜는 고를 수 없다.
4. **V0-F12-AC-04** — **Given** 동시에 상대가 사귄 날을 바꿈, **When** 내가 저장하면, **Then** 버전 충돌로 최신 값을 다시 보여 주고 다시 확인하게 한다.
5. **V0-F12-AC-05** — **Given** 기준 시간대 행, **When** S13 시간대 시트에서 바꾸면, **Then** 두 사람의 하루 경계·알림 시각·위젯 자정이 새 시간대를 따른다(`set.us.tz.note`). 방 점유(prompt session)와 무관하게 바꿀 수 있다.
6. **V0-F12-AC-06** — **Given** `V0-set-lang`, `V0-set-mode`, **When** 바꾸면, **Then** 이 기기에만 적용된다("이 기기에만 적용돼요.").
7. **V0-F12-AC-07** — **Given** `V0-set-disconnect`, **When** "내용을 확인했어요"를 체크하고 연결 끊기를 확인하면, **Then** 공간이 끝나고(기존 `block` 끝점, reason `disconnect`) 상대는 `V0-state-ended`를 보며 이 기기의 위젯·알림이 지워진다.
8. **V0-F12-AC-08** — **Given** 앱 비밀번호가 없는 Apple 계정의 `V0-set-delete`, **When** Apple로 다시 로그인해 확인하면, **Then** 기존 계정 삭제 흐름(S13 진행·실패·완료)이 실행되고 공간이 끝나며 Apple 연결이 해제되고 위젯·알림이 지워진다.
9. **V0-F12-AC-09** — **Given** 도움 행, **When** 문의하기·개인정보 처리방침·이용약관을 누르면, **Then** 각각 메일 작성 또는 웹 문서(앱 언어별 `/privacy/`)를 연다. 주소가 아직 없으면 문의하기는 숨긴다. 자체 약관이 없는 동안 이용약관은 Apple 표준 EULA를 연다(A-23). 버전 행은 마케팅 버전과 빌드 번호를 보여 준다.
10. **V0-F12-AC-10** — **Given** 로그아웃, **When** 확인하면, **Then** 세션을 지우고 `V0-start-intro`로 가며 위젯은 "공간 없음" 상태, 예약 알림은 취소된다.

### User Story 9 - 이메일과 비밀번호로 로그인한다 (Priority: P1) — V0-F15

앱 심사 데모 계정과 다른 기기의 Apple 계정이 이메일과 비밀번호로 들어온다. 메일 발송 수단이 연결되기 전에는 가입과 재설정 메일이 닫혀 있고, 그 사실을 그대로 보여 준다.

**Why this priority**: App Review는 Apple 계정 없이 앱을 볼 데모 로그인이 필요하고, 오너가 비밀번호 로그인을 요청했다(2026-11-06).

**Independent Test**: 로컬 스택에서 운영자가 만든 이메일 계정으로 로그인하고, 틀린 비밀번호 5회 뒤 잠금과 없는 이메일의 같은 응답을 Deno로 확인한다. 화면은 RNTL로 `V0-auth-*` 상태를 확인한다.

**Acceptance Scenarios**:

1. **V0-F15-AC-01** — **Given** `V0-start-intro`, **When** "이메일로 로그인"을 누르면, **Then** `V0-auth-login`이 이메일과 비밀번호를 한 화면에서 받고, 비밀번호는 기본 숨김이며 보기·숨기기(`V0-auth-login-show`)로 바꿀 수 있다.
2. **V0-F15-AC-02** — **Given** 틀린 비밀번호 또는 없는 이메일, **When** 로그인하면, **Then** 서버 응답이 같고(`INVALID_LOGIN`, 응답 시간 하한 포함) `V0-auth-login-wrong`의 같은 문구가 보인다.
3. **V0-F15-AC-03** — **Given** 같은 이메일로 연속 5회 실패, **When** 다시 시도하면, **Then** 맞는 비밀번호라도 서버가 10분 동안 `LOGIN_LOCKED`로 막고 없는 이메일도 똑같이 잠기며, `V0-auth-login-rate`에서 Apple 로그인은 열려 있다. 동시 요청도 5회를 넘겨 검사되지 않는다.
4. **V0-F15-AC-04** — **Given** 맞는 이메일·비밀번호, **When** 로그인하면, **Then** 실패 횟수가 지워지고 세션이 앱에 들어와 공간이 있으면 홈, 없으면 `V0-start-choose`로 간다.
5. **V0-F15-AC-05** — **Given** 메일 값이 꺼진 상태(`auth_email_enabled=false`), **When** "처음이세요?"를 누르거나 가입 API·Auth 가입 끝점을 직접 부르면, **Then** 앱은 `V0-auth-signup-nomail`을 보이고 서버는 `MAIL_NOT_CONNECTED`로 거절하며 DB 트리거가 이메일 계정 생성을 막는다. `review_login_email`에 적힌 주소 하나만 운영자가 만들 수 있고, Apple 계정 생성은 막지 않는다.
6. **V0-F15-AC-06** — **Given** 메일 값이 켜진 상태, **When** 계정을 만들면, **Then** `V0-auth-signup`에서 규칙 3개가 입력하며 충족 표시로 바뀌고 약관 동의 없이는 제출할 수 없으며(`V0-auth-signup-err`), 서버도 같은 규칙을 검사(`WEAK_PASSWORD`)한다. 이미 있는 이메일도 같은 응답으로 `V0-auth-signup-sent`에 간다.
7. **V0-F15-AC-07** — **Given** 메일 값이 꺼진 상태, **When** "비밀번호를 잊으셨나요?"를 누르면, **Then** 메일 요청 없이 `V0-auth-reset-nomail`로 가고 보내지 못한 메일을 보냈다고 말하지 않는다.
8. **V0-F15-AC-08** — **Given** 메일 값이 켜진 상태, **When** `V0-auth-reset`에서 메일을 요청하고 링크로 돌아와 `V0-auth-newpw`에서 저장하면, **Then** 가입 여부와 관계없이 같은 `V0-auth-reset-sent`가 보이고, 새 비밀번호가 저장되어 바로 로그인된다.
9. **V0-F15-AC-09** — **Given** 만료됐거나 이미 쓴 메일 링크, **When** 앱으로 돌아오면, **Then** `V0-auth-link-exp`가 보이고 재설정 메일을 다시 요청할 수 있다.
10. **V0-F15-AC-10** — **Given** 메일 값은 켰지만 Auth의 이메일 확인이 꺼져 있음, **When** 앱이 설정을 읽으면, **Then** 메일이 연결되지 않은 것으로 다뤄 가입이 열리지 않는다. 앱이 설정을 못 읽어도 닫힌 상태로 다룬다.
11. **V0-F15-AC-11** — **Given** 비밀번호를 쓰는 모든 경로, **When** 요청이 처리되면, **Then** 비밀번호는 인증 제공자에 해시로만 저장되고 우리 DB·로그·멱등 저장소·기기 저장소·오류 응답에 남지 않는다.

### User Story 10 - Apple 계정에 비밀번호를 더한다 (Priority: P2) — V0-F16

Apple로 들어온 사람에게 비밀번호를 만들 수 있다고 안내하지만 강제하지 않는다.

**Why this priority**: 오너 결정 B(2026-11-06): Apple 로그인을 남기고, 로그인 뒤에도 비밀번호를 설정할 수 있게 안내한다.

**Independent Test**: RNTL로 안내·건너뛰기·완료 화면을, Deno로 비밀번호를 만든 Apple 계정의 이메일 로그인을 확인한다.

**Acceptance Scenarios**:

1. **V0-F16-AC-01** — **Given** Apple 첫 로그인, 공간 없음, 비밀번호 없음, **When** 로그인이 끝나면, **Then** `V0-auth-setpw-prompt`가 보이고 "나중에 할게요"를 누르면 `V0-start-choose`로 가며 다시 묻지 않는다(서버에 본 시각 기록).
2. **V0-F16-AC-02** — **Given** `V0-auth-setpw`, **When** 규칙을 어기거나 확인이 다르면 `V0-auth-setpw-err`가 보이고, 맞게 만들면 `V0-auth-setpw-done`이 이메일 로그인 주소와 복사 버튼을 보인다. 가림 주소 안내는 `@privaterelay.appleid.com`일 때만 보인다. 비밀번호 칸은 iOS 자동 완성(`password`, `newPassword`)이 켜져 있다.
3. **V0-F16-AC-03** — **Given** 공간이 있고 비밀번호가 없는 기존 TestFlight 계정, **When** 업데이트 뒤 처음 홈을 열면, **Then** `V0-auth-setpw-sheet`가 한 번만 보이고, 건너뛰면 다시 나오지 않으며 설정의 `V0-sec-apple-nopw`에서 만들 수 있다.
4. **V0-F16-AC-04** — **Given** 앱 비밀번호를 만든 Apple 계정, **When** 계정 이메일 + 앱 비밀번호로 로그인하면, **Then** 같은 계정으로 들어오고 `app_metadata.provider`는 `apple`로 남는다.
5. **V0-F16-AC-05** — **Given** 이메일이 비어 있는 Apple 계정, **When** 안내 대상을 정하면, **Then** 안내·시트·만들기 버튼을 보이지 않고 서버도 `EMAIL_REQUIRED`로 거절한다. 어떤 화면도 막지 않는다.

### User Story 11 - 로그인·보안에서 비밀번호를 관리한다 (Priority: P2) — V0-F17

**Why this priority**: 비밀번호가 있으면 바꾸고 잊었을 때 되찾는 길이 있어야 한다.

**Independent Test**: RNTL로 세 가지 모습을, Deno로 현재 비밀번호 확인·잠금·다른 기기 로그아웃을 확인한다.

**Acceptance Scenarios**:

1. **V0-F17-AC-01** — **Given** 설정 › 로그인·보안, **When** 열면, **Then** 계정에 따라 `V0-sec-apple-nopw`, `V0-sec-apple-pw`(로그인 주소·복사, 가림 주소 안내), `V0-sec-email`이 보인다.
2. **V0-F17-AC-02** — **Given** `V0-sec-change`, **When** 맞는 지금 비밀번호와 규칙에 맞는 새 비밀번호를 저장하면, **Then** `V0-sec-saved` 토스트가 보이고, 이 기기는 로그인된 채 다른 기기의 세션은 끝난다.
3. **V0-F17-AC-03** — **Given** 틀린 지금 비밀번호, **When** 저장하면, **Then** `V0-sec-change-wrong`(`WRONG_PASSWORD`)이 보이고, 5회면 `V0-sec-change-rate`(`LOGIN_LOCKED`, 로그인과 같은 횟수·10분)다.
4. **V0-F17-AC-04** — **Given** 앱 비밀번호를 잊은 Apple 계정, **When** `V0-sec-forgot`에서 Apple로 다시 로그인하면, **Then** 메일 없이 `V0-auth-setpw`로 가서 지금 비밀번호 없이 새로 만든다. 서버는 최근(5분) 비밀번호가 아닌 로그인이 있을 때만 허용한다.
5. **V0-F17-AC-05** — **Given** 비밀번호를 잊은 이메일 계정, **When** "비밀번호를 잊었어요"를 누르면, **Then** 메일이 켜져 있으면 `V0-auth-reset`, 꺼져 있으면 `V0-auth-reset-nomail`로 간다.

### User Story 12 - 비밀번호로 본인을 확인하고 계정을 삭제한다 (Priority: P2) — V0-F18

**Why this priority**: App Review 데모 계정(이메일)이 앱 안에서 삭제할 수 있어야 하고, Apple 계정은 어떻게 확인해도 Apple 토큰을 해지해야 한다(App Store 규칙).

**Independent Test**: Deno로 본인 확인 판정·토큰 해지 경로를, RNTL로 시트 상태를 확인한다.

**Acceptance Scenarios**:

1. **V0-F18-AC-01** — **Given** 앱 비밀번호가 있는 Apple 계정, 서버에 봉인한 Apple 토큰이 있음, **When** `V0-del-pw`에서 맞는 비밀번호로 확인하면, **Then** 삭제가 받아들여지고 토큰이 해지되며 봉인한 토큰은 지워진다.
2. **V0-F18-AC-02** — **Given** 봉인한 토큰이 없거나 읽을 수 없음, **When** 비밀번호로 확인하면, **Then** 아무것도 바뀌지 않고 `APPLE_CONFIRM_REQUIRED`로 `V0-del-apple-more`가 보이며, Apple 확인을 마치면 삭제가 이어진다.
3. **V0-F18-AC-03** — **Given** 삭제 본인 확인, **When** 비밀번호가 틀리면 `V0-del-pw-fail`, `V0-del-email-fail`이, 5회면 Apple 계정은 `V0-del-pw-rate`(Apple로 대신 확인), 이메일 계정은 `V0-del-email-rate`가 보인다. 잠금은 로그인과 같은 카운터다.
4. **V0-F18-AC-04** — **Given** 이메일 계정, **When** `V0-del-email`에서 맞는 비밀번호로 확인하면, **Then** S13 삭제 흐름이 끝까지 실행된다.
5. **V0-F18-AC-05** — **Given** 비밀번호를 잊음, **When** "비밀번호를 잊으셨나요?"를 누르면, **Then** Apple 계정은 `V0-del-forgot`(Apple 재로그인), 이메일 계정은 메일이 켜져 있으면 `V0-del-email-forgot`, 꺼져 있으면 `V0-del-email-nomail`(문의)이다.
6. **V0-F18-AC-06** — **Given** `reauthIsFresh`, **When** 판정하면, **Then** 비밀번호 확인은 `amr`의 `password` 항목이 5분 안일 때만 통과하고 계정의 `app_metadata.provider`와 무관하며, Apple·카카오 확인은 비밀번호 로그인으로 대신할 수 없다.
7. **V0-F18-AC-07** — **Given** Apple 로그인 성공, **When** 앱이 authorizationCode를 보내면, **Then** 서버가 토큰으로 바꿔 봉인 저장하고 다음 로그인에 갱신한다. Apple 비밀값이 없거나 교환이 실패해도 로그인은 그대로 끝나고 저장만 건너뛴다.
8. **V0-F18-AC-08** — **Given** 운영자 삭제, **When** 봉인한 토큰이 있으면, **Then** 그 토큰으로 해지하고, 없으면 기존처럼 `APPLE_TOKEN_UNAVAILABLE`로 기록한다.

### 날짜·계산 규칙 (V0-DR)

1. **V0-DR-01 일수** — 공간 시간대의 오늘 달력 날짜와 사귄 날의 **달력 날짜 차 + 1**. 사귄 날 당일 = 1일째 = D+1. 경과 초를 86400으로 나누지 않는다(기존 `apps/mobile/src/lib/dday.ts`, `supabase/functions/_shared/dday.ts`).
   - **V0-DR-01-AC-01** — **Given** 사귄 날 2025-06-29, Asia/Seoul, 지금 2025-06-29T15:00Z(서울 6/30 00:00), **Then** D+2.
   - **V0-DR-01-AC-02** — **Given** America/New_York, DST 시작일을 낀 기간, **Then** 일수가 하루 건너뛰거나 겹치지 않는다.
2. **V0-DR-02 N일 기념일** — 날짜 = 사귄 날 + (N − 1)일, N ∈ {50, 100, 150, 200, 300}, 각 한 번.
   - **V0-DR-02-AC-01** — **Given** 사귄 날 2025-06-29, **Then** 100일 = 2025-10-06, 150일 = 2025-11-25.
3. **V0-DR-03 주년** — 달력 기준(사귄 날과 같은 월·일, 매년 N주년). 1주년은 366일째(윤일이 끼면 367일째)로 보인다. 2월 29일 시작은 평년에 2월 28일. 주년과 일수가 같은 날이면 주년이 우선(카드·목록 행 하나).
   - **V0-DR-03-AC-01** — **Given** 사귄 날 2024-02-29, **Then** 1주년 2025-02-28, 4주년 2028-02-29.
4. **V0-DR-04 생일·시즌·직접 추가** — 생일은 양력 월·일, 2월 29일 생일은 평년 2월 28일. 시즌은 11/11, 12/25 고정. 직접 추가 매년은 같은 월·일(2월 29일 규칙 동일), 한 번만은 그 날짜.
5. **V0-DR-05 하루 경계** — 공간 시간대 자정(기본 = 만든 사람 기기 시간대, 보통 Asia/Seoul). 여행 중이어도 기기 시간대가 아니라 공간 시간대를 따른다.
   - **V0-DR-05-AC-01** — **Given** 공간 Asia/Seoul, 기기 America/Los_Angeles, **When** 서울 자정이 지나면, **Then** 앱·위젯·알림 모두 서울 기준 날짜로 바뀐다.
6. **V0-DR-06 목록 범위** — 오늘 기준 앞뒤 1년: 오늘 것은 "오늘" 구간, 다가오는 것은 내일부터 1년 뒤까지, 지난 것은 1년 전까지(보드의 "다가오는 기념일(오늘 포함)"은 오늘 구간을 위에 두는 것을 말함). 사귄 날보다 앞선 발생은 넣지 않는다.
   - **V0-DR-06-AC-01** — **Given** 사귄 날 2026-12-01, 오늘 2026-12-05, **Then** 2026-11-11 빼빼로데이는 지난 목록에 없다.

계산은 앱(TypeScript)·서버(Deno)·위젯(Swift를 쓰는 경우) 세 곳이 같은 fixture 파일로 교차 검증한다(`V0-NF-05`).

### Edge Cases

- **V0-EC-01 윤일** — 사귄 날·생일·직접 추가(매년)가 2월 29일이면 평년은 2월 28일. 2월 28일과 겹치는 다른 기념일과 우선순위 규칙을 그대로 쓴다.
- **V0-EC-02 상대 계정 삭제·연결 끊기** — 상대 쪽 데이터(이름·생일)는 즉시 보이지 않고 `V0-state-ended-deleted`/`V0-state-ended`. 직접 추가 기념일의 "만든 사람"이 삭제된 사용자면 이름 대신 "상대"로 표시(공간이 끝났으므로 실제로는 보이지 않지만 서버는 null을 안전하게 처리).
- **V0-EC-03 오프라인** — 읽기만, 편집 비활성, 대기열 없음. 첫 실행 오프라인은 `V0-state-offline-empty`. 위젯은 마지막으로 쓴 데이터와 timeline을 계속 쓴다.
- **V0-EC-04 편집 충돌** — 직접 추가·사귄 날·시간대는 버전 확인(`VERSION_CONFLICT`). 이름·생일은 본인만 쓰므로 충돌 없음(마지막 저장 승리).
- **V0-EC-05 시간대** — 공간 시간대가 바뀌면 오늘·D+N·축하·알림·위젯 timeline을 모두 다시 계산한다. 기기 시간대는 표시 형식(시각 표기)에만 쓴다.
- **V0-EC-06 사귄 날 변경 뒤 축하** — 이미 기록된 일수·주년 축하는 다시 하지 않되, 바뀐 날짜로 계산한 날이 아직 오지 않았으면 그 날 한 번 더(기존 001 FR-043, `update_anniversary` RPC 규칙 유지).
- **V0-EC-07 초대 코드 만료** — 홈 대기 중 코드가 만료되면 S04 만료 상태와 재발급이 홈에 보인다.
- **V0-EC-08 같은 날 여러 기념일** — 목록에는 모두, 홈 카드·위젯 "오늘"은 우선순위로 하나(`V0-F09-AC-04`).
- **V0-EC-09 알림 한도** — 예약 가능한 개수(iOS 64개)보다 적은 50개만 쓰고, 앱을 오래 안 열면 뒤쪽 알림이 없을 수 있다.
- **V0-EC-10 앱 이름은 브랜드 키로만** — 화면·위젯·알림의 앱·마스코트 이름(아룸·아루미, D-08)은 i18n 브랜드 키에서만 온다. 보드에 그려진 모피루·모피 문구는 브랜드 키로 바꾸고, 받침 있는 "아룸" 뒤 조사는 을·이·은·과·으로로 맞춘다("아룸을 시작해요"). 이름을 다시 바꿔도 문구 키 값 두 개와 앱 표시 이름 설정만 바꾼다.
- **V0-EC-11 언어 변경** — 위젯·알림 문구는 앱이 쓴 언어로 다시 써야 한다(언어 변경 시 위젯 데이터·예약 재작성).
- **V0-EC-12 생일을 나중에 넣음** — 둘 중 마지막 사람이 넣는 순간 두 사람 모두에게 두 생일이 보인다(다음 동기화 때).

## Requirements *(mandatory)*

### Functional Requirements

- **V0-F01 Apple 로그인**: Sign in with Apple이 첫 번째 로그인이다. 소개 한 장 + Apple 버튼 + "이메일로 로그인" + 약관 동의 문구(`V0-start-intro`). 시트·취소·오류는 S02 그대로. 카카오는 V0에서 보이지 않는다(서버 코드는 지우지 않는다). 개발 빌드의 빠른 로그인(PR 23)은 development 변형에서만 유지한다.
- **V0-F02 커플 연결**: 만드는 사람: 시작 방법 → 사귄 날 → 이름·생일 → 초대 코드(S04) → 홈 대기(코드 계속 보임). 초대받은 사람: 코드 입력(S05 오류) → 참여 확인 → 이름·생일 → 연결 완료. 이름은 필수 1~10자, 생일은 선택(월·일, 연도 선택, 양력).
- **V0-F03 홈 D+Day**: 앱 이름, 아루미(마스코트), 두 사람 이름, "함께한 지", D+N(가장 큼), 사귄 날, 다음 기념일 카드(제목·날짜·D-n), 다가오는 기념일 3개 + 전체 보기. 커버·방 카드·방 탭 없음. 상대 대기(`V0-home-pending`)와 상대 변경 안내(`V0-home-partner-edited`).
- **V0-F04 자동 기념일**: 50·100·150·200·300일(한 번씩)과 매년 주년. 고치거나 지울 수 없다. 서버의 기념일 목록에 150일을 더하고 500·1000일은 V0 응답에서 뺀다.
- **V0-F05 생일**: 각자 자기 생일만 넣고 고친다. 상대 생일은 두 사람 모두 넣은 뒤에만 서로 보인다. 연도는 저장해도 상대·위젯·알림에 보내지 않는다.
- **V0-F06 시즌 기념일**: 빼빼로데이(11/11), 크리스마스(12/25), 매년 자동, 코드 상수(데이터베이스에 저장하지 않음).
- **V0-F07 직접 추가 기념일**: 제목 1~20자, 날짜, 반복(매년/한 번만), 메모 0~100자, 알림(기본 설정/끄기 — 이 기기 설정). 두 사람 모두 추가·편집·삭제(삭제 확인), 공유. 만든 사람·마지막 수정일 표시. 버전 확인으로 충돌 안내, 이미 삭제됨 안내, 멱등 생성.
- **V0-F08 기념일 목록·상세**: 한 목록 날짜순(오늘 / 다가오는 1년 / 지난 1년 접기), 필터 전체·직접 추가, 종류 아이콘과 "직접" 배지, 상세(날짜·D-n·계산 방법·반복·메모·알림·만든 사람).
- **V0-F09 당일 축하**: 다음 기념일 카드 자리의 축하 카드(S28 단순화, 기념 꾸미기 제안 없음). 일수·주년만 7일 늦은 축하. 같은 날 하나만, 주년 > 일수 > 생일 > 직접 > 시즌.
- **V0-F10 기념일 알림**: 로컬 예약 알림만(서버 푸시 없음). 연결 직후 사전 안내 한 번. 설정: 켜기/끄기, 시간(기본 09:00 공간 시간대), 미리 알림 하나(없음/하루 전 기본/3일 전/일주일 전), 종류별 끄기, 기념일별 끄기, 거부 상태 안내. 모든 알림 설정은 이 기기에만 저장한다.
- **V0-F11 iOS 위젯**: 홈 small·medium·large, 잠금 circular·rectangular·inline. 외관 full color·dark·tinted(iOS 18)·clear(iOS 26)·vibrant. 상태: 보통·오늘·상대 연결 전·공간 없음·공간 끝남·자리표시. 공간 시간대 자정 timeline + 데이터 변경 시 reload. 공유 데이터는 `schemaVersion`이 있는 최소 JSON(이름·생일 연도·토큰 없음).
- **V0-F12 최소 설정**: 내 정보, 우리(사귄 날 확인 후 두 사람 적용, 상대, 시간대), 알림, 화면(언어·모드, 이 기기만), 도움(문의·개인정보 처리방침·약관·버전), 계정(로그인·보안, 로그아웃, 연결 끊기, 계정 삭제 — V0-F18의 본인 확인).
- **V0-F13 시스템 상태**: 로딩 스켈레톤, 불러오기 실패(전부 아니면 없음), 오프라인 읽기만(마지막 데이터 + 띠), 오프라인·데이터 없음, 상대가 연결 끊음·계정 삭제. S16 공통 상태(로그인 만료·업데이트 필요·권한 없음) 재사용.
- **V0-F14 출시 자동화·OTA**: `workflow_dispatch` → EAS Build → EAS Submit → TestFlight, EAS Update preview → production. 첫 빌드는 `.dev` bundle id. 위젯 extension·권한·네이티브 변경은 새 빌드. 비밀은 저장소 밖. App Store에 더 높은 버전이 나오면 앱이 업데이트를 권한다(V0-11, App Store 조회).
- **V0-F15 이메일·비밀번호 로그인(`V0-08`)**: 인증 제공자의 이메일·비밀번호를 쓰고, 앱은 `auth-password` 함수를 거쳐 로그인한다. 규칙은 8자 이상, 영문과 숫자를 함께, 이메일 주소와 다르게이며 서버에서도 검사한다. 연속 5회 실패하면 그 이메일은 10분 잠긴다(서버가 세고, 없는 이메일도 같게 응답). 메일 발송은 `app_settings.auth_email_enabled` 값 하나로 켠다. 꺼져 있는 동안 `V0-auth-signup-nomail`, `V0-auth-reset-nomail`, `V0-del-email-nomail`이 실제 화면이다.
- **V0-F16 Apple 계정 비밀번호 안내(`V0-08`)**: 비밀번호는 선택이다. 없는 Apple 계정도 정상이고 어떤 화면도 막지 않는다. 새 계정은 `V0-auth-setpw-prompt`, 기존 계정은 홈 위 `V0-auth-setpw-sheet`를 한 번만 본다. Apple 계정 암호는 앱에 들어오지 않는다.
- **V0-F17 로그인·보안(`V0-09`)**: 자격 증명에 따른 세 모습, 지금 비밀번호 확인 뒤 변경, 변경하면 다른 기기는 로그아웃.
- **V0-F18 계정 삭제 본인 확인(`V0-09`)**: 비밀번호 있는 계정은 비밀번호로 확인한다. 비밀번호 없는 Apple 계정은 Apple 재로그인 그대로다. Apple 계정은 어떻게 확인해도 Apple 토큰을 해지한다. Apple 로그인 때 받은 토큰을 봉인 보관하고 삭제 때 파기하며, 없으면 `V0-del-apple-more`로 Apple 확인을 한 번 더 받는다.

### Non-Functional Requirements

- **V0-NF-01 접근성(S20)**: 터치 대상 최소 48pt(보드 기준; 시스템 최소 44pt보다 큼), 안전 영역 위 47·아래 34pt 기준 프레임, 글자 200%까지 잘림 없이 줄 바꿈, 동작 줄이기 = 마스코트 정지 포즈, 모든 아이콘 버튼에 VoiceOver 라벨, 본문 대비 4.5:1.
- **V0-NF-02 i18n**: 한국어 원본 + 영어·일본어 초안(원어민 검수 전). 모든 화면 문구는 i18n 키로만 쓰고(기존 ESLint `i18next/no-literal-string`), 앱·마스코트 이름은 브랜드 키(`app.name`, `mascot.name`)만 참조한다.
- **V0-NF-03 테마**: 밝게·어둡게(시스템 따르기 기본), 기존 `apps/mobile/src/theme/tokens.ts` 토큰만 쓴다.
- **V0-NF-04 개인정보**: 위젯·알림·로그에 생일 연도·토큰·이메일·비밀번호를 넣지 않는다. 잠금 화면에는 사람 이름을 넣지 않는다.
- **V0-NF-05 계산 일치**: 날짜 계산은 공유 fixture(JSON)로 앱·서버·(Swift 위젯) 테스트를 함께 돌린다.
- **V0-NF-06 숨김은 삭제가 아님**: 방·프롬프트·커버·신고의 서버 데이터와 코드는 지우지 않고 V0 앱에서 진입만 막는다(기능 플래그).

### Key Entities

- **공간(couple_space)**: 사귄 날, 공간 시간대, 상태, `updated_at`(버전 확인용). 기존.
- **구성원 프로필**: 사용자별 표시 이름(1~10자), 생일 월·일(선택), 생일 연도(선택, 본인에게만). 신규(기존 `user_profile` 확장).
- **직접 추가 기념일**: 공간, 제목, 날짜, 반복(매년/한 번만), 메모, 만든 사람, 마지막 수정한 사람·시각, 버전, 삭제 시각(소프트 삭제). 신규.
- **축하 기록**: 일수·주년 축하와 구성원별 확인(기존 `milestone_celebration`, `milestone_seen`). 150일 키 허용으로 변경.
- **비밀번호 시도(`password_attempt`)**: 이메일의 HMAC, 시도 횟수, 잠금 시각. 이메일 원문·비밀번호 없음. 신규.
- **봉인한 Apple 토큰(`apple_credential`)**: 사용자, 봉인한 refresh token, 저장 시각. 계정 삭제가 받아들여질 때 지운다. 신규.
- **기기 알림 설정**: 켜기, 시각, 미리 알림, 종류별·기념일별 끄기, 사전 안내를 보았는지. 기기 로컬.
- **위젯 스냅샷**: App Group 공유 JSON(`schemaVersion` 1). 기기 로컬.
