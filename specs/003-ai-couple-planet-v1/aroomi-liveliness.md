# 아루미가 살아 보이게 하기

감자별 위 임시 아루미의 대기 동작 기획이다. 구현은 `apps/mobile/src/features/planet/aroomiLife.ts`(수치 계산, 순수 함수)와 `Aroomi.tsx`(모델에 적용)에 있다.

## 조사 방법과 한계

- 공개된 글만 읽었다. 게임 에셋이나 코드는 추출하지 않았다.
- **동물의 숲 화면을 프레임 단위로 재지 못했다.** 영상을 분석할 수단이 없었다. 그래서 동물의 숲에서 가져온 것은 개발자가 발표한 **원칙**이고, 아래 수치는 애니메이션 교재와 사람의 생리 수치에서 가져오거나 직접 정했다. 표의 "근거" 칸에 어느 쪽인지 적었다.
- 열지 못한 자료: GamesRadar의 대기 동작 기사(본문이 내려오지 않음), Animation Mentor의 깜빡임 글(403), PubMed 18565090 초록(쿠키 벽). Ken Perlin의 GDC 2002 노트는 열었지만 노이즈 기반 대기 동작 내용이 없어 쓰지 않았다.

## 층과 수치

모든 층은 프레임 루프 하나에서 매 프레임 합쳐진다. 층마다 주기가 달라서 같은 자세가 반복되지 않는다.

| 층 | 수치 | 근거 |
|---|---|---|
| 숨쉬기 | 3.4초 주기(분당 약 18회), 키 ±1.5%. 키가 늘면 둘레가 줄어 부피가 같다. | 호흡수는 출처 7(성인 12~18회, 6세 18~25회). 부피 규칙은 출처 8. 진폭은 직접 정했다. |
| 팔의 뒤따름 | 팔이 가슴보다 0.2초 늦게 ±0.04 rad | 출처 8의 겹치는 움직임. 수치는 직접 정했다. |
| 무게 이동 | 7.3초 주기 ±0.035 rad와 3.1초 주기 ±0.016 rad를 더한 옆 기울기 | 직접 정했다. 두 주기가 맞아떨어지지 않게 골랐다. |
| 깜빡임 간격 | 2~10초, 짧은 쪽이 더 잦다(`2 + 8u²`) | 범위는 출처 6. 분포 모양은 직접 정했다. |
| 깜빡임 길이 | 닫기 2프레임, 유지 1프레임, 열기 3프레임(24fps 기준 0.25초) | 프레임 수는 출처 4. 24fps는 가정이다(출처에 프레임률이 없다). 0.25초는 출처 6의 100~400ms 안이다. |
| 시선 이동 때의 깜빡임 | 시선이 0.15 rad 넘게 뛰면 깜빡인다 | 출처 4("A head turn ... would almost always get us to blink"), 출처 5 |
| 시선 | 2.5~6초마다 새로 본다. 45%는 보는 사람, 나머지는 그 주변 ±0.8 rad | 직접 정했다. 원칙은 출처 2, 5. |
| 눈이 먼저, 몸이 나중 | 얼굴은 약 3프레임(시상수 45ms) 만에, 몸은 시상수 0.35초로 따라간다. 얼굴은 몸보다 최대 0.22 rad 앞선다. | 눈 이동 3프레임은 출처 4. 몸의 지연은 출처 8의 드래그. |
| 버릇 동작 | 9~20초마다 하나: 깡충 뛰기(0.9초, 40%), 기지개(1.6초, 30%), 갸웃(1.6초, 30%) | 직접 정했다. 종류는 출처 9의 예와 V1-F02-AC-02의 팔 동작에서 골랐다. |
| 점프 | 움츠림(키 −10%) → 공중(높이 0.12, 키 +8%) → 착지(−8%) → 되돌아옴(+2%). 팔은 몸보다 늦게 오르내린다. | 출처 8의 예비 동작, 스쿼시와 스트레치. 수치는 직접 정했다. |
| 스카프 띠 끝 | 1.6Hz, 감쇠비 0.25의 스프링으로 몸의 회전·기울기·높이를 뒤쫓는다. 가만히 있을 때도 ±0.03 rad 흔들린다. | 출처 8의 뒤따르는 움직임. 수치는 직접 정했다. |

## 구현 방식

- `stepLife(life, pose, t, viewer, poked)`가 시간과 입력을 받아 자세 값 10개를 쓴다. 난수는 시드가 있는 생성기에서 뽑아서 같은 시드면 같은 동작이 나온다. 단위 테스트가 주기, 간격, 범위, 탭 반응을 확인한다.
- 얼굴(눈, 볼, 입)은 시선만큼 몸 표면을 따라 미끄러진다. 목이 없는 몸이라 얼굴 전체가 움직이면 고개를 돌리는 것처럼 보인다.
- 탭은 `PlanetScreen`이 움직이지 않은 터치로 판별해 넘기고, `Aroomi`가 화면에 투영한 자기 위치와 비교해 맞았을 때만 반응한다.
- 프레임마다 새 객체를 만들지 않는다. 자세와 상태 객체, 임시 벡터를 재사용한다.
- 동작 줄이기가 켜져 있으면 모든 층을 끄고 쉬는 자세로 둔다. 이때 장면은 원래도 필요할 때만 그린다.

## 넣지 않는 것

- 걷기와 가까이 보기(PR #99), 대사와 말풍선, 소리, 실제 GLB 리깅.
- 표정 바꾸기. 눈을 감고 크게 뜨는 것만 한다(OQ-18).
- 오브젝트에 반응하기(벌레를 쫓거나 가구를 쓰는 것). 놓인 오브젝트를 바라보는 것은 다음에 넣을 수 있다.
- 시간대나 날씨에 따른 동작.

## 확인하지 못한 것

- 동물의 숲의 실제 주기와 진폭. 위 수치는 그 게임을 잰 값이 아니다.
- 기기에서의 느낌. 시뮬레이터는 몇 초에 한 번만 새 프레임을 보여 줘서 움직임의 부드러움을 볼 수 없다.
