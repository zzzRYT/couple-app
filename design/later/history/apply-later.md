## 1. 스펙(`specs/001-couple-prompt-todo/spec.md`)

- **사용자 시나리오 2**(프롬프트로 방 꾸미기): "…직전에 적용한 변경을 되돌릴 수 있다" → "…이전 배치를 복구할 수 있다"로 되돌리고, **시나리오 8**을 "저장된 이전 배치, 사용자가 되돌리기(또는 기록에서 복구)를 요청하면 이전 방 배치가 복구된다"로 확장해요.
- **FR-013**: "되돌리기는 직전 적용 전 방 배치를 복구해야 하며 버전 목록(기록) 화면 없이 동작해야 한다…" 문장을 지우고 원래 문장 "구성원은 이전에 저장된 방 꾸밈도 복구할 수 있어야 하며, 버전 보관 개수나 정리 기간은 이 명세에서 정하지 않는다"를 복원해요. 새 요구로 아래를 추가해요: 기록 목록은 **시각 · 변경자 · 변경 요약**을 보여 주고 **프롬프트 전문은 숨긴다**. 복구는 **새 버전**을 만들어 현재 방도 기록에 남는다(복구해도 되돌릴 수 있다). 복구는 방을 바꾸는 일이라 **프롬프트 점유 세션이 필요**하고 상대가 점유 중이면 막힌다(가정, 열린 질문).
- **FR-027**: "설정·되돌리기·삭제·공간 나가기 컨트롤"에 **기록**을 다시 넣어요.
- **FR-018a·퀵스타트 A4**: 축소 방 목록에 "기록 섬네일"을 다시 넣어요(기록 섬네일은 정지 포즈).
- **Key Entities**: "방 테마 버전" 설명을 "…이전 상태로, 복구의 기준이 된다"로 되돌려요.
- **Out of Scope**: "기록" 항목을 지워요. **Clarifications** Session 2026-10-26의 기록 줄은 "후속 버전에 포함하기로 했다"로 고쳐요.
- **엣지 케이스**(추가): 복구 대상 버전이 현재 앱에서 읽을 수 없는 이전 스키마일 때 복구를 막고 앱 업데이트를 안내한다(`history.old.*`). 상대가 점유 중이면 복구를 막고 이유를 보여 준다. 복구 도중 상대가 먼저 적용하면 `VERSION_CONFLICT`로 안전하게 끝난다.
- **Open Decisions 8**(기록 없이 되돌리기)은 아래 5절에 따라 정리해요.

## 2. 데이터 모델(`data-model.md`)

- `RoomThemeVersion.source`에 **`restore`**를 다시 넣어요(`initial | prompt | undo | restore | manual_migration`). 복구는 지정 버전의 scene/presentation을 **새 복원 스냅샷**으로 복사하고 원본은 덮어쓰지 않아요(`restores_version_id` 사용).
- **버전 보관·정리**: 기록 화면이 보여 주는 개수가 정해져야 해서 버전 수 상한과 정리 기간이 이제 이용자에게 보이는 결정이 돼요(스펙은 "정하지 않는다"로 남아 있었어요). 상한(예: 최근 N개 또는 N일)을 정하고, 공간 종료 후 30일 복구 기간의 삭제 규칙과 맞춰요. 정해지기 전에는 기록이 무한히 쌓인다고 가정하고 목록은 페이지로 나눠요(`limit=20`).
- **목록 항목용 파생값**: 변경 요약 태그(소품 추가 · 소품 이동·제거 · 문구 변경 · 날짜 위젯 모양 변경 · 마스코트 변경 · 이전 버전에서 복구)를 이전 버전과의 비교로 계산해요. 저장해도 되고 목록 API가 계산해도 돼요(새 필드 `change_summary` 제안). 섬네일은 서버에 저장하지 않고 클라이언트가 현재 낮/밤 모습으로 그려요(저장하면 보관 대상에 이미지가 늘어요).
- **프롬프트 전문은 목록 응답에 넣지 않아요**(기록 보호). 대화 메시지 보관(적용된 prompt 30일)은 그대로예요.
- **읽을 수 없는 버전**: 기록 버전의 `schema_version`이 앱이 이해하는 범위 밖이면 목록은 보여 주되 복구는 막아요.
- `room-prompt-session.schema.json`의 `releaseReason`에 `restore`를 추가해요(복구 성공 시 점유 해제).

## 3. API(`contracts/api.md`)

- **`GET /spaces/{spaceId}/theme-versions?limit=20&before={cursor}`** 복원: 구성원만, version 메타데이터(번호 · 시각 · 변경자 · 변경 요약 · 복원 관계 · 현재 여부 · 읽을 수 있는지)를 읽는다. 프롬프트 원문은 포함하지 않는다.
- **`POST /spaces/{spaceId}/theme-versions/{versionId}/restore`** 복원: `{ "expectedCurrentVersion": 13, "idempotencyKey": "uuid" }`. 지정 버전을 새 복원 스냅샷으로 복사, 충돌 시 409, 성공한 변경은 같은 RLS Realtime 채널로 전달. **추가 제안**: 복구도 점유가 필요하다는 가정이면 요청에 `sessionId`를 넣고 owner 검사를 같은 트랜잭션에서 수행하며 성공 시 점유를 해제한다(`SESSION_OCCUPIED` / `NOT_OWNER` 오류는 undo와 같은 코드 재사용).
- **오류 코드**: `VERSION_CONFLICT`(기존), 읽을 수 없는 버전 `VERSION_UNREADABLE`(신규 제안).
- 문구: 오류 → `history.restore.err` · `history.old.*`, 점유 → `history.restore.busy`.

## 5. `undo` 열린 결정과의 관계 (spec Open Decisions 8)

기록을 채택하면 열린 결정 8의 세 질문이 거의 풀려요.

| 질문 | 기록이 있을 때 |
|---|---|
| (a) 연속 되돌리기 깊이 | 되돌리기는 **직전 한 번**만 하고, 더 거슬러 가려면 기록에서 고른다(자연스러운 답) |
| (b) 되돌린 뒤 다시 적용(redo) | 되돌리기도 새 버전이라 **기록에서 되돌리기 전 버전을 골라 복구**하면 다시 적용된다(별도 redo 불필요) |
| (c) 실수로 되돌린 것을 되돌릴 방법 | 기록의 복구가 안전장치(이전 문구 "지금 방은 기록에 남아 있어서 다시 돌아올 수 있어요") |

정해야 하는 것: **되돌리기 버튼을 기록과 함께 둘지**(권장: 둘 다 둔다. 되돌리기 = 빠른 한 단계, 기록 = 그 밖의 모든 복구) 아니면 되돌리기를 없애고 도구 막대의 기록 바로가기만 둘지. 후자는 S10을 지워야 해요. 둘 다 두면 S10과 방 도구 막대는 현재 V1 그대로이고 기록 바로가기만 추가돼요. 또한 "장면 데이터 읽기 오류"의 복구 연결(`room.recover.action` = "이전 버전 보기", 기록 탭으로 이동)도 `copy-keys.md`의 문구로 되돌릴 수 있어요.

## 6. 탭 수·이동·설정 링크

- 시스템 탭 바를 4개로(`tab.history` 추가, 순서 홈·방·기록·설정). 탭 개수가 들어간 접근성 문구 `a11y.tab`("{total}개 중 {n}번째")는 그대로 쓰고 total만 4가 돼요. 탭 루트 4개 · 푸시된 상세에 "버전 상세" 추가는 `interaction-notes.md`의 표를 따라요.
- 방 도구 막대에 **기록 바로가기**(`room.ctl.history`, 시계 아이콘)를 추가하고, 글자 ≥160%에서는 꾸미기 한 줄 + 되돌리기·기록 한 줄(2단)로 돌려요. 접근성 이름 `a11y.history`.
- 뒤로 가기·선택된 탭 다시 누르기 규칙은 V1과 같아요. 기본 탭은 홈 그대로예요.
- **설정·홈에는 기록으로 가는 링크가 없었어요**(V1에서 지운 링크 없음). 기록 탭의 빈 상태 "방 꾸미러 가기"는 방 탭으로 전환하고, 방의 읽기 오류 안내가 기록으로 이어져요(위 5절).
- 방 도구 막대 윤곽선·보호 영역 계산에 막대 폭 변화가 영향을 주는지 확인해요(항목 수가 2→3).

2. 이 폴더의 `copy-keys.md` 35개 키를 번역 리소스에 추가하고, 위 1~4절대로 스펙·데이터 모델·API·퀵스타트를 되돌린다.
3. 캔버스에서 `L-S11` · `L-S25`를 V1 보드 번호 S11 · S25로 되돌리고, V1 S07·S24·S23·S26 등의 탭 바와 도구 막대를 4탭·3항목 버전(`L-S24`)으로 교체한다. 이때 L 보드가 현재 V1 최신 화면과 어긋난 곳(문구, 홈 화면 등)을 다시 맞춘다.
4. `design/README.md` · `handoff.md` · 화면 수(15→16) · 키 수 · PNG를 갱신하고 대비 점검(`tools/contrast-check.mjs`)을 다시 돌린다.
