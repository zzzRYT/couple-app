# apply-later.md — 기록을 채택할 때 되돌릴 것

1차에서 기록을 뺄 때 고친 곳과, 그 뒤 "되돌리기는 열린 대화 안에서만, 적용한 뒤에는 되돌릴 수 없음"으로 정한 내용을 기준으로 **기록을 채택할 때 해야 할 일**이에요. 이 폴더의 파일은 V1 문서에 합치지 않고, 채택을 정하면 아래 순서대로 V1 문서에 반영해요. 숫자는 지금(V1) 기준이에요.

| 항목 | V1(지금) | 기록 채택 후 |
|---|---|---|
| 하단 탭 | 3개(홈·방·설정) | 4개(홈·방·기록·설정), 기록은 방과 설정 사이 |
| 방 도구 막대 | 꾸미기 하나 | 꾸미기 · **기록**(기록 탭으로 가는 바로가기). 되돌리기 버튼은 여전히 없음 |
| 되돌리기 | 열린 대화 안에서만, 적용한 뒤에는 불가, redo 없음 | 같음. **기록의 복구가 적용한 뒤 되돌리는 첫 번째 방법**이 됨(5절) |
| 화면 | S01~S16 중 S11 없음(15개), 탭 보드 S23·S24·S26 | S11 복원(16개), 탭 보드 S25 복원 |
| 문구 키 | 542 | 577(`copy-keys.md`의 35개를 더함). 공통 빈 상태 키를 옛 `sys.empty.hist` 1개로 되돌리면 576 |
| 스펙 | FR-013 되돌리기는 열린 대화 안, 이전 버전 복구 없음 | FR-013에 기록 복구 추가(아래) |

## 1. 스펙(`specs/001-couple-prompt-todo/spec.md`)

- **FR-013**: 지금 문장("…되돌릴 수 있어야 한다. 적용한 변경은 되돌릴 수 없고 … 이전 버전을 목록에서 골라 복구하는 기능(기록)은 첫 버전에 없다")에서 마지막 문장을 지우고 다음을 넣어요: "구성원은 이전에 저장된 방 꾸밈도 목록에서 골라 복구할 수 있어야 하며, 버전 보관 개수나 정리 기간은 이 명세에서 정하지 않는다." 새 요구로 아래를 추가해요: 기록 목록은 **시각 · 변경자 · 변경 요약**을 보여 주고 **프롬프트 전문은 숨긴다**. 복구는 **새 버전**을 만들어 현재 방도 기록에 남는다(복구해도 다시 돌아올 수 있다). 복구는 방을 바꾸는 일이라 **프롬프트 점유 세션이 필요**하고 상대가 점유 중이면 막힌다(제안).
- **FR-011·시나리오 18·적용 확인 문구**: "적용한 뒤에는 되돌릴 수 없다"를 "적용한 뒤에는 기록에서 이전 버전으로 복구할 수 있다"로 바꿔요(`copy-keys.md`의 문구 표 참고).
- **사용자 시나리오 2**: "…적용한 뒤에는 되돌릴 수 없다" 부분을 "…적용한 뒤에는 기록에서 이전 버전을 복구할 수 있다"로 바꾸고, 시나리오 8·19의 "적용한 방은 되돌릴 수 없다" 안내도 같은 방향으로 바꿔요.
- **FR-027·FR-018a·퀵스타트**: 고정 컨트롤 목록에 **기록**을 다시 넣고(되돌리기는 이미 빠져 있음), 축소 방 목록에 "기록 섬네일"(정지 포즈)을 다시 넣어요.
- **Key Entities**: "방 테마 버전"을 "…이전 상태로, 기록·복구의 기준이 된다. 이용자에게 목록으로 보여 준다"로 되돌려요.
- **Out of Scope**: "기록" 항목과 "적용한 변경의 되돌리기와 다시 적용(redo)" 항목을 고쳐요(기록 복구는 포함, redo는 정하는 대로). **Clarifications** Session 2026-10-26의 기록 줄은 "후속 버전에 포함하기로 했다"로 고쳐요.
- **엣지 케이스**(추가): 복구 대상 버전이 현재 앱에서 읽을 수 없는 이전 스키마일 때 복구를 막고 앱 업데이트를 안내한다(`history.old.*`). 상대가 점유 중이면 복구를 막고 이유를 보여 준다. 복구 도중 상대가 먼저 적용하면 `VERSION_CONFLICT`로 안전하게 끝난다.

## 2. 데이터 모델(`data-model.md`)

- `RoomThemeVersion.source`에 **`restore`**를 넣어요(`initial | prompt | restore | manual_migration`). 복구는 지정 버전의 scene/presentation을 **새 복원 스냅샷**으로 복사하고 원본은 덮어쓰지 않아요. 복원 관계를 위해 `restores_version_id?`를 되살려요.
- **버전 보관·정리**: 지금은 버전 스냅샷이 감사·충돌 검사용이라 이용자에게 보이지 않아요. 기록을 채택하면 보관 개수와 정리 기간이 이용자에게 보이는 결정이 돼요. 상한(예: 최근 N개 또는 N일)을 정하고, 공간 종료 후 30일 복구 기간의 삭제 규칙과 맞춰요. 정해지기 전에는 목록을 페이지로 나눠요(`limit=20`).
- **목록 항목용 파생값**: 변경 요약 태그(소품 추가 · 소품 이동·제거 · 문구 변경 · 날짜 위젯 모양 변경 · 마스코트 변경 · 이전 버전에서 복구)는 이전 버전과의 비교로 계산해요(새 필드 `change_summary` 제안). 섬네일은 서버에 저장하지 않고 클라이언트가 현재 낮/밤 모습으로 그려요.
- **프롬프트 전문은 목록 응답에 넣지 않아요**(기록 보호). 대화 메시지 보관(적용된 prompt 30일)은 그대로예요.
- **읽을 수 없는 버전**: `schema_version`이 앱이 이해하는 범위 밖이면 목록은 보여 주되 복구는 막아요.
- `room-prompt-session.schema.json`의 `releaseReason`에 `restore`를 추가해요(복구 성공 시 점유 해제). 열린 대화 안의 되돌리기(`DecorationRequest.reverted`)는 그대로 두고, `reverted`는 적용 전 후보에만 써요.

## 3. API(`contracts/api.md`)

- **`GET /spaces/{spaceId}/theme-versions?limit=20&before={cursor}`** 복원: 구성원만, version 메타데이터(번호 · 시각 · 변경자 · 변경 요약 · 복원 관계 · 현재 여부 · 읽을 수 있는지)를 읽는다. 프롬프트 원문은 포함하지 않는다.
- **`POST /spaces/{spaceId}/theme-versions/{versionId}/restore`** 복원: `{ "expectedCurrentVersion": 13, "sessionId": "uuid", "idempotencyKey": "uuid" }`. 지정 버전을 새 복원 스냅샷으로 복사하고, owner 검사와 점유 해제를 같은 트랜잭션에서 수행하며, 충돌 시 409, 성공한 변경은 같은 RLS Realtime 채널로 전달한다(`SESSION_OCCUPIED` / `NOT_OWNER`는 기존 코드 재사용).
- **`POST …/theme-versions/undo`(적용 후 방 되돌리기)는 되살리지 않아요.** 기록을 넣어도 적용 후 되돌리기는 기록의 복구가 맡아요. 열린 대화 안의 되돌리기(`POST …/prompt-session/{sessionId}/undo`)는 그대로예요.
- **오류 코드**: `VERSION_CONFLICT`(기존), 읽을 수 없는 버전 `VERSION_UNREADABLE`(신규 제안). 문구: `history.restore.err` · `history.old.*`, 점유 `history.restore.busy`.

## 4. 계획·퀵스타트·브리프

- **plan.md**: "장면/버전" 표의 설명에서 "적용 후 되돌리기와 이용자용 기록은 V1에 없고…"를 지우고, 구현 전 결정 3의 버전 보관 문구를 이용자에게 보이는 결정으로 바꿔요. 버전 목록 읽기를 위한 인덱스와 페이지 처리를 마이그레이션에 포함해요. 헌법 확인의 "단순한 설계" 항목에서 "적용은 되돌릴 수 없는 한 방향 동작"을 "기록에서 복구할 수 있다"로 고쳐요.
- **quickstart.md D절**: 검증을 추가해요 — 목록 페이지 처리, 복구가 새 스냅샷을 만들고 원본이 불변, 두 기기 동시 복구, 점유 중 복구 거절, 읽을 수 없는 버전, 빈 기록, 오프라인에서 복구 불가, 복구 후 양쪽 sync. "적용 후 undo가 `ALREADY_APPLIED`로 거절된다" 항목은 유지해요. 오프라인 항목에 `restore`를 다시 넣어요.

- **research.md**: "적용한 변경은 되돌릴 수 없다" 문장을 "history는 구성원 읽기 전용이며 restore 전 확인을 요구한다"로 바꿔요.

## 5. 되돌리기와의 관계 (1차 결정: 열린 대화 안에서만, redo 없음)

1차 결정은 되돌리기를 **지금 열린 프롬프트 대화 안에서 적용 전 변경**으로 한정하고, 적용한 뒤에는 되돌릴 수 없으며, 다시 적용(redo)은 두지 않는 거예요. 기록을 채택하면 다음이 달라져요.

| 상황 | 1차(기록 없음) | 기록 채택 후 |
|---|---|---|
| 적용 전 미리 보기를 바로 앞 것으로 | 열린 대화의 "이전 미리 보기로 되돌리기"(S10) | 같음. 이 버튼은 그대로 둬요 |
| 이미 적용한 방을 이전 모습으로 | **불가** | **기록 > 이전 버전 선택 > 복구**가 **적용한 뒤에 되돌리는 첫 번째 방법**이에요 |
| 복구를 취소하고 싶을 때(= redo 비슷한 것) | 해당 없음 | 복구도 새 버전이라 기록에서 복구 전 버전을 다시 골라 복구하면 돼요. 별도 redo 버튼은 두지 않아요 |
| 읽을 수 없는 방 데이터 | "저장된 방은 그대로 있어요 · 다시 불러오기" | 원하면 옛 문구("이전 버전 보기" → 기록 탭)로 되돌려 이전 버전 복구로 이어져요 |
| 적용 확인 안내 | "적용한 뒤에는 되돌릴 수 없어요" | "적용한 뒤에는 기록에서 이전 버전으로 복구할 수 있어요"(`copy-keys.md` 표) |

따라서 기록을 넣을 때 정할 것은 하나예요: 적용 확인 안내와 `undo.none.body`가 "기록에서 복구할 수 있다"를 안내하도록 바꿀지(권장), V1 문구를 그대로 둘지. 되돌리기 버튼을 도구 막대에 되살릴 필요는 없어요.

## 6. 탭 수·이동·설정 링크

- 시스템 탭 바를 4개로(`tab.history` 추가, 순서 홈·방·기록·설정). 탭 개수가 들어간 접근성 문구 `a11y.tab`("{total}개 중 {n}번째")는 그대로 쓰고 total만 4가 돼요. 탭 루트 4개 · 푸시된 상세에 "버전 상세" 추가는 `interaction-notes.md`의 표를 따라요.
- 방 도구 막대에 **기록 바로가기**(`room.ctl.history`, 시계 아이콘)를 추가해 꾸미기 · 기록 둘로 만들고, 글자 ≥160%에서는 꾸미기 한 줄 + 기록 한 줄(2단)로 돌려요. 접근성 이름 `a11y.history`.
- 뒤로 가기·선택된 탭 다시 누르기 규칙은 V1과 같아요. 기본 탭은 홈 그대로예요.
- **설정·홈에는 기록으로 가는 링크가 없었어요**(V1에서 지운 링크 없음). 기록 탭의 빈 상태 "방 꾸미러 가기"는 방 탭으로 전환해요.
- 도구 막대 항목 수가 1→2가 되므로 윤곽선·보호 영역 계산을 확인해요.

## 7. 채택 순서 제안

1. 열린 결정(버전 보관 개수, 복구의 점유 필요 여부, 읽을 수 없는 방 데이터의 복구 연결, 적용 안내 문구)을 정한다.
2. 이 폴더의 `copy-keys.md` 35개 키를 번역 리소스에 추가하고, 위 1~4절대로 스펙·데이터 모델·API·퀵스타트를 되돌린다.
3. 캔버스에서 `L-S11` · `L-S25`를 V1 보드 번호 S11 · S25로 되돌리고, V1 S07·S24·S23·S26 등의 탭 바와 도구 막대를 4탭·2항목(꾸미기·기록) 버전(`L-S24`)으로 교체한다. 이때 L 보드가 현재 V1 최신 화면과 어긋난 곳(문구, 홈 화면 등)을 다시 맞춘다.
4. `design/README.md` · `handoff.md` · 화면 수(15→16) · 키 수 · PNG를 갱신하고 대비 점검(`tools/contrast-check.mjs`)을 다시 돌린다.
