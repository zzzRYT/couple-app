# interaction-notes.md — 상호작용 노트

화면 사이 이동, 키보드와 공유 시트, 꾸미기 독과 방 위 미리 보기·적용·적용 직후 되돌리기, 점유와 이어받기·넘겨주기 시간, 오프라인·오류 동작, 두 사람 동기화가 눈에 보이는 방식을 정리했어요. 숫자는 `plan.md`의 가정(3분 idle 등)을 따르고, 디자인에서 새로 정한 값은 **(제안)** 으로 표시했어요.

## 1. 내비게이션 구조

```
앱 시작
 ├─ 로그인 안 됨 ─ S01 온보딩 ─ S02 로그인 ─ (공간 없음) S03 공간 생성 ─ S04 초대 코드
 │                                         └ (코드 있음) S05 코드 입력 ─ 참여
 ├─ 공간 종료됨 ─ S14 종료 안내(새 공간 시작하기)  ※ 탭 구조 대신
 └─ 활성 공간 ─ [시스템 탭 바]
        ① 홈 ─ 홈 루트(S06)
        │        ├ 초대 코드 보기(푸시, 탭 바 숨김) → S04 코드 화면
        │        ├ 날짜 수정(시트)
        │        └ 우리 방 열기 → ② 방 탭으로 전환
        ② 방 ─ 방 루트(S07) · 하단 입력창(처음에는 위에 요청 칩)
        │        └ 보내기 · 칩 한 번 → 꾸미기 독(방 아래 작은 독, 스크림 없음) → S08 / S09
        │                  ├ 방 위 미리 보기 → 적용하기 한 번 → 독이 닫히고 방 위 "적용했어요 · 되돌리기" 한 줄 → S10
        │                  └ X · 아래로 밀기 → 적용하지 않고 닫기(방은 그대로)
        ③ 설정 ─ 설정 루트(S13)
                 ├ 언어 · 시간대(시트)
                 ├ 마일스톤 알림 행(토글 → OS 권한 창 / 기기 설정 열기)
                 ├ AI 처리 동의 관리(푸시) / 동의 화면 S12(모달)
                 ├ 글꼴·오픈소스 라이선스(푸시)
                 ├ 문의 · 신고(푸시) → S15
                 └ 공간 종료(푸시) → S14 확인 → 종료 화면
```

### 1.1 탭을 이렇게 정한 이유 (제안)
- 홈 · 방 · 설정 3개. 스펙 범위(D-day, 꾸미는 방, 설정)를 그대로 3개 목적지로 나눈 거예요.
- **기록 탭은 첫 버전에 없어요(후속 버전)**: 버전 목록과 이전 버전 복구는 뺐어요. 방 도구 막대의 기록 바로가기도 함께 없앴어요. 나중에 다시 넣을 때는 설정과 방 사이에 탭 하나로 추가하는 안을 쓸 수 있어요. 되돌리기는 적용한 직후 방 위 한 줄에만 있어요(한 단계 · 다시 적용 없음, 아래 §4).

### 1.2 탭 바 표시 규칙
| 화면 종류 | 탭 바 |
|---|---|
| 탭 루트 3개 | 보임 |
| 푸시된 상세(라이선스 등) | 숨김 |
| 작업 흐름(공간 종료, 동의 관리, 신고·연결 끊기, 초대 코드) | 숨김 — 되돌리기 어렵거나 중요한 결정이라 다른 탭으로 새지 않게 |
| 시트·다이얼로그 | 시트는 탭 바를 덮음(모달) |
| 꾸미기 독 | 독이 열려 있는 동안 탭 바는 가려지고 닫으면 돌아와요. 모달이 아니라서 스크림이 없고 방은 독 위로 그대로 보여요 |
| 탭 구조 앞의 흐름(S01~S05)과 종료 화면 | 없음 |

### 1.3 플랫폼 동작
- 각 탭은 자기 스택을 기억해요. **선택된 탭을 다시 누르면** 루트에서는 맨 위로 스크롤, 푸시된 화면에서는 루트로 돌아가요(iOS 관례, Android도 동일하게).
- 뒤로: iOS 왼쪽 가장자리 스와이프 + 뒤로 버튼. Android 시스템 뒤로(제스처·버튼): 푸시/시트/다이얼로그를 먼저 닫고, 탭 루트에서는 **홈 탭으로**, 홈 탭 루트에서는 앱 나가기.
- 딥링크(초대 코드 링크 등)는 이번 범위가 아니에요. 공유 문구에는 코드만 넣어요(`invite.shareMsg`).
- 탭 바에는 배지를 쓰지 않아요("상대가 꾸미는 중"은 방 화면 안에서 보여요). 마일스톤 알림은 OS 알림 배너로만 와요.

## 2. 시스템 컴포넌트 원칙 (탭 바 등)
탭 바는 **시스템이 소유하는 UI**예요(방 장면 밖). 구현은 네이티브 탭(iOS UITabBarController 기반, Android Material 3 NavigationBar)을 쓰고 직접 그린 막대를 쓰지 않아요. 재질(반투명 블러)·높이·아이콘 크기·글꼴·선택 애니메이션은 OS가 정하고, 앱은 **틴트색 · 비선택 틴트 · 라벨 문구 · 아이콘 이미지 · 배지**만 정해요. 탭 바는 **보호 영역**이라 방 장식이 가리거나 터치를 가로챌 수 없고, 보호 영역 계산에는 기기에서 측정한 실제 높이를 써요(글자 확대 시 Android는 높이가 늘어요).

## 3. 레이어 순서 (방 화면, 아래 → 위)
1. 방 배경(테마 에셋) → 2. 장면 캔버스(오브젝트·마스코트·장면 문구, 사용자가 정한 레이어 순서) → 3. **D-day 위젯**(네이티브) → 4. **방 하단 입력창과 꾸미기 독**(네이티브, 아래쪽 · 미리 보기 배지와 "원래 방 보기" 토글은 위쪽) → 5. **시스템 탭 바**(OS) → 6. 안내 배너·토스트 → 7. 모달(시트·다이얼로그, 스크림 포함).
장면 오브젝트는 3~5번 아래에 있고 터치를 받지 않아요(방은 프롬프트로 꾸미고 직접 끌지 않아요). 3~5번과 시스템 안전 영역이 보호 영역이라, 서버·클라이언트 검증이 장식 배치를 이 영역 밖으로 자동 이동시켜요(미리 보기에 안내: `preview.warn.protected`).

## 4. 꾸미기 흐름: 꾸미기 독 · 방 위 미리 보기 · 적용 한 번 · 적용 직후 되돌리기

방이 화면의 중심이에요. 대화는 방 아래 작은 **꾸미기 독**(모달 아님, 스크림 없음)에서 하고, 미리 보기는 **방 화면 위에** 그려요. 채팅 시트·작은 방 카드·적용 확인 화면은 없어요. 2026-11-10에 오너가 되돌리기(D1), 차례 넘겨주기(D2), 횟수 표시(D3)를 정했어요. 화면은 캔버스 S07 위쪽 · S08 · S09 · S10.

| 단계 | 꾸미는 사람(점유자) | 상대 |
|---|---|---|
| 시작 | 방 하단 입력창. 처음에는 그 위에 "이렇게 말해 볼 수 있어요" + 요청 칩(S07-first), 다시 온 사람은 최근 요청 · 우리 장식 · 아이디어 칩(S08-free). 칩을 누르거나 보내면 **그때 점유가 시작돼요**(보내기 = 점유, "내가 꾸밀게요" 단계 없음). 칩은 미리 보기만 만들고 방은 바꾸지 않아요 | 입력창이 "{이름}님이 꾸미는 중이에요 · 지켜보기"로 잠겨요(S24-partner). 지켜보기를 누르면 같은 독을 읽기 전용으로 봐요 |
| 만드는 중 | 작은 독(약 210pt)에 내 요청 + 진행 한 줄 "방에 맞게 고르는 중이에요" + 움직이지 않는 진행 막대 + "보통 10초 안에 끝나요"(**가정** · 서버 실측으로 정해요). **15초(가정)** 가 넘으면 "평소보다 오래 걸려요 · 닫고 기다리기". 닫아도 계속 만들고, 다 되면 방 위 한 줄 "미리 보기가 준비됐어요 · 보기"(S09-chat-ready) | 같은 진행 한 줄 + 잠긴 입력창(차례 부탁하기) |
| 미리 보기 | **방 화면 위에** 그려요. 바뀐 소품은 점선 + "새로 · 옮김 · 빠짐" 이름표, 위쪽 배지 "미리 보기 · 아직 적용되지 않았어요", 오른쪽 위 **원래 방 보기** 토글(누를 때마다 바뀌고 배지가 "원래 방이에요"로). 독(약 200pt)에는 요약 한 줄 + "오늘 n번 남음" + **적용하기** · 다시 만들기 + 하나만 바꾸기 칩("{소품} 빼 줘 · {소품} 하나 더 · 색만 바꿔 줘 · 직접 말하기") | 자기 방 위에 같은 미리 보기, 배지 "{이름}님의 미리 보기 · 아직 적용 전", 원래 방 보기 가능. 독에는 "{이름}님이 적용할지 정하고 있어요" + 잠긴 입력창(차례 부탁하기) |
| 지난 미리 보기 | 독을 위로 밀면 이번 대화 기록(S08-mine). 지난 미리 보기의 "이걸로 다시 보기"가 그 미리 보기를 방 위에 다시 그려요(AI 호출·횟수 없음, 점유와 대화는 이어져요) | 같은 미리 보기로 바뀌는 걸 실시간으로 봐요 |
| 적용 | **적용하기 한 번이 확인**이에요(확인 화면 없음, 자동 적용 없음). 서버 transaction(점유자 + 기대 버전 + 멱등 키) → 새 버전 → 독이 닫히고 탭 바가 돌아오며 바뀐 방이 바로 보여요. 방 위에 **"적용했어요 · 되돌리기"** 한 줄(S09-applied). **점유는 이 한 줄이 끝날 때까지 유지돼요** | 방이 바로 바뀌고 한 줄 "{이름}님이 방을 바꿨어요". 입력창은 그 한 줄이 끝날 때까지 잠겨 있어요(차례 부탁하기 가능, S09-partner-applied). 앱이 닫혀 있었으면 열 때/동기화 때 바뀐 방을 봐요 |
| 적용 직후 되돌리기 (**한 단계**) | 한 줄의 되돌리기 → 같은 자리에서 "되돌리는 중이에요" → "되돌렸어요 · 적용하기 전 방으로 돌아왔어요". 확인 창 없음, **다시 적용(redo) 없음**. 서버는 바로 앞 버전을 새 버전으로 다시 적용해요. 한 줄은 **다음 요청을 보내거나, 방 탭을 떠나거나, 3분 동안 쉬면** 사라지고(S10-ended) 그 뒤에는 되돌릴 수 없어요. 그새 방이 바뀌었으면 되돌리지 않고 지금 방을 보여 줘요(S10-conflict). 실패하면 방은 적용한 그대로이고 같은 자리에서 다시 시도해요(S10-error) | 버튼이 없어요. 되돌려지면 방이 바뀌고 한 줄 "{이름}님이 되돌렸어요"(S10-busy) |
| 닫기 (적용 안 함) | X나 아래로 밀기. 확인 없이 닫히고 현재 방 유지, **점유 해제**, "적용하지 않고 닫았어요. 우리 방은 그대로예요."(S09-cancelled) | "{이름}님이 적용하지 않고 닫았어요. 방은 그대로예요." |

- **막힐 때는 한 줄 + 다음 행동 하나**: 할 수 없는 요청 → 할 수 있는 요청 칩, 거절 → 대안 칩(이유는 "왜 안 되나요?"를 눌러야 펼쳐요), 만들지 못함 → 다시 시도("방도 횟수도 그대로예요"), 하루 3번 → 입력창 한 줄 + 자세히(§14), 오프라인 → 적용·다시 만들기 잠김 + 이유, 동의 전 → 입력창 한 줄 → S12(동의하면 고른 칩·쓰던 글을 그대로 보내요). 쓴 글은 입력창에 남아요.
- **경고**: 보호 영역을 가리던 소품을 옮겼거나 한도(소품 16 · 문구 3)로 줄였을 때는 요약 아래 한 줄로 알리고 남은 횟수를 같은 줄 뒤에 둬요(S09-warn-protect · S09-warn-limit).
- **버전 충돌**(두 기기의 동시 적용·늦은 재시도): 서버가 거부하면 "방이 방금 바뀌었어요 · 최신 방을 불러왔어요"와 다시 만들기 한 번으로 안전하게 끝나요(방은 한 번만 바뀜, S09-conflict).
- **마스코트 꾸미기는 없어요**(`handoff.md` §11). 마스코트는 고정 캐릭터이고, 프롬프트가 모습을 바꾸라고 하면 "아루미는 바꿀 수 없어요" 한 줄과 대안 칩으로 방 오브젝트 꾸미기를 권해요.

## 5. 점유와 이어받기 · 넘겨주기 (시간은 `plan.md` 가정 · 캡틴이 조정 가능)

| 항목 | 값 | 화면에서 |
|---|---|---|
| idle 만료 | **3분**(가정): 의미 있는 편집·제출·모델 생성 중에는 서버 시간 기준으로 연장 | 늘 떠 있는 안내는 없어요(예전 입력칸 아래 문구는 지웠어요). 30초 전 경고만 보여요 |
| 앱이 백그라운드/종료 | heartbeat가 멈춰 만료 시각에 풀림 | 상대 화면은 만료 후에 이어받기를 제안 |
| 만료 임박 알림 | 남은 시간 **30초**(제안)부터 독 맨 위 한 줄 "{s}초 뒤에 꾸미기가 풀려요 · 계속하기"(S09-expiring) | 계속하기 = 활동으로 간주해 연장 |
| 내 점유가 풀렸을 때 | 쓰던 글은 입력창에 남아요(로컬 초안) | "꾸미기가 풀렸어요 · 쓰던 글은 남아 있어요"(S08-idle). 보내면 다시 내가 맡아요 |
| 적용한 뒤 | **되돌리기 한 줄(§4)이 끝날 때까지 점유 유지**(2026-11-10 오너 결정). 독은 닫혀 있고 30초 경고는 띄우지 않아요. 3분 idle이면 한 줄만 조용히 사라지고 점유가 풀려요 | 상대 입력창은 그동안 "{이름}님이 꾸미는 중이에요 · 차례 부탁하기"(S09-partner-applied) |
| 차례 부탁하기 · 넘겨주기 | **꾸미는 사람이 스스로 넘겨줄 수 있어요**(2026-11-10 오너 결정). 지켜보는 사람이 잠긴 입력창 안 **차례 부탁하기**를 누르면 꾸미는 사람에게 알리고, **넘겨주기** 한 번에 서버가 점유를 원자적으로 옮겨요. 대화와 미리 보기는 그대로예요. 부탁은 점유를 바꾸지 않는 실시간 알림이에요(저장 안 함, 가정) | 부탁한 쪽: 같은 자리에 "{이름}님에게 알렸어요"(다시 누를 수 없음, S08-nudge-sent). 꾸미는 쪽: 독 맨 위 "{이름}님도 꾸미고 싶대요 · 넘겨주기"(S08-nudge, 무시하면 그대로). 넘겨받은 쪽: "{이름}님이 넘겨줬어요 · 이제 내가 꾸며요" + 바로 적용 가능(S08-handover). 되돌리기 한 줄이 떠 있을 때 넘겨주면 되돌리기는 거기서 끝나요 |
| 상대가 이어받기 | 상대 점유가 **만료된 뒤에만** 가능. 서버가 `expectedOwnerUserId`와 만료 시각을 비교해 원자적으로 owner 변경 | "{이름}님이 자리를 비웠어요 · 이어서 꾸미기"(S08-takeover). 대화와 미리 보기는 그대로이고, 이어받은 미리 보기는 한 줄 안내와 함께 바로 적용할 수 있어요(S09-chat-takeover) |
| 이어받기 경합 | 둘이 동시에 누르면 한 명만 성공 | 진 쪽에 "{이름}님이 먼저 이어받았어요" 한 줄 + 잠긴 입력창(차례 부탁하기, S08-takeover-lost) |
| 해제 이벤트 | 적용하지 않고 닫기, 적용 뒤 되돌리기 한 줄이 끝날 때(되돌리기 완료 · 방 탭 이탈 · 3분 idle), 넘겨주기(상대에게 이동), idle 만료. 적용 자체와 "이걸로 다시 보기"는 점유를 풀지 않아요. 적용한 사람이 다음 요청을 보내면 한 줄만 끝나고 점유는 이어져요 | 상대 입력창의 잠금이 풀려요 |

숫자(3분, 30초 경고)는 코드에 상수로 두지 말고 서버 설정으로 받아요(캡틴이 조정할 수 있다고 `plan.md`에 있어요). 만드는 중의 "보통 10초"와 오래 걸림 15초도 가정이라 같은 방식으로 받아요.

## 6. 키보드와 공유 시트
- **키보드(꾸미기 입력)**: 입력창을 누르면 요청 칩 한 줄 + 입력창이 키보드 바로 위로 올라오고, **방은 그 위에 그대로 보여요**(시트가 방을 덮지 않아요, S07-chat-typing · S08-free). 칩은 입력창이 비어 있을 때만 보이고 쓰기 시작하면 숨어요. 칩 줄은 한 줄 가로 스크롤이고 끝이 흐려져요. 처음 보낼 때는 입력창 아래 한 줄 "보내면 내가 꾸미는 동안 {이름}님은 지켜봐요". 결과 독의 "직접 말하기" 칩도 키보드 + 입력창을 열어요. 보내기는 입력창 안 원 버튼, 키보드의 완료/줄바꿈 키는 줄바꿈(제출은 보내기 버튼으로만 — 의도치 않은 제출 방지 (제안)).
- **날짜 입력**: 키보드가 아니라 3열 휠 시트(년·월·일).
- **초대 코드 입력**: 영문 대문자 + 숫자 키보드, 자동 대문자, 붙여넣기 버튼(`join.paste`), 8자가 차면 자동으로 확인 버튼 활성.
- **공유 시트(초대 코드)**: "코드 공유하기" → OS 공유 시트(iOS 시트 / Android 공유 시트)에 문구 `invite.shareMsg`("... 초대 코드: {code} (24시간 안에 입력해 주세요)")를 넘겨요. 시트를 닫으면 코드 화면 그대로(공유 취소 안내 `invite.shareCancelled`). "코드 복사"는 클립보드에 코드만 복사하고 "복사했어요" 토스트.
- **재발급**: 새 코드를 만들면 이전 미사용 코드는 즉시 폐기돼요. 확인 다이얼로그에서 이 점을 먼저 알려요.

## 7. D-day 위젯의 이동·숨김
- 위젯의 위치·모양·색·크기는 **프롬프트로만** 바꿔요(방에서 직접 끌지 않아요). 이동은 보호 영역 밖에서만 허용되고, 이동 결과가 가리면 서버/클라이언트 검증이 자동으로 옮겨요.
- 위젯을 숨기면 방에는 안내 배너(`room.ddayHidden`)가 보이고, 홈 탭의 D-day는 그대로예요.
- 글자 확대 시 위젯은 같이 커지고(자동 축소 없음) 보호 영역이 다시 계산돼요. 최대 폭을 넘으면 줄바꿈.

## 8. 오프라인 · 오류 · 재시도

| 상황 | 동작 |
|---|---|
| 오프라인 | 마지막 확정 방·D-day를 읽기 전용으로 보여요. 방 탭: 꾸미기 비활성, 배너 "인터넷이 끊겨서 보기만 할 수 있어요". 꾸미기 패널은 열 수 있지만 입력칸 비활성("인터넷에 연결되어야 꾸밀 수 있어요"). **오프라인 편집·미리 보기 적용은 없어요.** |
| 동기화 실패 | 마지막 저장본을 보여 주고 배너(다시 시도). 자동 재시도는 연결이 돌아올 때 한 번, 이후 사용자 요청. |
| 동기화 대기 | 연결되면 최신으로. 대기 중 표시 배너(`sys.pending.*`) |
| 서버/AI 일시 장애 | 꾸미기만 막고(`sys.ai.*`) D-day·방 보기는 유지. 방은 안 바뀌었다고 말해요. |
| 로그인 만료 | 전체 화면 안내 + 다시 로그인(`sys.login.*`). 입력하던 프롬프트는 로컬 초안으로 보존. |
| 접근 거부(구성원 아님·종료) | 전체 화면 안내 + 코드가 있으면 입력 / 새 공간 만들기 |
| 요청 한도(하루 3회, 커플당, 성공한 미리 보기만 셈) | 입력칸 잠김 + 안내(방은 그대로, 내일 이어서). 한도는 남용 방지용이라 가격 문구를 쓰지 않아요. |
| 구버전 장면 | 읽을 수 있는 부분만 보여 주고 "앱 업데이트" 안내(`sys.old.*`) |
| 삭제된 에셋 | 빈 자리를 점선 상자로 두고 안내, 연결이 좋아지면 자동으로 다시 불러와요 |
| 장면 데이터 읽기 오류 | 방 위에 "저장된 방은 그대로 있어요" 안내 + "다시 불러오기"(`room.recover.*`). 이전에는 기록 탭의 복구로 이어졌지만 기록을 뺐어요 |
| 버튼 중복 탭 | 제출·적용·되돌리기는 진행 중 비활성(로딩 상태)이고 서버는 멱등 키로 이중 처리를 막아요 |

## 9. 두 파트너의 동기화가 눈에 보이는 방식
- 지켜보는 사람 화면 위쪽 한 줄 "{이름}님이 꾸미는 중 · 실시간으로 보고 있어요", 독의 "쓰는 중…"과 같은 진행 한 줄, **자기 방 위에 그려지는 같은 미리 보기**(배지 "{이름}님의 미리 보기 · 아직 적용 전"), 잠긴 입력창 "{이름}님이 꾸미는 중이에요 · 차례 부탁하기", 한 줄 알림(방을 바꿨어요 · 되돌렸어요 · 적용하지 않고 닫았어요 · 넘겨줬어요)으로 보여요. 꾸미는 사람 자신의 화면에는 점유 칩이 없어요(상대 화면이 말해요).
- 차례를 부탁하면 꾸미는 사람 독에 한 줄이 뜨고, 넘겨받으면 대화와 미리 보기가 그대로 넘어와요(§5).
- 상대가 방을 바꿨을 때(내가 방 탭을 보고 있는 중): 장면이 바로 바뀌고 토스트 "{이름}님이 방을 바꿨어요". 상대의 되돌리기 한 줄이 끝날 때까지 내 입력창은 잠겨 있고, 상대가 되돌리면 장면이 다시 바뀌며 "{이름}님이 되돌렸어요"가 보여요.
- 초대·꾸밈 변경에 대한 알림은 없어요. 앱을 열거나 동기화될 때 최신 상태를 봐요(스펙). 알림은 사용자가 켠 마일스톤 로컬 알림뿐이에요(§13).

## 10. 접근성 상호작용
- **스크린 리더**: 읽기 순서(제안, 화면 위 → 아래) = D-day 위젯 → 마스코트 → 방 하단 입력창(꾸미기 독이 열려 있으면 독) → 시스템 탭 바. 방 위 미리 보기는 이미지 하나로 "미리 보기: {바뀐 내용}. 아직 적용되지 않았어요"라고 읽고 점선 이름표는 읽지 않아요. 장식 소품은 건너뛰어요. 상태 변화는 한 번만 알려요(점유 변경, 미리 보기 생성, 적용, 오류).
- **큰 글자**: 줄바꿈과 스크롤로 받고 자동 축소 없음. 꾸미기 독은 200%에서 위쪽 방 영역 아래에 고정되고 버튼이 세로로 쌓이며 독 안이 스크롤돼요. iOS 탭 바는 시스템의 큰 글자 보기를 써요.
- **동작 줄이기**: 화면 전환 애니메이션 없음. 떠다니는 편지(§10.1)도 멈춘 채로 그려요.
- **고대비**: 윤곽선 3px, 글자·컨트롤 색을 더 진하게. 에셋 그림은 그대로.
- **터치**: 최소 48 × 48. 긴 누름에만 있는 동작은 없어요(모든 동작에 명확한 탭 동작).

### 10.1 떠다니는 편지 (S04 상대 대기 화면)
- 대상: S04 **상대 참여 대기** 화면의 편지 일러스트(스팟) 하나. 편지 오브젝트만 움직이고 구름·반짝임은 가만히 있어요(제안: 움직이는 요소를 하나로 제한).
- 움직임: 제자리에서 위로 6pt 올랐다가 내려오는 왕복, 3.2초, ease-in-out, 무한 반복. 회전·크기 변화 없음.
- **밝은 화면과 어두운 화면에서 똑같이** 적용해요. 색이 아니라 위치만 바꾸는 움직임이라 모드별로 다른 값이 없어요. 캔버스의 S04 밝은 앱·어두운 앱 두 프레임에 모두 들어 있어요.
- 동작 줄이기(웹 `prefers-reduced-motion`, iOS '동작 줄이기', Android '애니메이션 제거')가 켜져 있으면 정지한 채 보여 줘요.
- 장식이라 읽기 순서에서 제외(`aria-hidden`)하고, 상태 안내는 제목·본문 글자가 맡아요. 정적 PNG 내보내기에는 움직임이 담기지 않아요.
- 다른 화면의 편지 스팟(온보딩 재실행, 로그인 처리, 신고 완료)은 그대로 정적이에요. 같은 움직임을 쓰고 싶으면 알려 주세요(제안).

### 10.2 오브젝트 순환 로더 (전역 기본 로딩 표시)
- 쓰는 곳: 전체 화면을 차지하는 로딩(S03 공간 생성 중, S02 로그인 처리 중·로그인 화면으로 이동 중). 버튼 안의 작은 로딩과 목록·카드의 자리 표시(스켈레톤)는 기존 그대로예요.
- 모양: 화분 → 풍선 → 창문 → 책 순서로 오브젝트가 하나씩 커지며 나타났다가 작아지며 사라져요. 한 바퀴 4.8초, 오브젝트마다 1.2초 간격, 항상 한 개만 보여요. 아래에 문구("공간을 만들고 있어요" 등)를 붙이고 스피너는 따로 두지 않아요.
- 밝은 앱·어두운 앱 모두 같은 그림·같은 움직임이에요. 동작 줄이기가 켜져 있으면 첫 오브젝트(화분)가 멈춘 채로 보여요.
- 읽기: 그림은 읽지 않고(`aria-hidden`) 문구만 상태로 한 번 알려요.
- 창문은 **로더 전용 그림**이에요(결정 · 가정, 2026-10-27: 권고안 "로더 전용"을 소유자가 "계속 진행하자"로 받아들임). 카탈로그에 넣지 않고 24개 그대로예요. 정식 오브젝트(`obj_decor_window`)로 만들지 않고, 프롬프트로 방에 놓을 수도 없어요. 나중에 방 소품으로 쓰고 싶으면 그때 카탈로그에 더하는 별도 결정이에요.

## 11. 방 안을 돌아다니는 마스코트 (S07 · S24 전체 크기 방)
- 마스코트는 방 장면의 기본 오브젝트이면서 가만히 서 있지 않고 **40초 한 바퀴**로 행동을 번갈아 해요. 방 안 포즈 6종과 좌우 반전만 써서 새 그림이 필요 없어요(포즈 이름은 `design/mascot/` 기준).
- 순서(제안): 인사(`wave_main`) 2초 → 오른쪽으로 걷기(`walk` 반전) 4초 → 신나게 인사(`cheer`) 2.4초 → 왼쪽 끝까지 걷기 6.4초 → 올려다보기(`lookup`) 2.4초 → 엎드려 쉬기(`lie`) 3.2초 → 잠자기(`sleep`) 5.6초 → 올려다보기 2초 → 가운데로 걷기 4.8초 → 인사 2.4초 → 둘러보기(`lookup`) 4.8초 → 처음으로.
- 이동 범위는 화면 너비의 ±27% 안쪽 바닥 위(소품 앞으로 지나가요). 걷는 동안만 4pt씩 위아래로 통통 튀어요. 걷기는 왼쪽을 보고 있는 `walk` 포즈를 쓰고 오른쪽으로 갈 때는 좌우를 뒤집어요.
- **탭 반응**: 마스코트를 누르면 1.2초 동안 신나게 인사(`cheer`)를 하고 하던 행동으로 돌아가요(캔버스에서는 누르고 있는 동안만 보여요). 터치 영역은 마스코트 그림 전체예요.
- 상태별 규칙: 읽기 전용(오프라인)에서도 걷기는 계속해도 되지만(장식), 꾸미는 동안에는 돌아다니지 않고 앱이 정한 포즈로 서 있어요: 만드는 중엔 올려다보기(`lookup`), 미리 보기 중엔 인사한 채 멈춤(`wave_main`), 적용하면 신나게 인사(`cheer`) 1.2초 뒤 원래 행동으로(방이 바뀌는 순간에 시선이 분산되지 않게). 대화 아바타나 말풍선으로는 쓰지 않아요(FR-018). 로딩·복구 오류·보호 영역 표시 화면에는 마스코트가 나오지 않거나 정지 상태예요. 축소 보기(방 카드, 이번 대화 기록의 지난 미리 보기)는 늘 정지 포즈예요.
- 낮·밤 방, 밝은·어두운 앱에서 같은 순서예요. 밤 방에서는 잠자기 구간을 늘려도 좋아요(제안).
- 동작 줄이기가 켜져 있으면 걷지 않고 `wave_main` 한 장으로 서 있어요. 스크린 리더는 "마스코트, 인사하고 있어요"처럼 **현재 포즈를 한 번만** 알려요(행동이 바뀔 때마다 읽지 않아요).
- 더 자연스럽게 하려면 포즈별 프레임이 필요해요: 걷기 4~6장(다리·팔 교차), 자는 숨 2장(몸이 살짝 부풀었다 가라앉기), 엎드려 늘어짐 2장. 필요하면 소유자가 따로 제공(지금은 정지 이미지 6장으로 흉내).

- **되살림(결정, 시점은 가정)**: 방에는 항상 마스코트가 하나 있어요. 프롬프트로 위치·크기를 정하거나 방에서 **지울 수는 있지만**, 지워지면 방 화면에 고정 컨트롤 **"아루미 다시 부르기"**(S07-no-mascot)가 뜨고 누르면 기본 자리에 돌아와요(점유 중인 상대가 있으면 비활성). 방을 다시 열 때 점유자가 없으면 한 번 자동으로 돌아와요(가정). "아루미를 다시 불러줘" 프롬프트도 같고, 한도 16개에 포함되며 모습은 절대 바뀌지 않아요.

## 12. 홈 상단 배경 사진 (S06 · S23 · 설정)
- **무엇인가**: 홈 화면 맨 위 커버는 두 사람이 올린 사진이 채워요. 에셋 일러스트·마스코트를 넣지 않아요. 사진이 없으면 앱 바탕색(종이색)이고 글자는 어두운 색이에요.
- **누가 보나(결정)**: 공간의 두 사람이 같은 사진을 봐요. 어느 쪽이든 바꾸거나 없앨 수 있고 **마지막으로 바꾼 사용자의 사진**이 보여요. 사진을 고르는 시트 맨 위에 "마지막으로 {이름}님이 바꿨어요 · {시각}"(`cover.by`)이 있고, 상대가 바꾸거나 없앴을 때 홈을 열면 "{이름}님이 배경 사진을 바꿨어요/없앴어요" 토스트(`cover.partner.*`)가 한 번 떠요(S06-photo-partner-changed · S06-photo-partner-removed). 공간이 삭제될 때(30일 복구 기간이 끝나면) 사진 파일도 함께 지워요(복구 기간에는 유지).
- **들어가는 길**: ① 홈 커버의 "사진 추가"(없을 때) 또는 사진 아이콘 버튼(있을 때) ② 설정 > 공간의 "홈 배경 사진" 행. 둘 다 같은 시트(앨범에서 고르기 · 사진 없애기 · 취소)를 열어요.
- **올리는 흐름**: 시트 → **시스템 사진 선택기**(사진 접근 권한 요청 없음) → 자르기 화면(커버 비율 고정, 끌어서 옮기고 두 손가락으로 확대, 3×3 격자) → 완료 → 커버에서 "사진을 올리고 있어요" → 성공 토스트 "배경 사진을 바꿨어요".
- **실패**: 올리기 실패는 기존 사진을 유지하고 커버 아래 오류 배너 + 다시 시도, 사진 불러오기 실패는 종이색으로 대체 + 경고 배너 + 다시 시도, 형식·크기 오류(JPG·PNG·HEIC, 20MB 이하)는 알림창. 오프라인에서는 마지막으로 받은 사진을 보여 주고 바꾸기만 막아요(제안).
- **글자 읽기**: 사진 위 글자는 흰색 + 아래쪽 어두운 막(#201610, 64%)으로 가장 밝은 사진에서도 4.5:1 이상(5.33)이에요. 맨 위에는 상태 표시줄 글자를 위한 크림 베일(55%)을 덮어요. 앱 이름·사진 버튼은 사진 위에 직접 놓지 않고 앱 면 알약 위에 놓아요(`contrast-report.md` 홈 커버).
- **접근성**: 사진은 "우리가 올린 배경 사진"으로 읽고(대체 텍스트를 사용자가 입력하게 할지는 열린 질문), 사진이 바뀌어도 글자 크기·위치는 변하지 않아요. 200% 글자에서는 커버가 글자 높이만큼 늘어나고 막도 같이 늘어나요. 고대비에서는 알약 윤곽선만 진해져요.
- **다른 화면**: 홈 탭(S23)은 같은 커버를 써요. 그 밖의 화면은 위쪽에 에셋을 쓰지 않아요. 방 화면의 날짜 위젯 배경은 방 색이고 사진을 쓰지 않아요(사진은 홈 전용).
- **검수·신고(결정)**: 사진에는 검수 단계도 신고 기능도 없어요. S15의 신고 대상 목록(상대·공유 문구·방 장면)에 사진이 없고 사진 위에 신고 버튼도 없어요.
- **승인됨(2026-10-26)**: JPG·PNG·HEIC 20MB 이하, 비율 고정 자르기, 서버 재인코딩, 교체·삭제한 이전 파일은 새 사진 저장 확인 뒤 24시간 뒤 삭제, 개인정보 문구는 초안대로. 최종 개인정보 처리방침 문구만 법률 검토가 필요해요. 해상도(@3x 기준 1170px 너비)와 원본 보관 여부는 구현 때 확정해요.

## 13. 마일스톤 축하와 알림 (S28 · 홈 S06/S23 · 방 S07/S24 · 설정 S13/S26)
- **마일스톤**: 일수 50·100·200·300·500·1000일(당일 = 1일째)과 **주년(함께한 날짜와 같은 달력 날짜, 매년)**. 2월 29일 시작은 평년 2월 28일, 주년과 일수가 같은 날이면 축하는 하나(주년 우선). 방 시간대 기준으로 서버가 계산해요. 값은 제안이에요.
- **앱을 열었을 때**: 마일스톤 당일부터 7일(주년 포함) 안에 처음 열면 홈에 **축하 카드**, 방 탭에 마스코트 `신나게 인사` 포즈와 **말풍선**이 보여요. 7일이 지나면 보이지 않고 지난 것으로만 기록돼요. 당일이면 "아루미가 두 사람의 오늘을 함께 축하해요", 늦게 열면 "{날짜}이 기념일이었어요. 아루미가 조금 늦게 축하해요".
- **한 번만**: 마일스톤마다 커플당 한 번, 두 사람은 각자 한 번씩 봐요. 카드 ✕ 또는 말풍선 ✕ = 본 것으로 처리(한쪽만 닫아도 둘 다 사라져요). 오프라인에서 닫으면 기기에 저장했다가 연결되면 한 번만 전달해요. 한 번에 하나만 보여요.
- **알림(옵트인, 기기에 예약하는 로컬 알림)**: 서버 푸시는 없고 서버에 토큰도 저장하지 않아요.
  - **언제 묻나**: 구성원이 **첫 축하 카드를 닫은 직후** 사전 안내 시트가 한 번 떠요("알림 켜기" / "다음에"). **앱 첫 실행에서는 절대 묻지 않아요.** "다음에"면 시트는 다시 안 뜨고 설정의 알림 행에서만 켤 수 있어요. "알림 켜기"를 눌러야 OS 권한 창이 떠요.
  - **권한 결과**: 허용 → 설정 행 켜짐(기념일 오전 9시). 거절·해제 → 행이 "기기에서 알림이 꺼져 있어요" + 켜는 방법("기기 설정 열기").
  - **보내는 것**: 마일스톤 당일 오전 9시(방 시간대), 제목 = 앱 이름, 본문 "아루미가 축하할 일이 생겼어요."(이름·날짜·일수 없음, 잠금 화면 안전). 알림은 당일 1회이고 놓친 날은 다시 보내지 않아요(앱 안 7일 규칙이 대신해요).
  - **예약 규칙**: 구성원마다 자기 기기가 다가오는 마일스톤 최대 3개를 OS에 예약하고 마일스톤 키로 중복을 막아요. 다시 예약: 함께한 날짜 변경 · 방 시간대 변경 · 앱 업데이트 · 앱을 열 때. 취소: 공간 종료 · 연결 끊기 · 로그아웃 · 알림 끄기. 상대를 초대하는 중에는 예약하지 않아요.
  - **누르면**: 앱이 **홈**으로 열리고 아직 안 본 축하 카드가 바로 보여요(이미 본 것이면 홈만). 카드를 닫으면 본 것으로 기록돼요.
  - **켜는 곳(설정)**: 설정 > 알림 > 마일스톤 알림 토글. 이 기기에만 적용돼요. 한 사람만 켜도 돼요.
  - **스토어·개인정보 메모**: 사용자가 켠 로컬 알림이고 마케팅이 아니에요. 알림 권한 사용 목적을 적고, 서버에 토큰을 저장하지 않으며 문구에 개인정보가 없다는 점을 심사 메모에 써요. 처리방침 문구는 법률 검토.
- **함께한 날짜를 고치면**: 이미 축하한 마일스톤은 다시 안 보여요. 다만 고친 날짜로 계산한 마일스톤 날이 아직 오지 않았다면 기록을 지우고 그날 한 번 더 축하해요(예약 알림도 다시). 지난 날짜로 바뀌면 기록이 없는 마일스톤만 7일 규칙을 따라요.
- **보이지 않는 경우**: 상대를 초대하는 중, 공간 종료, 오프라인, 서버 오류. 이때도 홈·방·꾸미기는 그대로예요.
- **움직임**: 마스코트가 2.4초 주기로 통통(최대 16pt), 반짝이 두 개가 1.4초 주기로 깜박임 — 앱이 정한 고정 동작이고 프롬프트·장면 데이터로 바꿀 수 없어요. 카드·말풍선이 열려 있는 동안 반복하되 10초 뒤 멈춰요(제안). **동작 줄이기**에서는 정지 포즈·정지 반짝이예요.
- **기념 꾸미기 제안(기존 흐름 그대로)**: 카드의 "기념 방 꾸미기 보기" 또는 방 하단 제안 입구 → (아무도 점유하지 않았으면) 점유 시작 → **미리 보기(S09)**에 "{라벨} 제안" 뱃지, 변경 요약, "AI를 쓰지 않는 앱의 제안이에요" 안내 → **적용하기 한 번**(확인 화면 없음) → 방이 바뀌어요. 적용 직후 되돌리기 한 줄은 꾸미기와 같아요(§4 · 2026-11-10 오너 결정, S28 보드의 제안 미리 보기 화면은 아직 예전 그림이에요). **방은 구성원이 확인하고 적용해야만 바뀌어요.** 상대가 점유 중이면 입구가 잠기고, 방이 가득 차면 일부만(없으면 잠김). AI·동의·하루 5회 한도와 무관해요.
- **접근성**: 카드 영역 이름 "{라벨} 축하 카드", 말풍선 상태(status) 낭독, 닫기 버튼 이름, 터치 44pt, 글자 130%에서 카드 세로 쌓기(알림 안내 시트·설정 행도 줄바꿈).
- **에셋**: 새 오브젝트 0개(24종 그대로).

## 14. 신고·연결 끊기, 한 공간만, 연령, 하루 한도 (2026-10-26 2차 답변)

- **연결 끊기(예전 "차단")**: S15의 진입 버튼은 "○○님과 연결 끊기". 누르면 확인 창이 **결과를 먼저 말해요**: "연결을 끊으면 ○○님은 이 공간의 방과 대화를 볼 수 없고, 이 공간이 종료돼요. 함께 쓰던 데이터는 삭제돼요." (기간·날짜·복구 안내 없음) 확인하면 공간 종료 안내(S14)와 같은 상태로 가요. 신고는 별개 흐름(대상 → 이유 → 보내기)이고 연결 끊기를 하지 않아도 보낼 수 있어요. 구현의 문구 키·API 이름(`report.block*`, `block`)은 그대로예요.
- **한 공간만**: 이미 다른 공간에 있는 사용자가 초대 코드를 입력하면 S05의 안내 배너("이미 다른 공간에 있어요 — 한 번에 하나의 공간만 쓸 수 있어요. 지금 공간에서 먼저 나온 뒤(설정의 공간 종료) 코드를 다시 입력해 주세요")와 "지금 공간 보기" 버튼이 나와요. 코드는 소모되지 않아요.
- **연령**: 가입 시작 화면의 약관 줄이 "계속하면 만 14세 이상이며 아래 내용에 동의하는 것으로 봐요"라고 말해요. 생년월일은 묻지 않아요(가정). 최종 문구는 법률 검토 전이에요.
- **하루 꾸미기 3회(커플당, 2026-10-27에 5회에서 줄임)**: **성공한 미리 보기마다 1번** 세요(거절·실패는 세지 않아요 · 2026-11-10 오너 확인). **남은 횟수는 꾸미기 독의 결과 요약 아래에 "오늘 n번 남음"으로 보여요**(2026-11-10 오너 결정 · 예전에는 카운터를 두지 않았어요). 경고가 있는 결과는 같은 줄 뒤에 붙여요. 세 번째 결과에서는 "오늘 마지막 미리 보기예요" + 다시 만들기 잠김 + "더 만들기는 내일부터 · 이 미리 보기는 적용할 수 있어요"(S08-quota-last). 다 쓰면 입력창이 "오늘은 다 썼어요 · 내일 다시 꾸밀 수 있어요"로 잠기고 "자세히"가 규칙 전문을 열어요(S08-quota). 거절·실패 안내는 "횟수는 그대로예요"를 같이 말해요. 초기화는 방 시간대 자정이에요.

## 15. 공간 종료는 소프트 삭제 · 복구 기능 없음 (2026-10-27 · 가정)

소유자의 결정("복구 기능은 빼고 소프트 삭제만, UI에서는 알리지 않고 내부적으로 30일 뒤에 지움")을 해석해 반영했어요. 각 해석은 가정이고 고칠 수 있어요.

- **복구 기능이 없어요**: 종료·연결 끊기 뒤에는 되돌리는 화면·버튼·설정·문구가 없어요. 서버는 공간을 **소프트 삭제**(상태만 `ended`)하고 내부적으로 일정 기간 뒤 **완전히 삭제**해요. 이용자 화면 어디에도 **기간(며칠)이나 복구 방법을 쓰지 않아요**. 개인정보 처리방침·스토어 데이터 안전 양식에 실제 동작을 쓰는 문제는 법률 검토 항목이에요.
- **종료 즉시**: 두 사람 모두 방·대화·사진·장식·마일스톤에 접근할 수 없어요(서버 호출 전부가 종료된 공간을 "없는 공간"으로 취급). 예약된 마일스톤 알림은 취소돼요.
- **종료 안내(S14)**: 종료한 사람은 "공간을 종료했어요 · 함께 쓰던 데이터는 삭제돼요. 새 공간을 시작할 수 있어요", 상대는 "{이름}님이 공간을 종료했어요"(또는 연결을 끊었다면 "{이름}님이 연결을 끊었어요") + 같은 본문을 앱을 열 때 한 번 봐요. 버튼은 **"새 공간 시작하기"** 하나(공간 만들기 S03 또는 초대 코드 S05로)이고, 확인하면 안내가 사라져요(서버의 종료 알림 확인 호출). 날짜·남은 일수·진행 막대·복구 버튼·만료 화면은 없어요.
- **한 공간만(활성 공간만 셈)**: 종료한 공간은 소프트 삭제라 안 세어요. 종료 직후 바로 새 공간을 만들거나 초대를 수락할 수 있어요.
- **사진·장식**: 홈 커버 사진과 생성 장식은 종료 즉시 읽을 수 없고, 파일은 완전 삭제 때 지워져요.
- **계정 삭제**: 스펙에 계정 삭제 기능이 없어요(스토어 규칙상 필요, 열린 항목). 가정: 계정을 지우면 그 사람의 활성 공간이 같은 방식으로 종료돼요(상대에게는 "공간을 종료했어요").
- **문구 변경(26)**: 종료 확인 `end.body`·`end.b2`·`end.b3`, 종료 안내 `end.done.body`, 설정 `set.end.help`, 연결 끊기 확인 `report.block.body`에서 기간·날짜·복구를 지웠고, 복구 관련 키 16개(`end.restore*`·`end.expired*`·`end.left`·`end.date`·`end.onlyDisconnector`·`end.newSpace.note`)는 없앴어요. S14의 복구 확인·진행·성공·실패·막힘·만료 상태 6개와 남은 일수 막대도 없앴어요. (앞서 2026-10-27에 "가정"으로 넣었던 복구 규칙 — 복구 대기 중 새 공간 · 복구 막힘 · 연결 끊기는 끊은 사람만 복구 — 은 이 결정으로 **대체되어 무효**예요.)

## 16. 생성 장식(배경·말풍선·방 소품)과 신고 (US8·US9 · P2 · 2026-10-27 가정)

소유자의 "프롬프트로 새 오브젝트가 만들어지고 모든 커플의 방이 달랐으면"을 새 벡터 오브젝트를 기준 라이브러리 기반으로 생성해 커플별로 저장하는 안으로 해석했어요. 모든 해석은 가정이에요. MVP(카탈로그 오브젝트로 꾸미기)에는 들어가지 않고 **바로 다음 단계(P2)**예요.

- **만들 수 있는 것**: 방 **배경 조각**(벽·바닥·배경 띠·창밖 풍경), **말풍선 틀**, **방 소품**(바닥·벽·선반에 두는 작은 물건). 마스코트는 어떤 프롬프트로도 바뀌지 않고, 마스코트·앱 캐릭터를 닮은 소품이나 글자·로고·브랜드가 있는 소품은 거절해요. 모든 생성물은 기준 라이브러리(`reference-library/`)의 그림체(평면 채움 + 갈색 윤곽 + 크림 림)를 따라요.
- **만들기 흐름(S08 → S09)**: 프롬프트 입력 → ① 거절(범주별 `gen.refuse.*`: 이유 + 허용되는 대안 하나 + "이번 요청은 오늘 횟수에 들어가지 않았어요", 입력한 글은 그대로 남고 "다시 말해 보기"), ② 만들지 못함(`gen.fail.*`, 방은 그대로, 횟수 안 씀), ③ 킬 스위치로 생성 중단(`gen.disabled.*`: 입력칸이 잠기지만 다른 꾸미기는 계속), ④ 보관함 가득(`gen.lib.full`: 모델을 부르기 전에 막음) → 성공하면 미리 보기(S09)에 **"새로 만든 장식 N개"**(`gen.badge`·`gen.preview.count`, AI 배지가 아니라 기능 설명)와 장식 수(요약 아래 한 줄) → 적용하기 한 번 → 방. 점유·방 위 미리 보기·닫기·적용 직후 되돌리기는 꾸미기와 같아요(§4). **하루 3번은 성공한 미리 보기만** 세요.
- **방의 장식 상세(S07)**: 방에서 생성 장식을 누르면 아래 시트가 올라와요 — 이름·종류(배경 장식 / 말풍선 틀 / 방 소품)·만든 사람·**신고하기**·**방 전체 신고**·(신고했다면) "신고했어요 · 접수됨" 또는 "검토를 마쳤어요"·"내 화면에서만 숨겼어요". 눌릴 수 있는 장식은 접근성 이름(`a11y.gen.open`)과 44pt 이상의 터치 영역을 가져요. 카탈로그 오브젝트와 마스코트는 지금처럼 터치를 받지 않아요.
- **우리 장식 보관함(S08 안의 시트)**: 프롬프트 화면에서 열어 목록(썸네일·이름·만든 사람, `n/상한`)을 보고 **다시 쓰기**(프롬프트에 "‘이름’ 놓기" 칩이 들어가요)나 **지우기**를 해요. 상한은 서버 설정값(기본 40, 가정)이라 숫자는 앱에 박혀 있지 않아요. **방에 놓인 장식도 지울 수 있고**(확인 창이 "방에서도 사라져요"를 알려요) 지우면 방 버전은 바뀌지 않고 읽을 때 걸러져 두 사람 화면에서 사라져요.
- **신고(S15)**: 사유 4가지(저작권을 닮음 / 불쾌하거나 성적·폭력적 / 개인정보 / 기타) → 선택 메모(상대에게 안 보임) → 보내기 → 접수 화면("이 장식은 내 화면에서 숨겼어요 …"). 실패하면 입력이 남고, 하루 10건을 넘으면 안내해요. 신고하면 신고자 화면에서 **즉시 숨겨지고**(상대는 운영 검토 전까지 그대로) 운영자가 수동으로 검토해 방에서 빼면 두 사람 화면에서 사라지고 같은 요청의 재생성이 막혀요(두 사람은 "검토 결과 이 장식은 방에서 빠졌어요"를 한 번 봐요). **홈 커버 사진은 신고 대상이 아니에요**(업로드된 사진, 결정). 연결 끊기와는 별개예요.
- **모션**: 새 장식이 나타나는 별도 효과는 없어요(정지). 동작 줄이기와 큰 글자에서도 읽혀요.
- **새 문구**: `gen.*`(거절 9·실패 2·중단 2·표시 2·보관함 13) · `obj.*`(상세 9) · `report.obj.*`(14) · `a11y.gen.open` — ko/en/ja, 영어·일본어는 원어민 검수 전 초안이에요.

## 17. 계정 삭제 (US10 · P1 · 2026-10-27 · 모두 가정)

스토어 규칙(Apple 5.1.1(v), Google Play)이 앱 안 계정 삭제를 요구하고, 소유자가 V1에 넣기로 했어요. 비트윈·썸원을 참고했고 비교는 `specs/…/research.md` §10에 있어요.

- **진입**: 설정 > **위험 구역** > "계정 삭제"(`set.account.delete`, "되돌릴 수 없어요") — 로그아웃·공간 종료 아래에 같은 위험 행으로 있어요. 찾기 쉬워야 한다는 스토어 요구를 맞춰요.
- **흐름**: ① 결과 설명(`acct.delete.*`): 바로 로그아웃·되돌릴 수 없음 / 내 계정과 프로필이 삭제됨 / **함께 쓰는 공간이 있으면 종료됨(두 사람 모두 들어갈 수 없고 방·사진·장식이 삭제됨)** / 같은 계정으로 다시 가입해도 이전 내용은 돌아오지 않음 + "내용을 확인했어요" 체크(체크해야 버튼 활성) → ② **본인 확인**(시트: 카카오·Apple·이메일로 한 번 더 로그인, 5분 안에 로그인한 적이 있어야 함) → ③ 삭제하는 중(순환 로더) → ④ 끝나면 모든 기기에서 로그아웃되어 로그인 화면으로 가고 "계정을 삭제했어요"가 잠깐 보여요. **유예·복구는 없어요**(공간 종료와 같은 결정). 확인 단어 입력은 쓰지 않아요(재로그인이 안전장치).
- **실패·오프라인**: 인터넷이 없으면 요청을 보내지 않고 "인터넷에 연결되어야 계정을 삭제할 수 있어요"만 보여 줘요(대기열 없음). 요청이 거절되면 "아직 아무것도 지워지지 않았어요"와 다시 시도. 본인 확인 실패는 시트 안에서 안내.
- **상대에게**: 공간이 있었다면 상대는 앱을 열 때 **"상대가 계정을 삭제했어요"** + "함께 쓰던 데이터는 삭제돼요. 새 공간을 시작할 수 있어요"를 한 번 봐요(S14 `partner-deleted`). **이름과 사유를 넣지 않아요**(개인정보 최소화). 서버 푸시가 없어 앱을 열 때 보여요. 대안(원인을 말하지 않는 "공간이 종료됐어요")은 열린 질문이에요.
- **정리**: 삭제한 기기는 로컬 예약 알림을 모두 취소하고 캐시(공간·사진·장식)를 지워요. 다른 기기의 예약 알림은 그 기기가 다음에 앱을 열어 로그아웃된 것을 알 때 취소돼요(서버 푸시 없음 → 한계).
- **새 문구 17개**: `set.account.delete`(+`.sub`) · `acct.delete.title/lead/b1/b2/b3/confirm/reauth.title/reauth.body/reauth.fail/progress/done/offline/fail.title/fail.body` · `end.byPartnerDeleted`. 체크 문구는 `end.check`, 재로그인 화면은 `login.*`를 그대로 써요. 영어·일본어는 원어민 검수 전 초안.
- **상태(캔버스 S13)**: 설명(체크 전·후) · 본인 확인 시트(실패 포함) · 삭제 중 · 오프라인 · 실패 · 로그아웃 후 로그인 화면 + 안내. S14에는 `partner-deleted`. **화면 번호는 16개 그대로**예요.
