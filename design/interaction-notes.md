# interaction-notes.md — 상호작용 노트

화면 사이 이동, 키보드와 공유 시트, 미리 보기·확인·취소·되돌리기, 점유와 이어받기 시간, 오프라인·오류 동작, 두 사람 동기화가 눈에 보이는 방식을 정리했어요. 숫자는 `plan.md`의 가정(3분 idle 등)을 따르고, 디자인에서 새로 정한 값은 **(제안)** 으로 표시했어요.

## 1. 내비게이션 구조

```
앱 시작
 ├─ 로그인 안 됨 ─ S01 온보딩 ─ S02 로그인 ─ (공간 없음) S03 공간 생성 ─ S04 초대 코드
 │                                         └ (코드 있음) S05 코드 입력 ─ 참여
 ├─ 공간 종료됨 ─ S14 종료 화면(복구 기한·복구)  ※ 탭 구조 대신
 └─ 활성 공간 ─ [시스템 탭 바]
        ① 홈 ─ 홈 루트(S06)
        │        ├ 초대 코드 보기(푸시, 탭 바 숨김) → S04 코드 화면
        │        ├ 날짜 수정(시트)
        │        └ 우리 방 열기 → ② 방 탭으로 전환
        ② 방 ─ 방 루트(S07)
        │        ├ 꾸미기(모달 시트, 탭 바를 덮음) → S08 / S09
        │        └ 되돌리기(다이얼로그) → S10
        ③ 설정 ─ 설정 루트(S13)
                 ├ 언어 · 시간대(시트)
                 ├ AI 처리 동의 관리(푸시) / 동의 화면 S12(모달)
                 ├ 글꼴·오픈소스 라이선스(푸시)
                 ├ 문의 · 신고(푸시) → S15
                 └ 공간 종료(푸시) → S14 확인 → 종료 화면
```

### 1.1 탭을 이렇게 정한 이유 (제안)
- 홈 · 방 · 설정 3개. 스펙 범위(D-day, 꾸미는 방, 되돌리기, 설정)를 그대로 3개 목적지로 나눈 거예요.
- **기록 탭은 첫 버전에 없어요(후속 버전)**: 버전 목록과 이전 버전 복구는 뺐어요. 방 도구 막대의 기록 바로가기도 함께 없앴어요. 나중에 다시 넣을 때는 설정과 방 사이에 탭 하나로 추가하는 안을 쓸 수 있어요. 되돌리기는 기록 목록 없이 방 도구 막대에서 직전 적용만 되돌려요(연속 되돌리기 깊이와 다시 적용은 미정, `specs/001-couple-prompt-todo/spec.md` Open Decisions 8).

### 1.2 탭 바 표시 규칙
| 화면 종류 | 탭 바 |
|---|---|
| 탭 루트 3개 | 보임 |
| 푸시된 상세(라이선스 등) | 숨김 |
| 작업 흐름(공간 종료, 동의 관리, 신고·차단, 초대 코드) | 숨김 — 되돌리기 어렵거나 중요한 결정이라 다른 탭으로 새지 않게 |
| 시트·다이얼로그·꾸미기 패널 | 시트는 탭 바를 덮음(모달) |
| 탭 구조 앞의 흐름(S01~S05)과 종료 화면 | 없음 |

### 1.3 플랫폼 동작
- 각 탭은 자기 스택을 기억해요. **선택된 탭을 다시 누르면** 루트에서는 맨 위로 스크롤, 푸시된 화면에서는 루트로 돌아가요(iOS 관례, Android도 동일하게).
- 뒤로: iOS 왼쪽 가장자리 스와이프 + 뒤로 버튼. Android 시스템 뒤로(제스처·버튼): 푸시/시트/다이얼로그를 먼저 닫고, 탭 루트에서는 **홈 탭으로**, 홈 탭 루트에서는 앱 나가기.
- 딥링크(초대 코드 링크 등)는 이번 범위가 아니에요. 공유 문구에는 코드만 넣어요(`invite.shareMsg`).
- 탭 바에는 배지를 쓰지 않아요(알림 기능이 없고 "상대가 꾸미는 중"은 방 화면 안에서 보여요).

## 2. 시스템 컴포넌트 원칙 (탭 바 등)
탭 바는 **시스템이 소유하는 UI**예요(방 장면 밖). 구현은 네이티브 탭(iOS UITabBarController 기반, Android Material 3 NavigationBar)을 쓰고 직접 그린 막대를 쓰지 않아요. 재질(반투명 블러)·높이·아이콘 크기·글꼴·선택 애니메이션은 OS가 정하고, 앱은 **틴트색 · 비선택 틴트 · 라벨 문구 · 아이콘 이미지 · 배지**만 정해요. 탭 바는 **보호 영역**이라 방 장식이 가리거나 터치를 가로챌 수 없고, 보호 영역 계산에는 기기에서 측정한 실제 높이를 써요(글자 확대 시 Android는 높이가 늘어요).

## 3. 레이어 순서 (방 화면, 아래 → 위)
1. 방 배경(테마 에셋) → 2. 장면 캔버스(오브젝트·마스코트·장면 문구, 사용자가 정한 레이어 순서) → 3. **D-day 위젯**(네이티브) → 4. **방 도구 막대**(네이티브, 위쪽) → 5. **시스템 탭 바**(OS) → 6. 안내 배너·토스트 → 7. 모달(시트·다이얼로그, 스크림 포함).
장면 오브젝트는 3~5번 아래에 있고 터치를 받지 않아요(방은 프롬프트로 꾸미고 직접 끌지 않아요). 3~5번과 시스템 안전 영역이 보호 영역이라, 서버·클라이언트 검증이 장식 배치를 이 영역 밖으로 자동 이동시켜요(미리 보기에 안내: `preview.warn.protected`).

## 4. 꾸미기 흐름: 미리 보기 · 확인 · 취소 · 되돌리기

| 단계 | 점유자(나) | 상대 |
|---|---|---|
| 방 탭 → 꾸미기 | 패널이 열려요. 아무도 점유 안 했으면 **"내가 꾸밀게요"**로 점유를 시작해요(자동 점유 안 함 — 상대가 의도치 않게 막히지 않도록 (제안)) | 대화·미리 보기를 실시간 읽기 전용으로 봐요. 점유 칩 "{이름}님이 꾸미는 중" |
| 입력·제출 | 입력 → 보내기 → "만드는 중이에요"(입력 잠김) | 같은 대화에서 "쓰는 중…", "미리 보기를 만드는 중이에요"를 봐요 |
| 미리 보기 | 방 축소 보기에 후보가 보이고 배지 "미리 보기 · 아직 적용되지 않았어요". **현재 방 / 미리 보기** 전환. 적용 · 취소 | 같은 후보를 읽기 전용으로 봐요(적용·취소 비활성, "{이름}님이 적용할지 정하고 있어요") |
| 적용 | 서버 transaction(점유자 + 기대 버전 + 멱등 키) → 새 버전 → **점유 해제** → 방 탭으로 돌아가요(토스트/상태 칩) | 실시간이면 바로 방이 바뀌고, 앱이 닫혀 있었으면 열 때/동기화 때 바뀐 방을 봐요 |
| 취소 | 현재 방 유지, **점유 해제**, "취소했어요. 우리 방은 그대로예요." | 대화에 "{이름}님이 취소했어요" |
| 되돌리기 | 확인 다이얼로그 → 직전 적용 전 방으로 복구 → 성공 시 **점유 해제**. 버전 목록을 열지 않고 동작해요. 상대가 점유 중이면 막히고 이유 안내. 되돌린 뒤 다시 적용하는 기능은 없어요(열린 결정) | 방이 바뀐 모습을 봐요 |

- **버전 충돌**(두 기기의 동시 적용·늦은 재시도): 서버가 거부하면 "방이 방금 바뀌었어요 — 최신 방을 불러왔어요. 미리 보기를 다시 만들어 주세요"로 안전하게 끝나요(방은 한 번만 바뀜).
- **마스코트 꾸미기는 없어요**(`handoff.md` §11). 마스코트는 고정 캐릭터이고, 프롬프트가 모습을 바꾸라고 하면 거절 안내(`prompt.brand.*`)로 방 오브젝트 꾸미기를 권해요.

## 5. 점유와 이어받기 (시간은 `plan.md` 가정 · 캡틴이 조정 가능)

| 항목 | 값 | 화면에서 |
|---|---|---|
| idle 만료 | **3분**(가정): 의미 있는 편집·제출·모델 생성 중에는 서버 시간 기준으로 연장 | 입력칸 아래 "3분 동안 아무것도 하지 않으면 자동으로 풀려요." |
| 앱이 백그라운드/종료 | heartbeat가 멈춰 만료 시각에 풀림 | 상대 화면은 만료 후에 이어받기를 제안 |
| 만료 임박 알림 | 남은 시간 **30초**(제안) 부터 점유 칩에 `0:30` 카운트다운 + 배너 "{n}초 뒤에 풀려요 · 계속하기" | 계속하기 = 활동으로 간주해 연장 |
| 내 점유가 풀렸을 때 | 쓰던 글은 입력칸에 남아요(로컬 초안) | "꾸미기가 자동으로 풀렸어요 · 다시 꾸미기" |
| 상대가 이어받기 | 상대 점유가 **만료된 뒤에만** 가능. 서버가 `expectedOwnerUserId`와 만료 시각을 비교해 원자적으로 owner 변경 | "{이름}님이 자리를 비웠어요 · 이어서 꾸미기". 이전 대화와 미리 보기가 그대로 이어져요 |
| 이어받기 경합 | 둘이 동시에 누르면 한 명만 성공 | 진 쪽에 "{이름}님이 먼저 이어받았어요" 토스트, 화면은 읽기 전용으로 |
| 해제 이벤트 | 확정·취소·되돌리기 성공, idle 만료 | 점유 칩이 "지금은 아무도 꾸미고 있지 않아요"로 |

숫자(3분, 30초 경고)는 코드에 상수로 두지 말고 서버 설정으로 받아요(캡틴이 조정할 수 있다고 `plan.md`에 있어요).

## 6. 키보드와 공유 시트
- **키보드(꾸미기 입력)**: 입력칸을 누르면 패널이 키보드 위로 올라가고 방 축소 보기는 얇은 띠(약 110)로 줄어요. 키보드는 모달 패널 안에서만 열리므로 도구 막대·탭 바와 겹치지 않아요. 보내기는 키보드 위 원 버튼, 키보드의 완료/줄바꿈 키는 줄바꿈(제출은 보내기 버튼으로만 — 의도치 않은 제출 방지 (제안)).
- **날짜 입력**: 키보드가 아니라 3열 휠 시트(년·월·일).
- **초대 코드 입력**: 영문 대문자 + 숫자 키보드, 자동 대문자, 붙여넣기 버튼(`join.paste`), 8자가 차면 자동으로 확인 버튼 활성.
- **공유 시트(초대 코드)**: "코드 공유하기" → OS 공유 시트(iOS 시트 / Android 공유 시트)에 문구 `invite.shareMsg`("... 초대 코드: {code} (24시간 안에 입력해 주세요)")를 넘겨요. 시트를 닫으면 코드 화면 그대로(공유 취소 안내 `invite.shareCancelled`). "코드 복사"는 클립보드에 코드만 복사하고 "복사했어요" 토스트.
- **재발급**: 새 코드를 만들면 이전 미사용 코드는 즉시 폐기돼요. 확인 다이얼로그에서 이 점을 먼저 알려요.

## 7. D-day 위젯의 이동·숨김
- 위젯의 위치·모양·색·크기는 **프롬프트로만** 바꿔요(방에서 직접 끌지 않아요). 이동은 보호 영역 밖에서만 허용되고, 이동 결과가 가리면 서버/클라이언트 검증이 자동으로 옮겨요.
- 위젯을 숨기면 방에는 안내 배너(`room.ddayHidden`)가 보이고, 홈 탭의 D-day는 그대로예요.
- 글자 확대 시 위젯은 같이 커지고(자동 축소 없음) 보호 영역이 다시 계산돼요. 최대 폭을 넘으면 줄바꿈.

## 8. 오프라인 · 오류 · 재시도

| 상황 | 동작 |
|---|---|
| 오프라인 | 마지막 확정 방·D-day를 읽기 전용으로 보여요. 방 탭: 되돌리기·꾸미기 비활성, 배너 "인터넷이 끊겨서 보기만 할 수 있어요". 꾸미기 패널은 열 수 있지만 입력칸 비활성("인터넷에 연결되어야 꾸밀 수 있어요"). **오프라인 편집·미리 보기 적용은 없어요.** |
| 동기화 실패 | 마지막 저장본을 보여 주고 배너(다시 시도). 자동 재시도는 연결이 돌아올 때 한 번, 이후 사용자 요청. |
| 동기화 대기 | 연결되면 최신으로. 대기 중 표시 배너(`sys.pending.*`) |
| 서버/AI 일시 장애 | 꾸미기만 막고(`sys.ai.*`) D-day·방 보기는 유지. 방은 안 바뀌었다고 말해요. |
| 로그인 만료 | 전체 화면 안내 + 다시 로그인(`sys.login.*`). 입력하던 프롬프트는 로컬 초안으로 보존. |
| 접근 거부(구성원 아님·종료) | 전체 화면 안내 + 코드가 있으면 입력 / 새 공간 만들기 |
| 요청 한도(하루 10회) | 입력칸 잠김 + 안내(방은 그대로, 내일 이어서). 한도는 남용 방지용이라 가격 문구를 쓰지 않아요. |
| 구버전 장면 | 읽을 수 있는 부분만 보여 주고 "앱 업데이트" 안내(`sys.old.*`) |
| 삭제된 에셋 | 빈 자리를 점선 상자로 두고 안내, 연결이 좋아지면 자동으로 다시 불러와요 |
| 장면 데이터 읽기 오류 | 방 위에 "저장된 방은 그대로 있어요" 안내 + "다시 불러오기"(`room.recover.*`). 이전에는 기록 탭의 복구로 이어졌지만 기록을 뺐어요 |
| 버튼 중복 탭 | 제출·적용·되돌리기는 진행 중 비활성(로딩 상태)이고 서버는 멱등 키로 이중 처리를 막아요 |

## 9. 두 파트너의 동기화가 눈에 보이는 방식
- 점유 칩(누가 꾸미는 중인지, 남은 시간), 대화의 "쓰는 중…/만드는 중", 같은 미리 보기, 시스템 상태 칩(적용했어요·취소했어요·꾸미기가 풀렸어요)으로 보여요.
- 상대가 방을 바꿨을 때(내가 방 탭을 보고 있는 중): 장면이 바로 바뀌고 토스트 "{이름}님이 방을 바꿨어요".
- 알림은 없어요. 앱을 열거나 동기화될 때 최신 상태를 봐요(스펙).

## 10. 접근성 상호작용
- **스크린 리더**: 읽기 순서 = 도구 막대(되돌리기 → 꾸미기) → D-day 위젯 → 마스코트 → 시스템 탭 바. 장식 소품은 건너뛰어요. 상태 변화는 한 번만 알려요(점유 변경, 미리 보기 생성, 적용, 오류).
- **큰 글자**: 줄바꿈과 스크롤로 받고 자동 축소 없음. 방 도구 막대 라벨은 160%에서 멈추고 긴 누름/탭 시 라벨 풍선 제공. iOS 탭 바는 시스템의 큰 글자 보기를 써요.
- **동작 줄이기**: 화면 전환 애니메이션 없음. 떠다니는 편지(§10.1)도 멈춘 채로 그려요.
- **고대비**: 윤곽선 3px, 글자·컨트롤 색을 더 진하게. 에셋 그림은 그대로.
- **터치**: 최소 48 × 48. 긴 누름에만 있는 동작은 없어요(모든 동작에 명확한 탭 동작).

### 10.1 떠다니는 편지 (S04 상대 대기 화면)
- 대상: S04 **상대 참여 대기** 화면의 편지 일러스트(스팟) 하나. 편지 오브젝트만 움직이고 구름·반짝임은 가만히 있어요(제안: 움직이는 요소를 하나로 제한).
- 움직임: 제자리에서 위로 6pt 올랐다가 내려오는 왕복, 3.2초, ease-in-out, 무한 반복. 회전·크기 변화 없음.
- **밝은 화면과 어두운 화면에서 똑같이** 적용해요. 색이 아니라 위치만 바꾸는 움직임이라 모드별로 다른 값이 없어요. 캔버스의 S04 밝은 앱·어두운 앱 두 프레임에 모두 들어 있어요.
- 동작 줄이기(웹 `prefers-reduced-motion`, iOS '동작 줄이기', Android '애니메이션 제거')가 켜져 있으면 정지한 채 보여 줘요.
- 장식이라 읽기 순서에서 제외(`aria-hidden`)하고, 상태 안내는 제목·본문 글자가 맡아요. 정적 PNG 내보내기에는 움직임이 담기지 않아요.
- 다른 화면의 편지 스팟(온보딩 재실행, 로그인 처리, 신고 완료)은 그대로 정적이에요. 같은 움직임을 쓰고 싶으면 알려 주세요(제안).

### 10.2 오브젝트 순환 로더 (전역 기본 로딩 표시)
- 쓰는 곳: 전체 화면을 차지하는 로딩(S03 공간 생성 중, S02 로그인 처리 중·로그인 화면으로 이동 중). 버튼 안의 작은 로딩과 목록·카드의 자리 표시(스켈레톤)는 기존 그대로예요.
- 모양: 화분 → 풍선 → 창문 → 책 순서로 오브젝트가 하나씩 커지며 나타났다가 작아지며 사라져요. 한 바퀴 4.8초, 오브젝트마다 1.2초 간격, 항상 한 개만 보여요. 아래에 문구("공간을 만들고 있어요" 등)를 붙이고 스피너는 따로 두지 않아요.
- 밝은 앱·어두운 앱 모두 같은 그림·같은 움직임이에요. 동작 줄이기가 켜져 있으면 첫 오브젝트(화분)가 멈춘 채로 보여요.
- 읽기: 그림은 읽지 않고(`aria-hidden`) 문구만 상태로 한 번 알려요.
- 창문은 아직 카탈로그에 없는 임시 스케치예요(`obj_decor_window`로 그릴 것).

## 11. 방 안을 돌아다니는 마스코트 (S07 · S24 전체 크기 방)
- 마스코트는 방 장면의 기본 오브젝트이면서 가만히 서 있지 않고 **40초 한 바퀴**로 행동을 번갈아 해요. 방 안 포즈 6종과 좌우 반전만 써서 새 그림이 필요 없어요(포즈 이름은 `design/mascot/` 기준).
- 순서(제안): 인사(`wave_main`) 2초 → 오른쪽으로 걷기(`walk` 반전) 4초 → 신나게 인사(`cheer`) 2.4초 → 왼쪽 끝까지 걷기 6.4초 → 올려다보기(`lookup`) 2.4초 → 엎드려 쉬기(`lie`) 3.2초 → 잠자기(`sleep`) 5.6초 → 올려다보기 2초 → 가운데로 걷기 4.8초 → 인사 2.4초 → 둘러보기(`lookup`) 4.8초 → 처음으로.
- 이동 범위는 화면 너비의 ±27% 안쪽 바닥 위(소품 앞으로 지나가요). 걷는 동안만 4pt씩 위아래로 통통 튀어요. 걷기는 왼쪽을 보고 있는 `walk` 포즈를 쓰고 오른쪽으로 갈 때는 좌우를 뒤집어요.
- **탭 반응**: 마스코트를 누르면 1.2초 동안 신나게 인사(`cheer`)를 하고 하던 행동으로 돌아가요(캔버스에서는 누르고 있는 동안만 보여요). 터치 영역은 마스코트 그림 전체예요.
- 상태별 규칙: 읽기 전용(오프라인)에서도 걷기는 계속해도 되지만(장식), 꾸미기 미리 보기·되돌리기 확인 중에는 **멈춰요**(제안: 방이 바뀌는 순간에 시선이 분산되지 않게). 로딩·복구 오류·보호 영역 표시 화면에는 마스코트가 나오지 않거나 정지 상태예요. 축소 보기(방 카드, 프롬프트 위 방 축소)는 늘 정지 포즈예요.
- 낮·밤 방, 밝은·어두운 앱에서 같은 순서예요. 밤 방에서는 잠자기 구간을 늘려도 좋아요(제안).
- 동작 줄이기가 켜져 있으면 걷지 않고 `wave_main` 한 장으로 서 있어요. 스크린 리더는 "마스코트, 인사하고 있어요"처럼 **현재 포즈를 한 번만** 알려요(행동이 바뀔 때마다 읽지 않아요).
- 더 자연스럽게 하려면 포즈별 프레임이 필요해요: 걷기 4~6장(다리·팔 교차), 자는 숨 2장(몸이 살짝 부풀었다 가라앉기), 엎드려 늘어짐 2장. 필요하면 소유자가 따로 제공(지금은 정지 이미지 6장으로 흉내).

## 12. 홈 상단 배경 사진 (S06 · S23 · 설정)
- **무엇인가**: 홈 화면 맨 위 커버는 두 사람이 올린 사진이 채워요. 에셋 일러스트·마스코트를 넣지 않아요. 사진이 없으면 앱 바탕색(종이색)이고 글자는 어두운 색이에요.
- **누가 보나**: 공간의 두 사람이 같은 사진을 봐요. 어느 쪽이든 바꾸거나 없앨 수 있고 마지막으로 바꾼 쪽이 이겨요(제안). 공간이 끝나면 사진도 함께 지워요(`end` 화면 문구에 반영 필요).
- **들어가는 길**: ① 홈 커버의 "사진 추가"(없을 때) 또는 사진 아이콘 버튼(있을 때) ② 설정 > 공간의 "홈 배경 사진" 행. 둘 다 같은 시트(앨범에서 고르기 · 사진 없애기 · 취소)를 열어요.
- **올리는 흐름**: 시트 → **시스템 사진 선택기**(사진 접근 권한 요청 없음) → 자르기 화면(커버 비율 고정, 끌어서 옮기고 두 손가락으로 확대, 3×3 격자) → 완료 → 커버에서 "사진을 올리고 있어요" → 성공 토스트 "배경 사진을 바꿨어요".
- **실패**: 올리기 실패는 기존 사진을 유지하고 커버 아래 오류 배너 + 다시 시도, 사진 불러오기 실패는 종이색으로 대체 + 경고 배너 + 다시 시도, 형식·크기 오류(JPG·PNG·HEIC, 20MB 이하)는 알림창. 오프라인에서는 마지막으로 받은 사진을 보여 주고 바꾸기만 막아요(제안).
- **글자 읽기**: 사진 위 글자는 흰색 + 아래쪽 어두운 막(#201610, 64%)으로 가장 밝은 사진에서도 4.5:1 이상(5.33)이에요. 맨 위에는 상태 표시줄 글자를 위한 크림 베일(55%)을 덮어요. 앱 이름·사진 버튼은 사진 위에 직접 놓지 않고 앱 면 알약 위에 놓아요(`contrast-report.md` 홈 커버).
- **접근성**: 사진은 "우리가 올린 배경 사진"으로 읽고(대체 텍스트를 사용자가 입력하게 할지는 열린 질문), 사진이 바뀌어도 글자 크기·위치는 변하지 않아요. 200% 글자에서는 커버가 글자 높이만큼 늘어나고 막도 같이 늘어나요. 고대비에서는 알약 윤곽선만 진해져요.
- **다른 화면**: 홈 탭(S23)은 같은 커버를 써요. 그 밖의 화면은 위쪽에 에셋을 쓰지 않아요. 방 화면의 날짜 위젯 배경은 방 색이고 사진을 쓰지 않아요(사진은 홈 전용, 제안).
- **미정**: 부적절한 사진 검수·신고(S15 신고 대상에 사진을 넣을지), 사진 보관 기간, 원본 보관 여부, 해상도(@3x 기준 1170px 너비 제안).
