# design/ — 시각 설계 인계 폴더 (방향 A · 손그림 따뜻함)

두 사람이 함께한 날을 세는 홈, 프롬프트로 꾸미는 방, 앱의 얼굴인 마스코트까지의 **완성된 시각·상호작용 설계**와 구현 인계 자료예요. 앱 코드는 없어요. 구현팀은 이 설계를 기준으로 화면 코드를 시작해요.

> 방향: 캡틴이 **A(손그림 따뜻함)** 를 최종으로 정했어요. 짙은 갈색 윤곽선, 오른쪽 아래로 어긋난 파스텔 채움, 그림자 없음, 크림 방, 손으로 그린 바닥선. 구조(화면·탭·상태·세 언어·점유·보호 영역·낮밤·다크 모드·고대비)는 그대로예요. 요약과 확인할 점은 [`handoff.md`](handoff.md)에 있어요.

## 화면 번호

브리프의 화면 1~16은 그대로 **S01~S16**이고, 17번 마일스톤 축하는 **S28**이에요. **C01~C07 캐릭터 섹션**(마스코트, C06은 앱 아이콘, C07은 벡터 버전) · S11(기록)은 첫 버전에서 뺌 · S17은 비어 있음 · S18 에셋 · S19 글꼴·토큰 · S20 접근성 · S21 긴 문구 · S22 컴포넌트 · **S23 홈 탭 · S24 방 탭 · S26 설정 탭**(S25 기록 탭은 뺌, 탭마다 첫 실행·비어 있음·보통·긴 문구·오프라인·오류) · **S27 탭 구조와 이동** · **S28 마일스톤 축하**.

## 이렇게 쓰세요

1. `handoff.md`를 읽고 결정이 필요한 항목(§4, §5)을 정리해요. 구현은 `specs/001-couple-prompt-todo/tasks.md`(구현 태스크 목록)대로 시작해요.
2. `tokens.json`을 디자인 토큰으로 옮기고 `node design/tools/contrast-check.mjs`를 CI에 걸어요(토큰을 바꾸면 대비가 깨지는지 바로 알 수 있어요).
3. 화면은 `screens.md`의 상태 ID(예: `S07-decorated`)를 `exports/`·`canvas/`의 같은 이름 프레임과 대조하며 구현해요. 문구는 `i18n-copy.md`의 키만 쓰세요.
4. 에셋은 `assets-spec.md`와 `assets-manifest.csv`를 의뢰서에 첨부해서 일러스트레이터에게 보내요. 스케치(`assets-sketch/`)는 비율과 배치의 기준이고 최종 그림이 아니에요.

## 꼭 알아둘 것

- **하단 탭 바는 시스템 컴포넌트**예요(iOS UITabBar · Android Material 3). 직접 그리지 말고 틴트·라벨·아이콘만 정해요. 방 화면의 **방 도구 막대**(꾸미기 하나)는 방 화면 자신의 막대예요.
- 캔버스 그림은 **헤드리스 Chrome으로 렌더해 확인**했어요. 실기기·스크린 리더·시스템 탭 바의 실제 모습은 아직 확인하지 못했어요(`handoff.md` §8).
- 앱 이름은 **모피루(Mopiru)**, 캐릭터 이름은 **모피(Mopi)**, 슬로건은 **"Our little world, together."** 로 정해졌어요(일본어 표기 モピル·モピ까지 소유자 승인, 상표·스토어 이름·도메인·bundle ID·운영 주체는 확인 전, `handoff.md` §16). 일반 오브젝트 그림과 지원 이메일 `[지원 이메일]`은 **자리표시**예요. **마스코트 그림은 소유자가 생성형 AI 도구로 만든 마스터를 그대로 쓰기로 한 것이고(재작업 없음, 약한 저작권 보호 위험 수용), 닮음 검사·법률 검토는 출시 전 권장이에요**(`handoff.md` §10.4). **마스코트는 앱이 제공하는 고정 캐릭터이고 이용자가 꾸미지 않아요**(꾸미기는 첫 버전 범위 밖, `handoff.md` §11). **마스코트는 화면 곳곳에 뿌리지 않아요**: 방 장면의 기본 오브젝트와 온보딩 히어로 1개에만 나오고, 나머지는 오브젝트 스케치로 만든 작은 일러스트예요. 캐릭터 자체는 캔버스 **캐릭터 섹션(C01~C05)** 에서 봐요.
- 글꼴은 미리 보기에서만 Google Fonts를 불러와요. 실제 앱은 파일을 번들하고 원격 글꼴을 쓰지 않아요(라이선스 표기는 `tokens.json`의 `typography.fonts`와 캔버스 S19).
