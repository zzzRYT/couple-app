# design/mascot/vector — 아루미(Aroomi) 벡터 버전

방향 A로 다듬은 마스코트 래스터(`../harmonized/mascot_{pose}@3x.png`, 11포즈)를 **VectorCraft의 이미지 트레이스로 자동 변환한 SVG**예요. **다시 그리거나 손보지 않았어요.** 캐릭터의 모양·색은 래스터 그대로이고, 점(픽셀)으로 된 그림을 선과 면(패스)으로 바꾼 거예요.

## 출처와 권리

- 이 벡터는 **소유자가 생성형 AI 대화 도구로 만든 마스코트 마스터**(`../source/`)에서 파생됐어요. 권리 상태는 마스코트와 같아요: 마스터를 **그대로 쓰기로 했고**(일러스트레이터 재작업 없음), 약한 저작권 보호 위험은 소유자가 받아들였고, 닮음 검사·법률 검토는 출시 전 권장이에요(출시를 막지 않아요). 자세한 내용은 `../../handoff.md` §10.4, `../../assets-spec.md` §8.1.
- 벡터로 바꿨다고 권리 상태가 좋아지지는 않아요. 자동 트레이스라서 사람이 새로 그린 창작이 아니에요(그림이 새로 만들어진 것이 아니라 같은 그림의 다른 표현 형식이에요).
- 앱 이름 "아룸"의 상표·스토어 이름 확인은 아직이에요(`../../handoff.md` §16).

## 어떤 설정으로 했나 (재현)

```
vectorcraft-cli run --in design/mascot/harmonized/mascot_{pose}@3x.png \
  --cmd select.all \
  --cmd imageTrace.makeAndExpand --params '{"preset":"16 Colors"}' \
  --export mascot_{pose}.svg
```

같은 작업을 한 번에 다시 하는 스크립트: `design/tools/vectorize-mascot.py`(CLI 경로는 `--cli`, 환경 변수 `VECTORCRAFT_CLI`도 돼요). 파일을 다시 만들고, 아래 점검을 돌리고, 미리 보기 시트를 새로 그려요. `--check-only`는 이미 있는 파일만 점검해요(리포트를 덮어쓰지 않아요). 필요한 것: Python 3.9+, Pillow, NumPy, `resvg-py`(`pip install pillow numpy resvg-py`). SVG는 다시 돌려도 바이트까지 같아요(해시 확인). PDF·.ai는 파일 생성 시각이 들어가 바이트가 달라지지만 내용은 같아요.

### 프리셋을 어떻게 골랐나 (주 포즈 `wave_main`, 래스터와 겹쳐 비교)

가공본은 **불투명 영역이 14색뿐인 납작한 색 그림에 굵은 갈색 윤곽선**이라 "색 수가 적은 색 모드" 프리셋이 맞아요. 흑백·그레이 프리셋은 색을 잃어서 제외했어요.

| 프리셋 | 패스 | 색 | 크기 | 평균 색 차이(0~255) | 많이 틀린 픽셀 | 눈으로 본 결과 |
|---|---|---|---|---|---|---|
| 6 Colors | 23 | 6 | 249 KB | 2.78 | 0.91% | **볼터치가 살구색으로 바뀌고 눈 하이라이트가 사라져요 → 탈락** |
| Flat Logo | 165 | 10 | 192 KB | 1.27 | 0.33% | 이미지를 725px로 줄여서 따라 그려요. 눈 색이 갈색으로 바뀌고 하이라이트 손실, 점 잡티 → 탈락 |
| Auto Color | 49 | 14 | 158 KB | 0.49 | 0.37% | 좋음. 하지만 다른 포즈에서 별 핀 하이라이트(`#ffe4a6`) 등 작은 색 3개를 잃어요(`cheer`) |
| **16 Colors (선택)** | **44** | **14** | **182 KB** | **0.47** | **0.36%** | 가장 충실. 래스터에 있는 색이 한 개도 합쳐지지 않아요(최대 16색 > 14색) |
| Auto Color + 정밀도 90·모서리 50·잡티 4 | 50 | 14 | 316 KB | 0.43 | 0.33% | 수치는 비슷하지만 윤곽이 래스터의 계단 자국을 그대로 따라 울퉁불퉁하고 파일이 1.7배 → 탈락 |
| 색 14개 제한 + 정밀도 85 | 45 | 14 | 277 KB | 0.44 | 0.33% | 16 Colors와 거의 같은데 파일만 큼 → 탈락 |

"평균 색 차이"는 같은 크기로 그려(resvg) 래스터와 겹쳤을 때 둘 중 하나라도 그림이 있는 픽셀의 색 차이 평균이고, "많이 틀린 픽셀"은 그중 차이가 48/255를 넘는 비율이에요. 모두 윤곽선 가장자리의 1~2픽셀이었어요(차이를 그린 그림으로 확인).

## 점검 결과 (모두 통과)

`design/tools/vectorize-mascot.py`가 자동으로 확인하고, 아래는 따로 확인한 값이에요.

- **SVG가 진짜 벡터인가**: 13개 SVG 모두 `<image>`·`<script>`·`<style>`·`<use>`·`<filter>`·`<mask>`·`<clipPath>`·`<pattern>`이 없고, `href`·`url(`·`data:`·이벤트 속성·외부 주소가 없어요(네임스페이스 선언만). 패스만 있고 `viewBox`가 있어요. PDF 3개와 .ai 2개는 `pdfimages`로 삽입된 이미지가 0개임을 확인했어요.
- **다른 렌더러로 그려 봤나**: SVG를 **resvg**(Rust, 다른 코드베이스)와 **Google Chrome(헤드리스)** 으로, PDF를 **poppler**로 그려서 래스터와 겹쳤어요. 세 렌더러 모두 비어 있지 않게 그려지고 래스터와 일치해요(주 포즈 평균 색 차이: resvg 0.47(종이색 바탕) · Chrome 0.69 · PDF/poppler 0.62(둘은 흰 바탕), 나머지 10포즈의 Chrome은 1.7~2.1). 아이콘 B(탈락 후보)는 Chrome 0.94 · PDF 0.91로 아이콘 PNG와 겹쳤고, 선택안 A는 resvg로 1.15였어요(Chrome·PDF 렌더는 B만 따로 재 봤어요).
- **색**: 모든 SVG의 채우기 색이 `tokens.json` 마스코트 팔레트(`sampledPalette`의 가공 톤 + 윤곽 `#4A3426`·림 `#FFF4DF`) 안에 있어요. **새로 생긴 색은 0개**예요. 래스터에 있던 색 중 사라진 것은 `cheer`의 `#f0a650`(전체의 0.001%, 몇 픽셀)과 `phone`의 `#7081dc`(0.005%)뿐이에요.
- **실루엣**: 래스터와 SVG 윤곽의 겹침(IoU) 0.9988~0.9996.

## 품질 평가 (솔직히)

- **쓸 만해요**: 주 포즈와 나머지 포즈 모두 눈·입·볼터치·어깨띠·별 핀·윤곽선이 래스터와 눈으로 구분되지 않아요(얼굴 2배 확대, 별 핀·하트·휴대폰·어깨띠 매듭 확대까지 확인). 큰 크기(1024px, 확대)에서 래스터는 계단 모양이 보이지만 벡터는 매끈해요. 이것이 벡터로 바꾼 가장 큰 이득이에요.
- **래스터와 다른 점**: 래스터의 크림 림 바깥에 있던 얇은 회색 가장자리 선(안티앨리어싱 잔재)이 벡터에는 없어요. 경계가 약간 부드러워져서 원본 픽셀과 똑같지는 않아요.
- **한계**: 아래 "한계"를 보세요. 사람이 손으로 정리한 일러스트가 아니라서 앵커 수가 많고(주 포즈 3,623개) 점 배치가 고르지 않아요. 일러스트레이터가 편집하기에는 무겁고, 선 굵기를 바꾸는 것 같은 구조적 수정은 어려워요. 제작용 최종본이 필요하면 일러스트레이터가 이 SVG를 밑그림으로 다시 그리는 것이 맞아요(그때도 마스터는 그대로 쓰기로 한 결정이 유지돼요).

## 한계

- **자동 트레이스예요, 손으로 다시 그린 것이 아니에요.** 윤곽선은 칠한 면(채워진 모양)이지 굵기를 가진 선(stroke)이 아니에요. 선 굵기·붓 느낌을 바꾸려면 다시 그려야 해요.
- **`.ai`**: 만든 `.ai`는 PDF 호환 형식이고 **Illustrator에서 열어 보지 않았어요**. SVG·PDF는 Illustrator에서 열리는 표준 형식이에요(이것도 Illustrator에서 열어 보지는 못했어요).
- **레이어·이름**: 포즈마다 레이어(그룹) 하나 `aroomi-{pose}`, 그 안에 같은 색이 이어지는 패스를 묶은 그룹 `aroomi-{pose}-{역할}-{색}`(예: `aroomi-wave_main-outline-4a3426`, `…-cheek-f2a99b`, `…-sash-3-3f4e9e`)이에요. 몸·얼굴·팔 같은 **신체 부위별 구조는 아니에요**(색이 같은 면끼리 묶임). 모든 패스는 `fill`만 있어요.
- **Figma / Illustrator에서 열기**: Figma는 SVG를 끌어다 놓거나 `Place`로 가져오면 그룹 이름이 레이어 이름으로 보이고, Illustrator는 `파일 › 열기`로 SVG를 열어요. **둘 다 실제로 열어 보지는 못했어요.** 열었을 때 이름이 다르게 보이면 `id`가 이름의 출처예요.
- 방 안 포즈의 일부(`cheer`·`lie` 등)는 원본 시트의 해상도가 낮아서 @3x 래스터 자체가 확대본이에요. 벡터는 그 확대본의 계단을 매끈하게 하지만 없던 디테일을 만들지는 않아요.
- **창작이 아니라서**: 일러스트레이터가 실제 최종본을 다시 그리면 이 파일은 밑그림 용도로만 써요. 마스코트 닮음 검사·법률 검토는 아직이에요.
- 도구는 활발히 개발 중(0.x 버전, 3일 사이 0.15→0.17)이라 버전이 바뀌면 같은 프리셋의 결과가 달라질 수 있어요. 그래서 버전을 고정하고 SVG 해시를 리포트에 남겨요.
- 화면(앱)은 아직 PNG를 써요. 벡터를 앱에서 쓰려면 SVG 렌더링 지원(예: `react-native-svg`) 선택이 필요하고 이 작업은 앱 코드 범위 밖이에요.
