V0-08 로그인 · 비밀번호

Apple 로그인을 우선으로 두고 이메일·비밀번호 로그인을 더했어요(2026-11-06 오너 결정). Apple로 들어온 사람에게는 비밀번호를 만들 수 있게 안내하지만 강제하지 않아요. S02의 제안 보드를 V0 모양으로 옮겼고, 카카오와 인증 코드는 뺐어요.

로그인 · Apple 우선 + 이메일·비밀번호 보조

V0-start-intro(V0-01)의 Apple 버튼이 첫 번째이고, 그 아래 "이메일로 로그인"이 이 화면으로 와요. S02-select-pw와 같이 이메일과 비밀번호를 한 화면에서 받아서 가입 여부가 드러나지 않아요.

계정 만들기

비밀번호 규칙이 처음부터 보이고, 입력하면서 충족 표시로 바뀌어요. 메일 발송 수단이 없는 지금은 V0-auth-signup-nomail이 실제 화면이에요.

비밀번호를 잊었을 때

메일의 링크만 써요(재설정 코드는 V0에서 뺐어요). 메일이 없는 지금은 V0-auth-reset 대신 V0-auth-reset-nomail로 바로 가요. 보내지 못한 메일을 보냈다고 말하지 않아요.

Apple 계정 · 비밀번호 안내 (강제 아님)

Apple 로그인 뒤에 비밀번호를 만들 수 있게 안내해요. "나중에 할게요"로 넘어가도 앱을 그대로 써요. S02-setpw의 "건너뛰기 없음"을 대체해요. Apple 계정 암호는 앱에 들어오지 않아요(S02-apple 그대로).

iOS · 어두운 앱 · 한국어

영어 · 일본어 (주요 화면)

번역으로 길어진 문구가 잘리지 않고 줄바꿈되는지 봐요.

규칙 · 재사용

V0에서 가져온 것 · 뺀 것

  • 가져온 것: S02-select-pw → V0-auth-login, S02-signup·S02-signup-err·S02-signup-sent, S02-reset·S02-reset-sent, S02-pw-new → V0-auth-newpw, S02-setpw·S02-setpw-err.
  • 재사용(다시 그리지 않음): S02-apple(Apple 시트), S02-proc(처리 중), S02-cancel, S02-error, 공통 "<" 뒤로 가기 48pt.
  • 뺀 것(카카오): 카카오 버튼, S02-redirect, 문구의 "카카오" 전부.
  • 뺀 것(인증 코드): S02-email·S02-email-bad·S02-sending(이메일 먼저 묻는 단계), S02-pw·S02-pw-wrong·S02-pw-rate(별도 비밀번호 화면, 코드 안내), S02-code·-wrong·-exp·-rate, S02-reset-code, "대신 인증 코드로 로그인".
  • Android 프레임은 V0 범위가 아니라 그리지 않았어요.

로그인 · 잠금

  • Apple이 첫 번째, 이메일·비밀번호가 두 번째예요. 약관 동의는 Apple은 intro 한 줄, 이메일은 가입 체크 상자예요.
  • 틀렸을 때는 이메일과 비밀번호를 구분하지 않고 같은 문구예요(가입 여부가 드러나지 않게).
  • 연속 5회 틀리면 그 이메일은 10분 잠겨요. 없는 이메일도 같게 응답해요. 잠긴 동안 Apple 로그인은 열려 있어요.
  • 비밀번호 규칙: 8자 이상, 영문과 숫자를 함께, 이메일 주소와 다르게. 서버에서도 같은 규칙을 검사해요.
  • 보기·숨기기는 모든 비밀번호 칸에 있고 기본은 숨김이에요.
메일 발송 필요 · 아직 없음

메일이 아직 없을 때

  • S02 기록 그대로 Aroom-prod에는 메일 발송 수단이 없어요(Supabase 기본 메일만). 그래서 가입 확인과 재설정 메일은 지금 보낼 수 없어요.
  • 연결 전 실제 화면: V0-auth-signup-nomail, V0-auth-reset-nomail. 보내지 못한 메일을 보냈다고 말하지 않아요.
  • 연결 후 화면: "메일 연결 후의 화면" 표시가 있는 프레임이에요. 보내는 주소는 오너 도메인 jinjinstar.com으로 정할 예정이에요(주소 미정).
  • Apple 계정은 메일 없이 해결돼요: Apple로 로그인 → 설정에서 새 비밀번호.
  • 이메일 계정은 메일 전까지 문의(jinjinstar3@gmail.com)가 유일한 경로예요.

Apple 계정의 비밀번호

  • 비밀번호는 선택이에요. 없는 Apple 계정도 정상이고 어떤 화면도 막지 않아요.
  • 새 계정: S02-apple → V0-auth-setpw-prompt → 만들기 또는 나중에 → V0-start-choose.
  • 기존 TestFlight 계정: 업데이트 뒤 처음 열 때 홈 위에 V0-auth-setpw-sheet를 한 번만 보여요.
  • "나중에" 뒤에는 다시 묻지 않고 설정 › 로그인·보안에 "앱 비밀번호 · 아직 없어요" 행이 남아요.
  • Apple 계정 암호는 Apple 시트 안에서만 쓰여요. 앱은 받지도 저장하지도 않아요.
  • 가림 주소 안내 문구는 주소가 @privaterelay.appleid.com일 때만 보여요.
검토 필요

Apple 계정이 이메일로 로그인할 때

  • 앱 비밀번호를 만든 Apple 계정은 "계정의 이메일 + 앱 비밀번호"로 V0-auth-login에서 로그인해요. 같은 계정으로 들어와요.
  • 이메일을 가린 Apple 계정의 주소는 Apple이 만든 가림 주소(@privaterelay.appleid.com)라 사람이 외울 수 없어요.
  • 그래서 완료 화면과 로그인·보안에서 주소를 보여 주고 복사할 수 있게 했어요. 다른 기기에서는 이 주소를 옮겨 적어야 해서 실제로는 불편해요.
  • 오너 검토: 이대로 갈지, 메일 인증 후 내 이메일을 로그인 주소로 더할지(메일 발송 수단이 먼저 필요).
검토 필요

비밀번호 저장 문구

  • "비밀번호는 입력한 그대로 저장하지 않아요…"는 V0-auth-signup, V0-auth-setpw, 로그인·보안에 넣었어요.
  • 실제 동작: 비밀번호는 인증 제공자 서버에 해시로만 저장돼요. 앱·우리 DB·로그에는 원문이 남지 않아야 해요.
  • "암호화"라고 쓰지 않은 이유: 해시는 되돌리는 암호화와 달라서 정확한 말로 풀었어요. 문구와 처리방침 표현은 오너 검토가 필요해요.

심사 · 접근성

  • App Review용 데모 로그인은 V0-auth-login을 써요. 메일 없이 운영자가 미리 만든 이메일 계정이고, 상대가 연결된 상태여야 홈까지 볼 수 있어요.
  • 칸과 버튼은 48pt 이상(눈 아이콘은 칸 안에서 44pt, S02와 같아요). 오류는 색과 함께 아이콘·문구로 보여요.
  • 글자 200%에서는 내용이 스크롤되고 아래 버튼은 고정돼요(S20 규칙).
  • 비밀번호 칸은 iOS 비밀번호 자동 완성을 켜 둬요.
