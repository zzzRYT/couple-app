S27 탭 구조와 이동

3개 탭 + 각 탭 안의 푸시/시트/모달. 점선은 탭 안에서 열리는 화면, 파란 테두리는 다른 탭으로 전환되는 이동, 빨간 테두리는 되돌리기 어려운 흐름이에요. 아래 막대는 시스템 탭 바(iOS UITabBar · Android Material 3 NavigationBar)이고, 앱은 틴트·라벨·아이콘·배지만 정해요.

왜 이 세 개인가 (제안)

  1. 홈 — 메인 D-day 페이지. 매일 열어 보는 기본 화면이라 첫 탭이에요.
  2. 방 — 꾸미기의 중심. 마스코트와 방, 날짜 위젯, 꾸미기 도구가 한 화면에 있어요.
  3. 설정 — 언어·방 낮밤·화면 모드·동의·공간 종료. 시스템 설정과 같은 위치라서 찾기 쉬워요.

탭을 더 늘리지 않았어요(캘린더·할 일·알림이 없는 범위라서 3개면 충분해요). 기록(버전 목록과 이전 버전 복구)은 첫 버전에서 뺐어요. 후속 버전에서 다시 넣을 때는 설정과 방 사이에 탭 하나로 추가하는 안을 쓸 수 있어요. 되돌리기는 기록 목록 없이 방 도구 막대에서 직전 적용만 되돌려요(연속 되돌리기 깊이는 아직 정해지지 않았어요).

탭 바 표시 규칙

화면 종류탭 바이유
탭 루트 3개(홈·방·설정)보임어디서든 다른 탭으로 이동할 수 있어야 해요. 방 탭에서는 시스템 영역이라 장식이 가릴 수 없어요.
목록 → 상세 푸시(라이선스 등)숨김상세는 한 가지 일에 집중해요(iOS hidesBottomBarWhenPushed, Android는 상세 화면에서 막대 제거).
작업 흐름(공간 종료, 동의 관리, 신고·차단, 초대 코드)숨김되돌릴 수 없거나 중요한 결정이라 다른 탭으로 새지 않게 해요.
시트·다이얼로그·꾸미기 패널시트는 탭 바를 덮음모달이라 닫기 전에는 탭 이동이 없어요. 꾸미기 패널을 열고 있어도 점유는 시간 제한(3분)으로만 풀려요.
키보드가 열린 화면키보드 아래로 밀림꾸미기 입력 중에는 패널이 모달이라 탭 바와 겹치지 않아요.

시스템 컴포넌트 원칙

탭 바는 시스템이 소유하는 UI예요(방 장면 밖). 구현은 Expo의 네이티브 탭(iOS는 UITabBarController 기반, Android는 Material 3 NavigationBar)을 쓰고 직접 그린 막대를 쓰지 않아요. 재질(반투명 블러)·높이·아이콘 크기·글꼴·선택 애니메이션은 OS가 정하고, 앱은 틴트색·라벨 문구·아이콘 이미지·배지만 정해요. 탭 바는 보호 영역이라 방 장식이 가리거나 막을 수 없어요. 이 캔버스의 탭 바 그림은 시스템 모습을 닮게 그린 참고용이고, OS 버전에 따라 실제 모습이 조금 달라요.
