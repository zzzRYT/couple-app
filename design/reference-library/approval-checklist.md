# approval-checklist.md — 기준 라이브러리 최종 승인 체크리스트 (소유자용)

현재 `objects/*.json` 14개(배경 6, 말풍선 4, 소품 4)는 **자리표시 스케치**예요. 이 목록을 모두 확인하고 서명한 뒤에야 `status`를 `placeholder`에서 `approved`로 바꾸고(`reference-library.json`과 각 항목), 모델 프롬프트의 기준 그림으로 확정해요. 일부 오브젝트만 승인했다면 그것만 `approved`로 바꾸고 나머지는 `placeholder`로 남겨요.

확인에 쓰는 것: `contact-sheet.png`, `previews/*.svg`, `style-spec.md`, 그리고 `node design/tools/aroomi-shape/cli.mjs check-samples`, `style-check`.

## 1. 스타일 일관성

- [ ] 열네 개가 한 사람이 그린 것처럼 보여요(윤곽선 굵기·둥근 정도·색 톤이 같아요).
- [ ] 기존 카탈로그 스케치(`design/assets-sketch/*.svg`)와 나란히 놓아도 어색하지 않아요(윤곽선 `#4A3426`, 크림 림, 오른쪽 아래로 어긋난 파스텔 채움).
- [ ] 그림자·광택·그라디언트·투명도가 없어요(형식에도 없지만 눈으로 확인).
- [ ] 뾰족한 가시, 완전한 기하학, 격자 같은 규칙적 무늬가 없어요(`style-spec.md` §4, `examples-dont`와 비교).
- [ ] `style-check` 결과 기준 오브젝트가 모두 통과해요(참고용 어림값이에요. 점수가 좋아도 눈으로 보는 확인이 우선이에요).
- [ ] 각 오브젝트의 채움이 4색 이하, 가능하면 3색 이하예요.

## 2. 외부 작품과 닮지 않았는지

- [ ] 각 오브젝트의 미리 보기 PNG/SVG로 **역이미지 검색**을 했어요(검색 도구·날짜·결과 링크를 아래 기록란에 적었어요).
- [ ] 유명 캐릭터, 브랜드, 로고, 상표가 있는 물건, 특정 작가의 대표 그림과 닮은 곳이 없어요(말풍선 꼬리·리본·구름처럼 흔한 소재라도 고유한 조합이 닮지 않았는지 봐요).
- [ ] **마스코트(아루미)와 닮은 요소가 없어요**: 달걀·감자 몸통, 점 눈과 분홍 볼, 파란 어깨띠, 노란 별 핀. 특히 **소품 4개**(`prop-*`)를 마스코트 이미지 옆에 놓고 비교했어요(실루엣·색 조합·눈 두 개 + 입 같은 배치가 겹치지 않아요).
- [ ] 소품 4개에 얼굴·표정·팔다리·사람/동물 모양이 없고, 앱 안의 다른 캐릭터와도 닮지 않았어요.
- [ ] `PROP_FACE_LIKE` 검증은 어림 점검일 뿐이라는 것을 알고, 소품이 새로 늘어나면 이 항목을 사람 눈으로 다시 확인해요.
- [ ] 얼굴(눈·코·입), 글자·숫자·기호(책등 포함), QR 같은 무늬가 없어요.
- [ ] 검색 결과에서 의심스러운 닮음이 나오면 해당 오브젝트를 고치거나 뺐어요(기록란에 적어요).

## 3. 권리·출처 진술

- [ ] 소유자(또는 계약한 일러스트레이터)가 아래 진술에 동의했어요.
  > 이 오브젝트들은 이 프로젝트를 위해 직접 그린 것이고 외부 이미지·생성 이미지·다른 작품을 참고하거나 사용하지 않았다. 권리는 앱 소유자에게 있다.
- [ ] 자리표시를 만든 방법을 알고 있어요: AI 코딩 도우미가 이 프로젝트의 스타일 규칙만 보고 **좌표를 계산하는 스크립트로** 그렸고, 외부 이미지·이미지 생성 도구는 쓰지 않았어요. 이 점을 알고도 최종 그림을 어떻게 할지 정했어요: ☐ 새로 그림 ☐ 이 스케치를 확정(AI 보조 제작물이라는 사실을 권리 검토에 알려요)
- [ ] 일러스트레이터에게 맡겼다면 계약서에 작업물 권리 이전과 "생성형 AI 도구·외부 이미지 미사용" 진술이 있어요.
- [ ] `reference-library.json`의 `provenance`를 최종 값으로 바꿨어요(예: `drawn by <이름>, <날짜>, rights: app owner`).
- [ ] 출시 전 법률 검토 항목(`design/handoff.md`의 권리 상태)에 이 라이브러리를 더했어요.

## 4. 낮·밤 방에서 읽히는지

- [ ] `previews/*.day.svg`(낮 벽 `#FBF1E3`, 러그는 바닥 `#F3E0C4`)에서 모양이 읽혀요.
- [ ] `previews/*.night.svg`(밤 벽 `#2B2320`, 러그는 `#352A25`)에서 크림 림 덕분에 윤곽이 읽혀요. 윤곽선 `#4A3426`은 밤 벽에서 1.33:1이라 림이 읽기를 책임져요(림은 밤 벽에서 14.12:1).
- [ ] 말풍선: 글자색 `#3A261C` 대비가 4.5 이상이에요(둥근 13.07, 구름 12.33, 물결 10.35, 리본 13.07). 낮·밤 방 모두에서 말풍선 몸통이 벽과 구분돼요.
- [ ] 실제 방 화면(낮·밤·다크 모드·고대비)에 올려 보고 마스코트와 컨트롤을 가리지 않는지 봤어요.
- [ ] 소품: 바닥·선반 소품은 바닥/선반 면에 닿는 자리(아래 가운데 앵커)에서 자연스럽게 놓이고, 벽 소품은 거는 점(위 가운데)에서 자연스러워요. 소품도 장면의 객체 16개 한도에 들어간다는 점을 화면 설계가 반영해요.

## 5. 작은 크기에서 읽히는지

- [ ] 말풍선을 화면 폭의 약 40%(약 150pt)로 줄여서도 모양과 꼬리가 읽혀요.
- [ ] 배경 조각을 실제로 놓을 크기에서 윤곽선이 너무 굵거나(큰 조각) 너무 가늘지 않아요(윤곽선은 긴 변의 3.75%예요).
- [ ] 가장 작은 무늬(점·줄)가 놓을 크기에서 윤곽선과 함께 뭉개지지 않아요.

## 6. 파일·검증

- [ ] `node design/tools/aroomi-shape/cli.mjs check-samples`가 실패 없이 끝나요.
- [ ] `node --test design/tools/aroomi-shape/test/`가 모두 통과해요.
- [ ] `objects/*.json` 파일 크기가 각각 3 KB 이하예요(현재 0.8~2.6 KB, 소품 0.8~1.8 KB). 요청 종류별 프롬프트가 예산(약 6k 토큰) 안이에요(배경 약 11.9 KB ≈ 4.0k 토큰, 소품 약 8.0 KB ≈ 2.7k, 말풍선 약 6.5 KB ≈ 2.2k 토큰 어림). 14개 전부를 한 번에 넣으면 약 20.5 KB로 예산을 넘어요.
- [ ] 바뀐 오브젝트가 있다면 `previews`와 `contact-sheet.png`를 다시 만들었어요.
- [ ] 접근성: 배경 조각과 말풍선은 장식이에요. 의미 있는 정보를 색이나 모양으로만 전달하지 않아요(`label`은 보조 기술용 이름으로 쓰이니 의미가 맞아요).
